# Судостроение 2.6 — проверка кода, свойства и верфь

**Ветка:** `feature/2.6-shipyard-inspection-upgrades-20261108`, отдельный draft PR #438 поверх PR #437; **не сливать в `release-2.5` или `main` до проверки в игре**.

## Что проверено по исходникам

- `RaftBoatEntity` хранит размеры (3×3 / 3×5 / 5×5 / 5×7), количество парусов, ограждение, руль, доп. вёсла и карту оборудования в синхронизируемых параметрах. Упаковка в `Raft2511Pack` версии 2 включает эти параметры и ItemStack-содержимое модулей.
- `RaftCharacteristics` — единый безопасный парсер ItemStack NBT для описания свойств. Он **не** декодирует реальный список предметов при показе подсказки, а только считает сохранённые позиции и стопки. Неподдерживаемый формат, дублированные клетки и противоречивые размеры помечаются недостоверными.
- Текущая математическая модель тяги в `RaftBoatEntity`: максимальный *программный предел* парусного горизонтального перемещения 0,50 блока/тик (1 парус) или 0,65 (2 паруса), дополнительный лимит +0,12 блока/тик при гребле. Значения в подсказке соответствуют этим же константам, то есть 10,0 / 13,0 блок/с, а с греблей 12,4 / 15,4 блок/с. **Это не гарантированная фактическая скорость**, на неё влияют базовая лодочная физика, вода и препятствия. Гребля без паруса остаётся движением ванильной лодки. Условная тяга ещё не моделирует реальные мировые направления ветра.
- `ShipyardMenu` содержит *реальную* ячейку 1 шт. под предмет судна, 36 слотов инвентаря и серверные кнопки: создать 3×3, увеличить размер, поставить ограждения/парус/руль/доп. вёсла. Действия разрешены только живому игроку у существующего блока станции в пределах 8 блоков. При закрытии предмет судна возвращается в инвентарь/выпадает, не остаётся в фиктивной BlockEntity.
- `ShipyardUpgrades` перед выполнением проверяет ресурсы и формат предмета, затем возвращает новый ItemStack, который заменяет исходный в *той же* ячейке; материалы тратятся только после успешного формирования данных результата. Модули переставляются с сохранением центра: при 3×3→3×5 они сдвигаются на +1 по Z, при 3×5→5×5 на +1 по X, при 5×5→5×7 на +1 по Z. Это не разрушает сундуки или их ItemStack-данные.
- `ShipyardScreen` — специализированный GUI с визуальным списком характеристик и подсказками. `ShipyardWorkbenchBlock`: обычный ПКМ пустой рукой или с плотом — открыть осмотр; **Shift+ПКМ пустой рукой** — открыть обычную 3×3 сетку крафта со специальной проверкой доступности верфи. Прежнее мгновенное закрытие окна при проверке vanilla crafting_table не должно происходить по этой причине.
- `RaftHud` показывает свойства судна при наведении на его сущность (либо при посадке), используя только синхронизированные данные. Нет доступа к чужому содержимому сундуков.
- Tooltips всех размеров и готовых парусных предметов используют то же описание, что и верстак: размер, экипаж, паруса, ограждения, руль, дополнительные вёсла, число клеток, число слотов хранилищ, тип тяги, лимит скорости, признак запакованного груза.

## Что нужно проверить в Minecraft (НЕ считать заранее PASS)

1. ПКМ по верфи пустой рукой открывает экран **Осмотр/улучшения**, и он не закрывается сам. Shift+ПКМ открывает обычный крафт.
2. Переместить с помощью мыши или Shift+клика в слоты верфи предмет плот 3×3, посмотреть на размеры, скорость и модификации. Закрыть экран — исходный предмет сохраняется.
3. С 6 палубными секциями в инвентаре нажать «Улучшить»: плот 3×3→3×5 с сохранением судового сундука и его предметов. Повторить 3×5→5×5 (10 секций) и 5×5→5×7 (10 секций).
4. Кнопками «Борта», «Парус», «Руль», «Вёсла» установить оснащение с соответствующими предметами в инвентаре. Проверить, что одна модификация не применяется дважды, 3×3 не принимает дополнительные вёсла, 5×7 допускает максимум два паруса.
5. Проверить, что в готовых предметах из Creative и в запакованных ключом судах свойства одинаково читаемы, нет утраты ItemStack, нет клонирования при переключении размера или закрытии меню.
6. При наведении на существующий плот на воде и при посадке проверить информационную панель, отсутствие ошибок/зависаний, соответствие реальному оснащению.
7. Dedicated server с двумя игроками, relog, chunk unload/reload и полный инвентарь: отсутствие исчезновений и дублей.

## Автономная проверка геометрии (JDK 21)

Проверена отдельная чистая Java21-компиляция `RaftSize`, `ShipyardLayout`, `ShipyardLayoutProof` и запуск `java -ea`: **136/136 проверок пройдены**. Проверены все клетки при каждом допустимом расширении, отсутствие столкновений локальных ячеек, совпадение последовательных и прямых переходов и запрет недопустимой геометрии. Данные реальных ItemStack и GUI в этом автономном тесте **не участвуют**.

```powershell
mkdir build\shipyard-proof -Force
javac -encoding UTF-8 -d build\shipyard-proof src\main\java\org\slavicmyths\ships\RaftSize.java src\main\java\org\slavicmyths\ships\ShipyardLayout.java experimental\raft26\ShipyardLayoutProof.java
java -ea -cp build\shipyard-proof org.slavicmyths.ships.ShipyardLayoutProof
```

Последняя Java21 CI-сборка текущей ветки проверяется по конкретному commit; **не** считать зелёную компиляцию доказательством успешного открытия экранов в игре.

**Оставшиеся инженерные ограничения:** физика ходьбы по палубе — экспериментальная, без полноценного движущегося блока; упаковка грузового плота **не crash-атомарна**, сохранность после жёсткого выключения сервера не доказана; скорость — расчётный предел, а не измеренная скорость; направление ветра ещё условное. PR сохранять в режиме draft.
