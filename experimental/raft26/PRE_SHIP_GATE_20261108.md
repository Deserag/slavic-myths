# Slavic Myths 2.6 — обязательные ворота перед полноценными кораблями

Дата: 08.11.2026. Ветка: `fix/2.6-raft-safety-audit-20261108` поверх чернового PR #439. Работа не слита в `release-2.5` или `main`. **Это аудит работоспособности плотов, НЕ утверждённый релиз 2.6.**

## Что завершено по коду (статический уровень)

- Четыре конфигурации 3×3 / 3×5 / 5×5 / 5×7 и один / два паруса на допустимых размерах, ограждения, руль, вёсла, поддержка сундуков / бочек / верстака / печки, верфь с осмотром и улучшением в одной ячейке.
- `RaftItem.use` проверяет всю палубу при **фактическом угле поворота** через полублочную сетку, наличие исходной воды и отсутствие твёрдого препятствия на уровне палубы; не допускает повёрнутый длинный корпус в берег.
- `RaftCharacteristics.fromItem` отбраковывает ошибочные ItemStack-NBT до модернизации: неправильные размеры, версия, неизвестные флаги, отсутствующий список Items, дублированные/выходящие за границы клетки.
- `RaftBoatEntity.loadPackedItem` проверяет версию 1 **только для старого 3×3**, размеры и паруса версии 2, полный набор модулей. До создания сущности декодирует каждый сундук/печь в отдельном временном SimpleContainer и сверяет обратную сериализацию: повреждённый груз не должен незаметно превратиться в пустой.
- Установленная/снятая рулевая часть теперь действительно отражается в названии предмета. Тестовые рецепты/модели сохранены.
- GitHub Actions: **24 530 проверок** повёрнутого контура, **656 проверок** моделей и рецептов, существующие JDK21 проверки ветра. Gradle Java21 полный build — отдельно по финальному коммиту.
- Никакой зависимости от Create/Aeronautics/Sable.

## Обязательная ручная приёмка — не выполнена

| Область | Проверить | До кораблей |
|---|---|---|
| Плавание и управление | Каждый из 4 размеров, руль + вёсла + 1/2 паруса, попутный/встречный ветер, берег | Обязательно |
| Палуба | Запрыгивание, свободная ходьба, повороты без рывков, прыжок за борт, 2–4 игрока | **Критический блокер** |
| Загрузка и груз | 2 заполненных сундука, рабочая печь с топливом, верстак, серверный рестарт, упаковка и распаковка с точным ItemStack | **Критический блокер** |
| Верфь | Открывается и остаётся открыта, улучшает все 4 размера, снимает детали/возвращает их, показывает реальные свойства | Обязательно |
| Тест на дубли | Полный инвентарь, Creative, быстрые клики, пользовательский NBT, два пользователя | **Критический блокер** |
| Внешний вид | Масштаб/освещение в инвентаре, паруса, бортовые ограждения, посадка и анимации | Обязательно |
| Переворот | Крен из-за неравномерной нагрузки, опрокидывание, ручное восстановление 1+ игроком | **НЕ РЕАЛИЗОВАНО**, требуется отдельный прототип |
| Транзакционное хранение | Аварийное отключение в момент упаковки, обнаружение/восстановление целого судна с грузом | **НЕ РЕАЛИЗОВАНО**, для важных грузов блокер |

**Важно:** Gradle build и чистая Java21 геометрия НЕ доказывают отсутствие игрового рывка, корректное отображение меню, сохранность сундуков в мире и аварийную надёжность. Не использовать ценный груз до выполнения QA на копии мира.

## Решение о начале больших кораблей

Полноценную разработку корабельных корпусов, трюмов и летучего корабля начинать **после** проверки безопасности сохранения груза, стабильного перемещения по палубе и интерфейса верфи. Можно отдельно проектировать корпусные детали и внешность, но не переносить экспериментальные физические механизмы в основную сборку. Крен и ручное восстановление — задача в рамках закрытия плотов (вопрос уже согласован владельцем, новое концептуальное согласование не требуется).
