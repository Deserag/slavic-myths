# 2.5.1.1 «Логика плавания» — первый игровой тест плота (WIP)

Связанные: #433 и draft PR #434. **Целевое крупное обновление остаётся 2.6 «Океан».** Техническая ветка 2.5.1.1 изолирована от `main` и `release-2.5`.

## Что здесь действительно реализовано

- Зарегистрированный тестовый предмет `slavicmyths:raft_2511_test` (отображается как «Плот») и отдельный `EntityType`; ПКМ по поверхности воды для установки.
- Отдельная вкладка творческого инвентаря **«Кораблестроение»**. В ней лежит предмет «Плот»; в будущем сюда попадут корабельные детали, модификации и верстак.
- **Исправлен баг первого отчёта пользователя:** прежнее `posY + 0.15` помещало плот внутрь воды; теперь позиция берётся с поверхностного попадания луча. Установка требует свободный участок воды **3×3**, иначе показывается предупреждение.
- Гребля на базе `Boat` в NeoForge 1.21.1; отдельное серверно-клиентское удержание высоты у **поверхности воды**, так как ванильный расчёт плавучести не удерживал сущность шириной 2.95 блока. Сохраняется уровень поверхности при обычном сохранении, старые погружённые тестовые экземпляры пробуют восстановить высоту. Без Create/Sable.
- **Средняя кнопка мыши (pick block)** по сущности теперь возвращает именно предмет `raft_2511_test`, а не ванильную дубовую лодку; предмет возможного выпадения также исправлен.
- Визуальный деревянный корпус 3×3 с толстыми брёвнами, поперечными креплениями и **парой анимированных вёсел**. Предмет теперь использует собственную 3D-модель из 9 элементов, а не иконку дубовых досок. Это ещё не окончательная утверждённая художественная модель.
- До четырёх пассажирских мест. **Они временно закреплены, а не являются свободно ходящими игроками.**
- Shift + ПКМ с сундуком/бочкой по плоту: ближайшая к лучу взгляда свободная клетка на палубе заносится в серверный список модулей. 27 реальных слотов `SimpleContainer` на каждый модуль, синхронизация внешнего состояния размещения и NBT ItemStack для чанков/обычного сохранения. Shift + ПКМ пустой рукой по выбранному модулю: стандартный интерфейс хранения.
- Хранение внутри судовой сущности; **никаких** операций слома/создания блоков мира при каждом перемещении. Урон не разрушает базовое судно.
- Разрешены пока только `minecraft:chest` и `minecraft:barrel`. Для верстака и печи нужны отдельные работающие контейнеры и тикание рецептов; нельзя считать завершёнными.

## Как попробовать в независимом тестовом мире

Java **21**, Minecraft **1.21.1**, NeoForge **21.1.255** и существующие штатные зависимости сборки Slavic Myths. **Create / Aeronautics / Sable пока не требуются; ничего дополнительного скачивать для этого теста не нужно.**

В отдельном клоне репозитория, не затрагивая рабочий проект:

```powershell
git fetch origin
git switch 2.5.1.1-raft-navigation
git pull --ff-only origin 2.5.1.1-raft-navigation
.\gradlew.bat clean jar --no-build-cache --no-configuration-cache
```

Если Gradle сообщает ошибку `compileKurganCheckJava`, это отдельный необязательный для JAR тестовый source-set; команда `jar` позволяет проверить игровой артефакт без него. Не удалять тесты или исходники.

Использовать чистый тестовый профиль и мир. Не заменять существующий мод в рабочем сохранении. После проверки сборки и JAR открыть Creative → вкладка **«Кораблестроение»** → взять предмет **«Плот»**. Команды для получения не нужны.

Затем ПКМ по **открытой воде 3×3** — появится плот у поверхности; обычный ПКМ — сесть и проверить греблю. Shift + ПКМ при взгляде на палубу с сундуком/бочкой — попытаться закрепить модуль; Shift + ПКМ пустой рукой — проверить содержимое. Учитывать текущие ограничения: реальная плавучесть, высота палубы, позиции установки/доступность GUI, замедление на суше и четырёхместная рассадка требуют новой фактической проверки в Minecraft. Старые экземпляры из предыдущей сборки должны попробовать восстановить высоту при очередном серверном тике, но это пока нужно проверить. **Первый тест проводить с новым пустым плотом** в копии мира, ничего не удалять у уже наполненных старых экземпляров.

## Зависимости и инженерное решение

Никакие новые JAR не включены и не скачаны. Create: Aeronautics требует Create и Sable и **не подходит для обязательной зависимости Slavic Myths**. Sable без Create можно исследовать отдельно в полностью чистом экспериментальном профиле; его интрузивные mixin/лицензия/совместимость требуют реальных проверок. Решение о подключении пока не принято.

Полный сценарий доказательства свободной ходьбы: сравнить автономную collision-обвязку и проверенный Sable sub-level (если совместим); игрок без режима пассажира должен спокойно двигаться по палубе 3×3, прыгать за борт, открывать хранилище, пересекать границы чанков и восстанавливаться после перезапуска на dedicated сервере с 2–4 игроками.

**Статус: WIP / первичная проверяемая игровая заготовка. Не сливать в release-2.5 и не переустанавливать в основную PolyMC сборку до приёмки.**

## Отчёт пользователя о второй итерации (08.11.2026)

Проблемы: лодка уже на поверхности при установке, затем падает на дно; герой плывёт под водой; средняя кнопка мыши даёт ванильную лодку; предмет назывался «испытательный», иконка и модель слишком примитивны. Исправлены конкретные причины кода: унаследованная непригодная плавучесть для широкой сущности, отсутствие переопределения `getPickResult`, вывод временного имени. Результат **ещё требует повторного игрового подтверждения**.

При повторном тесте проверить: (1) Y плота стабилен на воде через 20 секунд и при движении; (2) голова и туловище игрока не погружены; (3) ПКМ + WASD гребёт, вёсла меняют положение; (4) средняя кнопка мыши возвращает «Плот»; (5) после релога не появляется дублирующийся предмет и не пропадает груз; (6) отсутствие сцепления с берегом.

## 08.11.2026 — граница безопасности упаковки судна

После игрового отчёта о потере сундуков при креативном разрушении, в коде сделаны следующие отдельные экспериментальные изменения:

- Обычные удары, включая Creative, отклоняются через `RaftBoatEntity.hurt` — стандартное разрушение больше не является разрешённым способом забрать плот.
- Во вкладке «Кораблестроение» появился **«Верфяной ключ»** (пока временная иконка топора); ПКМ ключом по неподвижному плоту без пассажиров упаковывает его в один предмет «Плот» с `CustomData` и всем содержимым локальных сундуков и бочек.
- При повторном размещении этого **же упакованного предмета** мод читает полный список модулей и настоящие `ItemStack` из NBT; сервер сначала валидирует структуру груза, затем создаёт судно, и только после успешного размещения потребляет предмет. В Creative из использованного предмета удаляется грузовой компонент, чтобы он не оставался клонируемым источником того же содержимого.
- Старый `getPickResult` для средней кнопки **по-прежнему даёт новый пустой плот**; он не является операцией упаковки и не должен копировать груз.
- **NOT_PROVEN:** двойные клики под лагом, аварийная остановка сервера между удалением сущности и выдачей упакованного предмета, полные 9 модулей со сложными DataComponents, отключение при заполненном инвентаре, несогласованные сторонние вмешательства, многопользовательский runtime. Для полной атомарности при крашах понадобится транзакционный журнал `SavedData`.
- **Приёмка PENDING**: не использовать реальные миры с ценным грузом; проверить в копии: заполнить два сундука нестандартными ItemStack → выйти/войти → запаковать ключом → проверить, что предмет содержит груз → поставить снова → инвентари и предметы совпадают в точности и нигде не продублировались.

Все расширения 3×5, 5×5, 5×7, паруса, корабельный верстак и свободное перемещение игроков остаются предметом визуального и технического согласования; **не считать их реализованными**.
