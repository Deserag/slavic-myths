# Slavic Myths 2.6 — ветер и обслуживание парусов (08.11.2026)

Ветка: `feat/2.6-rigging-wind-controls-20261108`, черновой PR #439 поверх #438 → #437 → #436 → #434. **Ни main, ни release-2.5 не изменяются.** Ранее согласованные 3×3, 3×5, 5×5, 5×7 затронуты одной общей механикой, без отдельной реализации для каждого размера.

## Сделано в коде

- `RaftWind`: медленно меняющееся направление ветра в мире, зависимость силы от времени, местности и погоды. Парус даёт тягу по курсу судна: по ветру сильнее, поперёк — слабее, прямо против ветра — нулевую. Встречный ветер **не блокирует греблю**.
- Два паруса дают более сильную тягу, чем один; штатные ограничения максимальной скорости остаются в `RaftCharacteristics`. Парусная тяга работает только при наличии рулевого узла, пассажира-пилота и воды под судном.
- `RaftHud`: при наведении / управлении видны направление, сила ветра, эффективность текущего курса в процентах и фактическая скорость. Расчётное ограничение — **не** гарантированная скорость по игровым условиям.
- `RaftRenderer`: угол и плавное качание мачты/паруса зависят от ветра.
- `ShipyardUpgrades.dismantle`: четыре обратные операции в верфи — снять ограждения, один парус, руль, дополнительные вёсла. Сервер проверяет наличие установленного элемента и **свободное место для возврата**. При полном инвентаре не изменяет судно. Снимает ровно один парус за операцию, если их два.
- `ShipyardScreen`: кнопки снятия со знаком «−» и прокрутка панели полного описания свойств.
- Расширение плота теперь использует `ItemStack.transmuteCopy`, сохраняя прочие data components (имя судна, lore и т. д.) при смене зарегистрированного предмета размера.
- `RaftWindProof`: отдельный JDK21-only тест нормализации, детерминизма, погоды, встречного/попутного ветра и двух парусов. GitHub Actions `Shipbuilding 2.6 - pure wind proof` запускает этот тест автоматически.

## Локальное получение (PowerShell)

```powershell
git fetch origin
git switch --track origin/feat/2.6-rigging-wind-controls-20261108
.\gradlew.bat clean jar --no-build-cache --no-configuration-cache
```

Если ветка уже есть локально, вместо `--track` использовать `git switch feat/2.6-rigging-wind-controls-20261108` и `git pull --ff-only origin feat/2.6-rigging-wind-controls-20261108`. Игровой тест — **только в копии мира** с отдельным JAR. Create/Aeronautics/Sable не нужны.

## Обязательные проверки в Minecraft (пока NOT_RUN)

1. Взять 3×3, 3×5, 5×5, 5×7 с одним парусом из «Кораблестроения» и двухпарусный 5×7. Проверить плавучесть, движение, изменение курса и HUD при наведении.
2. Проверить курс при попутном, боковом и встречном ветре. Парус должен давать разную тягу, гребля оставаться доступной при любом курсе. Смена погоды должна влиять на силу ветра без резких скачков.
3. На всех размерах с парусом и рулём открыть верфь; снять один парус, вернуть его в инвентарь, снова установить. Повторить для руля, ограждения и доп. вёсел там, где они разрешены. На 5×7 с двумя парусами каждый клик снимает только один.
4. Проверить запрет снятия неустановленного элемента, отсутствие клонирования при полном инвентаре, сохранение упакованного сундука и содержимого до/после переконфигурации.
5. Проверить название/информацию судна при расширении и после повторного размещения; отсутствие потери иных ItemStack-компонентов.
6. Проверить реальный интерфейс верфи, прокрутку длинного списка свойств, отсутствие наложений кнопок и инвентаря. Проверить 2–4 игрока и dedicated сервер.
7. **Критично:** физика свободной ходьбы ещё экспериментальная, безопасность груза при аварийном выключении сервера не доказана. Не переносить PR в основную сборку до приёмки владельца.

## Архитектурные ограничения

Руление всё ещё использует механизм управления унаследованной лодки и пилота-пассажира; полноценная самостоятельная рулевая станция для стоящего игрока, парусный режим без посадки, ходьба в многопользовательском мире и реальные физические волны/крен требуют отдельных испытаний. Ветер **не** является индустриальным механизмом Create. HUD показывает направление, **куда дует** ветер, а не откуда.
