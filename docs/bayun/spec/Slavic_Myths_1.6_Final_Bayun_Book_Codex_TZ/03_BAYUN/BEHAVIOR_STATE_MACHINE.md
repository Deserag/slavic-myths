# Kot Bayun — exact server encounter, gifts, risk, trust, persistence and exploits

## Non-negotiable server numbers (defaults)
`noticeRadius=12.0`, `songRadius=15.0`, `giftReach=3.0`, `petReach=2.5` blocks; `giftGrace=160 ticks (8s)`, `escapeWarning=70 ticks (3.5s)`, `songWindup=40 ticks (2s)`, `compulsionTimeout=200 ticks (10s)`, `pounceWindup=8 ticks`, `pounceFlight=12 ticks`, `combatRecovery=120 ticks`. Mod configurable but these defaults in shipped build. Counts based on server tick, not real-time OS; pause in singleplayer should pause countdown.

## World entity state
`SLEEP_COILED, IDLE_SIT, IDLE_WALK, GROOMING, STRETCH, EATING, ALERT, WARNING, SINGING, CHARMING, POUNCING, RECOVERING`. Background states are lower priority; WARNING+ cannot be overwritten by ambient animation. World anchored: `homePos, persistentEntityUuid, leashFreeRadius=9`, no follower taming, no breeding, not pickable in buckets/boats/minecarts unless verified safe (default disallow conveyance), no looting. Server persists home and interaction cooldown, client receives summarized animation states.

## Per-player session state
`UNMET, GRACE, SAFETY_GIFT, ESCAPE_WARNING, CHARMED, ATTACK_PENDING, COOLDOWN, FRIENDLY`. Store by UUID on player/encounter service. One cat may observe multiple players; no aggressive broadcast status to everybody. Hard cap max 1 active physically pouncing victim per Bayun entity; other victims may be warned independently, but can't be autokilled without physical pounce. If two timelines conflict, queue/retry with fresh warning, NEVER silent kill.

### Transition details
0. Ignoring creative/spectator/dead players; players not in LoS or closer than noticeRadius only, new proximity trigger once per entry, not every tick.
1. On first valid entry GRACE, fixed 160t expires; client hint one-time: «Кот Баюн пристально смотрит на вас. Угостите его или отойдите». Cat wake/eye tracking, no attacks before expiration. If owner relationship is `FRIEND`, interaction safe from start.
2. Valid gift before timeout: **atomic** server stack consumption, branch SAFE for that encounter, stop dangerous timer, PLAY feeding clip, add trust and per-player 1-day cooldown. Same gift packet twice must consume once; verify hand, item, distance, cooldown; invalid item does not disappear and has RU feedback.
3. If no gift and player stays in proximity when grace expires, start WARN 70t; cat arches back & warning sound/amber particles. If player leaves `songRadius + 1.0 hysteresis` before WARN ends, reset safe, 15s re-entry cooldown (not magical killing from offscreen).
4. If still valid at WARN end: verify survival, same dimension, LoS/valid audio proximity, start SINGING 40t; client vignette and musical motif localized subtitle «Чарующая песнь Кота Баюна». Ensure motion control server safe. If player crossed boundary/breaks line of sight behind solid cover during windup, cancel charm; no killed-through-wall.
5. When song completes, CHARMED: max 200t. Movement induced physically toward cat at horizontal speed <=0.11 block/tick with collision and path safety, never noClip, no sudden 10-block relocation, no jumping into lava, no drowning. Preserve camera first-person, reveal effect via chromatic/soft vignette not nausea spin; mount/fall/glide/teleport/no-path/disconnect/death ⇒ terminate immediately.
6. When distance <=2.2 and LoS collision valid: cat freezes victim target, crouches 8t, leaps toward current reachable point over 12t; hit after actual attack collision/range <=1.8 (not merely at animation end), direct server lethal slashing `damageSource` so death message shows «Игрок был растерзан Котом Баюном». Only if victim still eligible and collidable; armor bypass permissible for mythical move but honor creative/spectator, invulnerability and protection hooks; don't corrupt player health data.
7. After damage/abort reset victim effect, cat return to RECOVERY 120t → wander/sit at home; after death reconnect victim is no longer charmed. Avoid immediate spawncamp: player receives fresh full warning on next encounter.

## Gifts and trust (server-authoritative)
Allowed first gifts: 1 milk bucket → empty bucket, 1 raw cod or 1 raw salmon consumed. Optional additional current mod fish only if registered with honest tag and localized name; never blindly accept any `ItemTags.FISHES` if includes cooked/inappropriate. Milk: +10 trust after first gift; fish +8. First successful encounter receives an **additional +15 first impression only once per (player,Bayun)**, yielding trust 25 for milk or 23 for fish. Grade boundaries: stranger `0–24`, familiar `25–59`, trusted `60–84`, friend `85–100`; first raw fish puts player into stranger but SAFE session; no arbitrary attack triggered during safe session. Gifts trust increments only 1/day **per unique NPC per player**, no giving 64 stacks at once. A pet action with empty hand (or explicit configured hand) at <=2.5b after safe meeting: +4 trust every 2 game days, animation rub cheek 22t; avoid shift+right click normal and UI conflict. Reject spam via `lastGiftGameDay` using monotonic world days, not client clock. Persist any pending recovery/trust updates.

## Dialogue/menu
After safe session: right click empty hand or dedicated interact path opens actual 4-option screen: «Расскажи предание» (get 1 actual book rumor), «Как меня зовут?» (Bayun identity/bond explanation), «Что ты знаешь о здешних местах?» (real generated **honest** hint if available, else RU ‘Пока мне нечего поведать’), «Попрощаться» (close). Danger state menu closed/no free pause. Each option with working state and a printed localized answer, no future bogatyr quest buttons in final 1.6; advanced options at trust thresholds are real unlocks, not placeholders.

## Persistence/performance/security
- `invulnerable` to combat+environmental damage; allow admin command removal/testing outside ordinary game. `setPersistenceRequired` or actual equivalent; never natural despawn, does not force chunk ticket. Health render not boss bar. Bind anchor separate SavedData mapping anchorUUID to BayunUUID; on chunk load reconcile duplicates without harming legitimate game data.
- No high-frequency scanning: goals and nearest-player check every 10 ticks, event tracking when enter radius, keep cached victim; avoid worldgen reference lookup in each `tick()`.
- If world chunk unloads or entity is removed legitimately, session clears and controls restore. Separate server-side per-player initial impression, gift times and known book facts from entity mutable state; survives world reload.
- No killing through creative/spectator, remote hit, door/wall, dimension travel, disconnect or another mob body interception. Player-level disable accessibility screen shake if exists; no permanent input grab.
- Vanilla death/resurrection must work with keepInventory and gamerules. Single server with many clients can have different relations toward same Bayun. Cache sound start+stop and sync to trackers, not all server players.
