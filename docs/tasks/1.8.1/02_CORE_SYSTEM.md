# Общая система «Мор»: данные, распространение, книга, нагрузка

## Состояния сущности
`NORMAL` → `MOR_TRANSFORMING` (50 ticks = 2,5 сек.) → `MOR_ACTIVE`; для естественного рождения допустимо сразу `MOR_ACTIVE` без 2,5 сек. анимации, чтобы новорождённые мобы не торчали неподвижно в чанках. Иные состояния не вводить. Повторное воздействие на TRANSFORMING/ACTIVE — нулевой результат без лечения или повторного запуска анимации.

### Серверные поля (персистентные, обновляются синхронно при изменении)
- `mor_state` enum/byte (0/1/2), `mor_transform_start` либо `mor_transform_ticks_remaining` (0..50) — сохранять корректно при unload/save; пауза на выгруженном чанке, без глобальных часов; после загрузки продолжить анимацию.
- `mor_abilities`: неизменный бит разрешения по обычному `EntityType`, **не** store mutable per-ability every tick, реальные cooldown хранить transient/per-entity и сохранять ключевые one-shot стадии.
- Огненный змей: `mor_clones_summoned` boolean — сериализуется и не сбрасывается после смерти клонов / перезахода / чанка, плюс server-only UUID родителя/клонов, если используется служебная сущность. У клонов `mor_is_clone`, `mor_parent_uuid`, `mor_clone_age` и текущие 30 HP.
- Не сохранять повторно всё содержимое исходной entity: исходные UUID, custom name, equipment, positioning, attack targets и vanilla data остаются в её штатном объекте.
- При новой сущности с отсутствующими NBT полями считать NORMAL; миграция старых миров автоматическая. Оставить стабильные namespaced ключи (например, `slavicmyths:mor_state`), не использовать конфликтующий чужой key.

### Атрибуты и здоровье
СОХРАНЯТЬ прежний max HP в base attribute: поставить `MAX_HEALTH` через постоянный modifier с **стабильным UUID/ID** и operation multiply_total: Леший ×2,5, Полудница ×2, Кикимора ×2, Огненный змей ×2,5 (раздел `05_BALANCE_AND_TIMING.md`). Прежде проверить supported API конкретной MC версии для UUID vs ResourceLocation modifiers; не выдумывать сигнатуры. Не накапливать modifier после unload/reload/зелья. На входе в ACTIVE: current HP = `min(newMax, oldCurrent / oldMax * newMax)` с защитой старого max<=0; существо с 50% прежних HP сохраняет 50% новых, не излечивается сверх своей доли. Для естественного морового спавна HP=полный новый max.
После превращения повышенная агрессия игроку, без атаки союзных сюжетных персонажей. Общие атакующие навыки используются только активным состоянием; в TRANSFORMING нет атак, движения (скорость 0) и новых целей; hitbox менять только при необходимости и не расширять через потолки/двери. Урон во время трансформации проходит без особой неуязвимости, чтобы избежать exploitable долгих бессмертий.

## NATURAL SPAWN, без зелья, без новых яиц
Событие окончательной инициализации естественно созданной сущности (NeoForge `FinalizeSpawnEvent` или фактический эквивалент) **на сервере**: только четыре whitelist EntityType, только NATURAL/spawner, если это штатно естественный тип (не команды, яйца, breeding, structure placement, квестовые/именованные NPC); только Overworld; world `dayTime / 24000 >= 7` (наступление восьмых игровых суток); >160 блоков от world spawn по горизонтали. Базовая вероятность **4% на подходящее событие спавна**. Спавн полностью остаётся в прежнем разрешённом биоме/структуре/времени моба; НЕ создаётся новый спавнер для огненного змея, НЕ меняются существующие веса.
Если random hit, один **ограниченный запрос** loaded entities within AABB ±48x24x48, но не глобальный список; если уже >=1 active или transforming **моровая сущность любого из четырёх видов** в зоне, событие оставляет обычную форму. Клоны исключены из подсчёта. Ограничение вычислять только после 4% рулетки, чтобы оно не нагружало регулярный spawn. Не форсить незагруженные чанки. Если игровой мир загружает custom spawn reason, карта исходных допустимых причин проверяется адресно, без логики «все non-command».
Внешний вид и состояние естественного морового моба активируются после `finalizeSpawn` без удаления сущности. Обычные существа во всех остальных случаях остаются обычными. Специальный тестовый splash может преобразовать существующего моба вне условий дня/биома.

## Серверный боевой контроллер
- Запуск AI проверки каждые 5 тиков на активном мобе (per-entity, без глобального registry loop); выбор и проверка навыка только если живая допустимая цель ≤ указанного радиуса и, где требуются снаряды, есть line-of-sight. Таймеры cooldown по server game ticks данного моба, не системным часам; при unload таймеры просто приостанавливаются. Сохранять one-shot флаги, cooldown можно возобновлять с полным остатком после NBT загрузки для надёжного антиспама.
- Один активный спецприём одновременно, приоритет: завершающаяся анимация > оборона/позиция > готовая спецатака > обычная атака. Во время cast нельзя начинать второй cast; cooldown стартует ПО ЗАВЕРШЕНИИ навыка, кроме оговорённого момента прыжка.
- Все телеграфы имеют визуальный cue и звук до урона; projectile hits серверные; не атаковать мирных NPC, pet и allied entities; не разрушать или поджигать блоки. Respect gamerule `mobGriefing=false` в любом случае, потому что грифинг **вообще выключен для всех новых атак**.
- Damage types: использовать существующие vanilla/general типы корректно через registry access; не добавлять бесконечный новый debuff глобально. Порог HP/кулдауны строго из индивидуальных файлов.

## Синхронизация и рендер
`SynchedEntityData` либо существующий проектный channel — `mor_state`, оставшиеся transform ticks/animation start marker, текущая attack-animation ID, seed cosmetic variations, clone flag. Клиент не вычисляет исход боя. Во время морфинга три текстурные стадии: 0–15ticks обычная, 16–34 тёмные пятна+свечение, 35–50 финальная моровая; **не применять реальное плавное текстурное GPU blending**. За 50 тиков отдельные редкие square particles (≤8/tick при видимости 32 блоков) и 1 событие звука начала, 1 по завершении. Ресурсные имена регистрировать внутри существующей asset naming convention, не ломать animation format проекта.

## Книга сказаний
Если уже существующая Книга сказаний поддерживает knowledge/discoveries — добавить **одну** запись `Мор: первые признаки` в раздел тварей/сказаний (строго в существующий раздел, если есть), `ru_ru/en_us` и icon из Склянки мора; без нового GUI/полноценного квестового дерева. Разблокируется ОДИН раз на **первую встречу живого игрока в Survival/Adventure с active моровым существом в радиусе 16 блоков**; серверная проверка на этих четырёх мобах каждые 40ticks, gated `mor_active` и наличием игроков в существующей nearby query. Creative/spectator не открывает сюжет при тестах. Флаг открытия сохраняется обычной системой книги. Если книга в текущей ветке не имеет расширяемой точки — сделать адресный минимальный интеграционный вызов, но НЕ новую книгу. Краткий текст RU: «В привычном мире появились моровые твари. Багровые трещины и злоба искажают прежних обитателей. Откуда взялась хворь — неизвестно». EN локализация смысловая; не выдавать намёки на будущего Полоза и Ад как подтверждённое содержимое 1.8.1.

## Защита старых сущностей
Только whitelist: `Leshy`, `Poludnitsa`, `Kikimora`, `FireSerpent` или реальные текущие эквиваленты. Блокировать: `hasCustomName`, passenger/vehicle with player, tamed/owner, существующий quest marker, временные копии, boss encounter owner или иной текущий `protected NPC` marker. Не придумывать новые теги для сюжетных NPC, использовать фактические поля. На взрослых мирных специальных entity не действует, кроме названных четырёх. Без заражения по цепочке от ударов/ауры/смерти.
