# Сопровождение ассетов и звуков (обязательно)

## Источники и права
Базовые арт-референсы в `references/`. Их повторение ОБЯЗАТЕЛЬНО. Изображения НЕ готовые текстуры: нельзя положить 1122×1402 PNG в текстурный атлас; из них необходимо создать реальные маленькие пиксельные PNG/ModelParts, отвечающие текущему мод-рендеру. Новые model JSON/Java ModelParts/texture files отдельные от обычной формы. Не менять обычные текстуры или модели. Нормальный и моровой вариант выбирается на клиенте по синхронизированному флагу в ОДНОМ entity ID.

Отдельные files per mob — в `mobs/.../01_VISUAL.md`; конкретные анимации — `02_ANIMATION.md`; real звуки — `04_SOUNDS.md`. Общая процедура:
1. Изучить только одно существующее модельное семейство и renderer данного моба; сохранить части обычной формы.
2. Создать отдельную **реальную** corrupted текстуру с блоковым рисунком и добавочными геометрическими ModelParts. Поддержать фронт/зад/бок, UV и нормальную артикуляцию рук/головы/челюсти/крыльев или хвоста. Без проникновения пикселей в воздух при Idle.
3. Задать цвета на 16×16/32×32 визуальном уровне, без фототекстур/airbrush, outline 1px по формам. Texture atlas разрешено 64×64/128×128 либо текущий размер, если модели больше; nearest-neighbor; emissive желательно native overlay из существующего проекта (только если поддерживается), иначе яркая пиксельная текстура без нового shader pipeline.
4. Для glow/red smoke применять существующие Minecraft square particles и 1–3 маленьких красных pix particles каждые 8 ticks на видимом клиенте в радиусе ≤24 блоков; эффекты не должны быть единственным визуальным различием.
5. Проверить фактический atlas UV и renderer shader pass, что normal использует старую текстуру, mor — новую; никаких missing textures.

## Звуковая дисциплина
Для каждой формы определить: 1 idle/дыхание (низкая частота/редко), 1 начало мора, 1 особый action cue на каждый уникальный навык, 1 death/hurt (reuse существующего с указанным pitch либо новый реальный OGG). **Ни одного пустого SoundEvent**. Исходные OGG только собственные оригинальные или созданные проектом процедурно, либо напрямую vanilla registry sound events; никогда не копировать чужой саундтрек/мод/игру, не скачивать чужие аудио без лицензии. Если нет нормального источника OGG — использовать аудио из уже существующих source-sets проекта или vanilla sound event напрямую, с явной записью использованного источника.

Рекомендуемое исполнение: звуки перерождения и уникальных навыков — новые `slavicmyths` SoundEvents с физически существующими короткими `.ogg` (mono 44.1kHz) на основе авторского фоли/процедурной смеси. Если инструмент для записи недоступен, составить sound profile из зарегистрированных vanilla событий с точно заданными pitch+volume и ограниченной длительностью, а новые SoundEvents не объявлять без `.ogg`. Sound JSON каждый key указывает только существующую `.ogg` либо valid vanilla `event` sound; provider/build должен проходить проверку.

## Общие ограничения аудио
Звуки server broadcast на одно действие; не воспроизводить по одному в каждый тик. 1 idle звук раз в 8–14 sec только на видимой/живой моровой форме; transforms 1 begin+1 finish; удар попадания ≤1 per skill execution, `hurt`/`death` не дублируют обычные файлы. Radius audible: 16 blocks для обычных; 24 для змей-мини-босса. Пики громкости держать примерно на уровне vanilla hostile mobs (volume≤1.0, если не оговорено); не создавать громкого низкочастотного непрерывного гула. Если уже есть модовый SoundEvent похожей семантики, переиспользовать.

## Технические deliverables
- native модель/texture для каждого морового + рабочий packet/synced flag переключения;
- визуальная фаза трансформации;
- real audio source list + sound registrations/aliases, все события реально играют;
- ru_ru/en_us имена и tooltip Склянки;
- resource links/model bake/animation metadata gate;
- краткий `docs/verification/mor-1.8.1/ART_AUDIO_SOURCES.md`: для каждого применённого источника OGG либо vanilla event, тесты синтаксиса links и ручные пункты, без ложных заявлений о прослушивании в игре.
