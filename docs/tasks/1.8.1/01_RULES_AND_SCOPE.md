Ограничиться поиском: `rg --files src/main | rg -i '(lesh|leshy|polud|kikim|fire.?serp|ognenn|zmey|moditems|entity|sound|knowledge|book|creative)'`, затем читать только релевантные файлы; выводу `rg -n` давать жёсткие `--max-count` и точные имена. Не делать сканирование полного проекта ради красоты.
2. Нельзя перезаписывать другие механики, существующие NBT/attachments и UUID мобов, менять старые registry IDs, ломать натуральный спавн обычных форм, bossbar других боссов, рецепты, классы/навыки, рунные системы, NPC и мирогенерацию.
3. Нельзя менять модлоадер/MC/зависимости, переименовывать пакеты или переписывать базовую архитектуру. Использовать уже имеющиеся NeoForge patterns: DeferredRegister, EntityDataAccessor/attachments и `SynchedEntityData` в соответствии с фактическим кодом, стандартные AI goals, клиентскую регистрацию рендеров.
4. Нельзя создавать четыре новых entity-типа только ради моровых форм или отдельные spawn egg для них. Исключение — **строго внутренние боевые двойники Огненного змея**: при архитектурной необходимости допускается одна служебная entity для клона, без яиц, естественного спавна, лута и Creative-доступа. Предпочесть существующий тип со служебным флагом, если он сохраняет корректное AI/рендер без рекурсии.
5. Нельзя добавлять новых мобов вне списка из четырёх; нельзя заменять Огненного змея Овинником; нельзя придумывать новую крафтовую цепочку, добычу или лут Склянки мора; нельзя заразить Домового/Бабу-ягу/Баюна/сюжетных NPC.
6. Нельзя запускать игру/PolyMC/GUI/client/world. Разрешено редактировать файл тестового профиля PolyMC и копировать собранный JAR ПОСЛЕ проверок.
7. Нельзя выдавать компиляцию за игру, загрузку NBT за ручной перезаход, ресурсную проверку за FPS/MSPT или потенциальный рендер за визуально утверждённую готовность.
8. Нельзя добавлять бесконечные global entity scans, обходы всех игроков каждый тик, принудительную загрузку чанков, тяжёлые сетевые пакеты каждый тик, новый animation engine без необходимости.
9. Нельзя подставлять пустые PNG, dummy sounds, фиолетово-чёрные missing textures, noop-атаки, несуществующие эффекты или невыполненные TODO. Если звук не удаётся записать, использовать **реальное** допустимое vanilla/существующее звуковое событие из конкретного списка звуков, не молчаливый stub; сами новые звуковые события только с существующим источником.
10. Нельзя оставлять английские ключи интерфейса при ru_ru, забывать en_us, ломать UTF-8.

## Перед редактированием, строго адресно
- `git status --short` и `git branch --show-current`; не очищать чужие изменения.
- `gradle.properties`, NeoForge metadata mod ID/version; реальные entity IDs через `ModEntities`/похожий реестр; `Leshy`, `Poludnitsa`, `Kikimora`, `FireSerpent` или действительные эквиваленты. В репозитории код мог двигаться: **не угадывать пути/типы**, определить точные имена из целевого поискового списка.
- У каждого: модель, renderer, texture, базовые AI goals, параметры, естественный spawn и death loot; затем Book/knowledge и звук. Проверить, что мобильные существа действительно имеют нужную базовую модель; не копировать весь Java файл в новую версию.
- Прочесть только нужные короткие разделы `docs/PROJECT_STATUS.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`; не считать устаревшее README отражением состояния `main`.

## Принципы внедрения
- Сервер принимает решения: начало превращения, HP, агрессия, cooldown, попадание, спавн/смерть двойников, разовая запись знания. Клиент отображает только синхронизированную модель, текстуру, частицы и анимации.
- Единая функция применить мор принимает **явно разрешённый** тип сущности; idempotent: повтор не усиливает/не лечит и не меняет UUID. Пока идёт превращение нет обычных атак, входящий урон проходит по правилам из `02_CORE_SYSTEM.md`.
- Common-код никогда не ссылается на клиентские классы. Использовать фактический event bus проекта, без клиентских вызовов с сервера.
- Архитектура расширения: одна небольшая общая state/controller ветка и 4 отдельных контроллера способностей/визуалов, без 4 изолированных копий одинакового кода.
- Достаточная оптимизация: отсутствие каждого-тикового локального world entity scan; проверки 10/20/40 тиков, атаки по target+LOS, частицы с локальным количеством, штатный despawn и без тикетов чанков.
- Настройки не должны ломать старые сущности в мирах: отсутствие флага = обычная форма; моровой флаг после загрузки пересчитывает применимые атрибуты один раз.
- Ранее добавленные питомцы и квестовые отношения не меняются. Не допускать поражения named/tamed/quest NPC без отдельного прямого решения — см. whitelist/blacklist.

## Визуальное качество
Minecraft native box geometry и pixelated textures. Референс — цель **формы, а не рендера с HDR-шейдерами**. Реальный `ModelPart` с кубоидами/отдельными рогами, шипами, волосами, крыльями/плавниками в пределах текущей инфраструктуры; пиксельные фактуры с nearest-neighbor, без сглаженных градиентов. Для каждого отдельная коррумпированная текстура и немного дополнительной геометрии. Замена одним красным тинтом/частицами — НЕ считается выполнением.
