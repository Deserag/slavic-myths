Это сохранённое требование пользователя для последующей реализации, не задача
на установку/публикацию в аналитическом1.9.8.1. Сейчас1.9.8.2 не начинается.

1. Перед зависимыми изменениями закрыть решения B1–B4 из REPORT.md. До подтверждения
   cursed_volkolak700 не внедрять. Не переносить PROPOSED в код как VERIFIED.
2. Учитывать параллельную разработку нескольких аспектов: сначала git status,
   сохранить чужие правки, выделить собственный diff и выбранный состав сборки.
   Название поставки/запись changelog должна дописывать **«патч оружия» поверх
   актуальной версии**, а не обозначать поставку одним номером. Не откатывать
   другие аспекты и не менять registry IDs. Эта подпись не означает, что в
   аналитическом аудите уже реализован баланс или исправлено оружие.
3. Если реализация включает новое оружие, до введения описать его силуэт,
   относительные размеры, материалы и отличительные признаки. Меч/кинжал/копьё/
   топор/булава/посох/щит должны различаться формой и пропорциями.
4. После реализации выполнить clean build с JDK21, проверку актуальных ресурсов
   и production NeoForge JAR, исключить tools/smoke. Зафиксировать результаты и
   SHA256 именно выбранного совместного артефакта. Клиент автоматически не запускать.
   При разрешённом запуске проверять runtime logs и повторять после runtime правок;
   число реальных запусков писать явно. Для механик использовать отдельный тестовый
   мир/копию, без перезаписи пользовательских миров.

   вне mods, сохранить остальные моды/конфигурации/миры, установить ровно один
   актуальный production JAR. Старый PolyMC1.16.5 не перезаписывать.
   В отчёте установки указать версию **+ «патч оружия»**, пути и SHA256.
6. Обновить проект в Git по указанию пользователя после реализации: подготовить
   проверенный diff и документы с подписью «патч оружия», учитывать границы
   параллельной работы; не включать чужие незавершённые изменения автоматически.
   Постоянное правило AGENTS.md «Не делайте commit автоматически» сохраняется:
   фактический commit/push выполняется по явному распоряжению на соответствующую
   поставку. Требование обновления Git не считать уже выполненной публикацией.
   Для собственной реализации пользователь уточнил точное имя ветки: **`audit`**.
   Подготовить её отдельно от текущей ветки/параллельных worktree и включить только
   собственные файлы и собственные изменения в общих документах. Не использовать
   `git add .` для всего рабочего дерева. Отчёт и manifest своих файлов хранить
   в `docs/implementation/creatures-1.9.8.2/`, как отдельную папку результата.
   Ветка/подготовленные изменения не означают commit или push: они выполняются
   только по отдельному распоряжению, как требует приложенное ТЗ первого этапа.
