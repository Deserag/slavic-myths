# Slavic Myths 2.6 — журнал изменения скорости кораблей, 11.11.2026

## Принятый исходник и запрет на регрессии

- **Неприкосновенная база:** ветка `ship-release-20261111`, коммит `d965d5c845c58f14c676931ef9621499573f926f`.
- **Доработка только в:** `feat/2.6-ship-speed-sails-20261111` (от указанного коммита).
- Обязательно читать `docs/SHIP_MOTION_RELEASE_20261111.md` перед изменениями сетевой позы, движения, экипажа, палубы, колеса или интерполяции.
- Коммит Codex `d965d5c84` сохранил единый предыдущий rigid-body transform `xo/yo/zo/yRotO`, аналогичную предыдущую позу капитана из координат корпуса, физическое движение палитры отсоединённых блоков, клиентскую интеграцию авторитетной скорости/угла без трёхтикового преследования пакетов, защиту от устаревших пакетов Boat, перенос экипажа и безопасный сход без телепортационного рывка.
- Также приняты V10 кормы/паруса, рендер и локальное положение штурвала: капитан на `z=-4`, колесо на `z=-3.25`. Сохранены миграции V7/V8 в V10 и модульная V9.
- **Не изменено в этой доработке:** `FirstShipEntity`, `FirstShipNetwork`, `FirstShipSteeringClient`, `FirstShipMovingDeckEvents`, `MovingShipVehiclePacketMixin`, геометрия, NBT/ID, правила валидации полного корпуса, ограничение угловой скорости и логика парковки.
- Подтверждения именно принятого выпуска: 22 GameTest и внутриигровая плавность по заявлению владельца. Подробные метрики покадровой ошибки есть в исходном документе. Это не результаты тестов новой скорости.

## Почему корабль был медленным

- `ShipRigidMotion.MAX_FORWARD` до изменения: `0.18` блока/тик.
- `ShipSailMotion.power(1,1)` для обычного корабля: `0.40`, после множителя `LINEAR_DRAG=0.985` итог `0.18 * 0.4 * 0.985 = 0.07092` блока/тик (1.4184 блока/с при 20 TPS).
- Для модульных кораблей `rawThrust()/loadFactor()` (снизу ограниченный старым вызовом минимумом 0.16) дополнительно обрушивал скорость одного паруса на крупном корпусе.
- Обычная ванильная лодка Java на воде имеет ориентировочную максимальную скорость `0.4` блока/тик, то есть `8` блоков/с. Источник для сравнения: https://minecraft.wiki/w/Boat. Это контрольный теоретический ориентир; одновременная гонка в игре пока не проводилась.

## Новая модель баланса

1. `ShipRigidMotion.MAX_FORWARD = 0.54`: **ровно ×3 относительно прежнего ограничения**. `MAX_REVERSE`, `ACCELERATION`, `LINEAR_DRAG`, `MAX_ANGULAR`, `ANGULAR_ACCELERATION` и swept collision не менялись. `FirstShipEntity` уже автоматически использует эту константу для ограничения пришедшей клиенту скорости.
2. Для обычного корпуса с парусами: `power = 0.80 + 0.20 * min(1, (effectiveThrust - 1) / 3.5)`, где `effectiveThrust` вычисляется из качества ткани и уровня такелажа. Начальный парус (1/1) = `0.80`, максимальный (4/3) = `1.00`. Уровни ткани/такелажа продолжают давать реальное увеличение. Без парусов гребная тяга = `0.16`.
3. Для модульного корабля при непустом наборе парусов: `efficiency = min(1, rawThrust / loadFactor)`, `sailUpgrade = min(1, (rawThrust - 1)/3.5)`, `propulsionFactor = 0.60 + 0.20*efficiency + 0.20*sailUpgrade`. Площадь ватерлинии, число палуб, мостик и каюта повышают `loadFactor`, а число и уровни парусов повышают `rawThrust`.
4. Стартовый модульный 7×11 с парусом уровня I получает **ровно ту же тягу**, что и обычный 7×11 с начальным парусом. Пустые паруса сохраняют существующее гребное ограничение на стороне `FirstShipEntity`, не меняется NBT и сетевой протокол.
5. При росте размера без улучшения парусов скорость намеренно падает. У крупных многомачтовых судов правильно подобранные паруса компенсируют массу. Предел скорости одинаков для всех, но фактический результат зависит от конфигурации.

**Важно:** фактическое ускорение базового обычного корабля относительно ранее работавшего стартового паруса получается примерно ×6, а не ×3: кроме утроения физического лимита пришлось поднять стартовую тягу с 0.4 до 0.8, иначе корабль оставался бы медленнее лодки. Физический максимальный лимит при этом ×3. Если потребуются строго ×3 именно по фактической скорости, нельзя одновременно сохранить требование обгонять лодку на стартовом парусе.

## Регрессионная защита и статус

Добавлен исходник `tools/ocean26-tests/org/slavicmyths/verify/Ocean26ShipSpeedGameTests.java` в изолированный тестовый набор `-Pocean26Check` (не входит в production JAR). Три новых GameTest:

## Как проверять без риска для принятого выпуска

1. Сначала собирать и проверять новый код отдельно: `gradlew.bat build -Pocean26Check --offline` (изолированная компиляция тестов); при отдельном разрешении владельца — `gradlew.bat runOcean26Checks -Pocean26Check --offline`. Не считать старые 22 теста результатом новой ветки.
2. На копии мира с единственным установленным новым JAR провести гонку с обычной лодкой по прямой на воде. Измерить 100 блоков и 20 TPS. Отдельно стартовый/максимальный обычный корабль и малый/средний/большой модульный с перечисленными парусами.
3. Обязательно проверить длинный W, W+A/D, плавный поворот с капитаном в третьем лице, сход Shift, экипаж на палубе, стену/берег/мелководье и парковку. Сравнить покадровую ошибку капитан-корпус с `docs/SHIP_MOTION_RELEASE_20261111.md` (порог не ухудшать без причины).
4. Проверить сохранение, перезаход, восстановление груза и корпус V7/V8→V10, в том числе multiplayer. В PolyMC оставить ровно один JAR и сверить SHA-256.
5. Если появляются рывки или проблемы производительности из-за дополнительных collision sweep шагов при 0.54 блока/тик, откатить feature-ветку/её коммиты; **не** переписывать принятый механизм плавности вслепую.
