# 1.8.3.1 — интерфейс заражения, persistence и тесты

## Серверный сервис замены
Реализовать узкую функцию-сервис (имя в стиле проекта), принимающую ServerLevel + BlockPos + reason/cause и возвращающую один из `CONVERTED`, `NOT_SUPPORTED`, `ALREADY_INFECTED`, `PROTECTED`, `NOT_LOADED`, `BLOCKED_BY_EVENT`.
- По точному сопоставлению 12 registry ID заменяет исходный blockstate; переносит `AXIS`, `DISTANCE/PERSISTENT/WATERLOGGED` (листва), при необходимости `SNOWY` у дёрна; без потери соседних данных.
- Не трогает предметы/BlockEntity, которые не имеют поддерживаемого аналога; никогда не заменяет воздух или жидкость.
- Не создаёт грабящие обновления блоков; очередь заражения в дальнейшем создаёт только событие Полоза.
- Пометить изменение как обычную server-side block update с соседними/lighting updates, чтобы клиент/сервер были синхронны.

## Тест без босса
Только `/sm test mor_block <ключ>` (или по существующему паттерну команд): однократно заражает выбранный подходящий целевой блок, на котором смотрит оператор, и выводит результат. Только operator level 2, не для обычного survival, не меняет инвентари. Подкоманда `/sm test mor_block reset` заменяет блок обратно в базовый прототип через отображение; это dev-инструмент, не survival-cleansing.

## Гейты
1. Все 12 зарегистрированы, имеют корректные blockstate/model/item/loot/tags/локализацию.
2. Базовые vanilla blocks по тем же 12 ID без изменений global appearance или mechanics.
3. Поражение только выбранного блока; соседние не затрагиваются сами собой.
4. Гравий/песок падают; брёвна сохраняют AXIS; листья не превращаются в нерушимый камень; obsidian остаётся сложным для добычи.
5. Сервер перезапущен: блоки сохраняются; не происходит автоматической очистки.
6. Пользователь на заражённом участке получает эффекты не раньше заданных 3/5 секунд, уходящий из зоны избавляется от них.
7. В Creative не наносится damage, множественные источники не складываются до смертельных величин.
8. JAR build проходит *после* этой части, до добавления босса.
