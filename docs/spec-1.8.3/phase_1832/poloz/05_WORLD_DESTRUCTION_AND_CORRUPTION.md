# Поступь гибели — реальные разрушение и заражение поверхности

## Два разных действия
**РАЗРУШЕНИЕ**: физический объём движущейся головы и тела (ширина 3–4 блока, большая масса) уничтожает допустимые окружающие блоки — дерево, листву, заборы, постройки и камень. Босс прокладывает путь через лес/здания, оставляя руины. Это НЕ партиклы и НЕ временный overlay.
**ПОРАЖЕНИЕ МАТЕРИАЛА**: уцелевшие поверхности вдоль всей траектории тела меняют blockstate на соответствующий `slavicmyths:mor_*` из 1.8.3.1; сохраняются после победы. Не заражать «весь мир» глобальным event wave: только непосредственный **контакт** + обоснованное малое кольцо у тела/снарядов.

## Геометрия зон
- Collision path для головы и 24 сегментов каждые 4 ticks; sweep volume между предыдущей и текущей позициями, чтобы быстрый рывок не пролетал сквозь деревья. Разрушение строго внутри colliding volume + 0.5 блока safety зазора, no spherical mass blast радиусом 100.
- Заражение **на опорной земле вдоль тела**: радиус 2.5 блока от осевой линии до соседних surfaces в I фазе, 3.5 во II, 4.5 в III; учитываются только support surfaces в верхнем слое (+/-1 y вокруг path), а скала/стена может заражаться при реальном касании тела. Сквозь толстые стены/подземные слои самопроизвольно не заражать.
- Поражение блока включается только если `canConvert()` 12 supported vanilla types; уже заражённые пропустить, блоки с BlockEntity не заменять. Это временный runtime operation, но **результирующий блок постоянен**.
- Уничтожение покрывает **только loaded и unprotected** blocks. Исключения: bedrock, barrier, command/structure/jigsaw/end portal blocks, obsidian end-frame tech, protected claims / admin protected zones (если интеграция существует), server configs; World border respected. Игроков от катастрофы не защищать невидимой ареной.
- Двери, сундуки, крыши, брёвна, камень, земля, стекло, фермы и большинство обычных player-built blocks **МОГУТ БЫТЬ РАЗРУШЕНЫ**. Не делать no-grief safety для построек вопреки утверждённой идее. Однако гибель контейнера обязана выдать/обработать item drops/contents один раз и honour `mobGriefing`/`doTileDrops`.
- При разрушении дерева/листвы фактический мир меняется: block updates корректны, растения могут выпадать, источники воды не удаляются, нет отмены повреждений после гибели.

## Производительность: очереди с пределом
- Только server event, bounded plan/snapshot near body. Потолки **32 block-break операций за tick**, **48 block-conversion операций за tick**, очередь каждого типа максимум 2048 уникальных `BlockPos`; при заполнении соединять/отбрасывать дальние позиции в пользу ближайших к голове и активному пути, а не бесконечно расти.
- Менять позиции один раз/сегмент за tick, избегать многократной обработки одного блока при наложении hitboxes. Нельзя ставить 1000 `setBlock` в одном tick, разрушать блоки из unloaded chunks, рекурсивно обойти целый лес.
- На один активный `great_poloz` единый список chunk-impact и очереди, не каждое body-segment entity сканирует блоки отдельно.
- Prioritize break collision before convert; если блок разрушен, не заменять там же воздух на infected matter.
- Ограничить item drops обычным `doTileDrops` с native handling, не собирать в одну гигантскую кучу по 10 000 `ItemEntity` на сервере: использовать существующие общие drop aggregation механизмы или bounded packing без потери ценных container items, не дублировать/drop-delete инвентари.

## Долговременные последствия
После победы: отключить разрушение/распространение, порождения мора из вызова исчезают, **сами поражённые блоки и разрушенные постройки остаются**. Никакого авто-restoration 20–30 сек — это только прежняя временная земля 1.8.2, не Полоз. Книга сказаний должна объяснить, что очищение мира позже станет отдельной механикой.

## Если `mobGriefing=false`
Вызов запрещён с сообщением на этапе ритуала, чтобы не создавать «безопасную подделку» мирового ивента. Административная отмена тестового события не должна автоматом восстановить сломанный мир — предупредить администратора.
