# Система диалоговых окон и мягкое возвращение к игре

## GUI
Использовать существующий модовый UI NPC. Там, где он не позволяет показывать 3 собеседников по очереди, добавить минимальный слой `speakerId + dialogueKey + choices`, а не новый UI framework.

## Отображение
- Лицо/портрет — пиксельная текущая модель головы NPC или существующая иконка, НЕ скриншоты AI-постера.
- Имя говорящего выделено янтарным, текст 1–3 строки, переход «Далее» по Enter/Space/клику.
- При участии трёх имена «Баба-яга», «Кот Баюн», «Серый Волк» меняются по репликам, все три видимы в сцене при условии доверия.
- Если кто-то отсутствует, не показывать серую заблокированную карточку/силуэт — просто нет ветки.
- При выборе «Приду сам» диалог пригласителя закрывается корректно.
- Надпись «Серый Волк» в UI соответствует существующей локализации, а не `GrayWolfEntity`.

## Обработка прерываний
- При Escape сцена сохраняет `dialoguePageIndex`, `questCandidateState`, player session UUID; следующий визит предлагает «Продолжить разговор».
- Не держать серверный chunk ticket навечно после выхода.
- Если игрок в бою/получает урон, необязательная сцена может безопасно закрыться и сохранить прогресс, NPC actors очистить.
- Если NPC исчез из загруженного чанка между страницами, сервер продолжает диалог по проверенной session/known location и не кидает NPE; после завершения нет ghost-entities.

## Разделение trust и сцены
Баба всегда ведущая; низкая доверительность Яги меняет только её первый приветственный текст, а не блокирует возможность завершения основного квеста. Баюн и Волк с trust II участвуют в сцене; низкое доверие не отнимает их имеющиеся старые задания.
