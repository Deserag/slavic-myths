# Slavic Myths 2.2.8 — «Грядки и житница», проект R1

**Решение владельца 29.10.2026:** продолжать самостоятельное архитектурное проектирование после 2.2.7. Ветка **`hell`**, Minecraft 1.21.1 / NeoForge. **Статус: точная проектная модель, не рабочий WorldGen и не прошедший Minecraft QA.**

## Состав и точные границы
- Городской участок **X=76..100,Z=12..39** (25×28), Y0 = пол городской площадки. Все локальные координаты в модели: u=X−76,v=Z−12.
- Житница **X=78..89,Z=14..24 (12×11)**, единственный этаж, 2-блочный центральный проход, 4 сундука.
- Инструментальный сарай **X=80..87,Z=32..37 (8×6)**, один сундук, рабочее место и бочки.
- Грядки нароста **X=92..99,Z=14..24 (8×11)**, две полосы soul sand + nether wart и проход по центру.
- Нилиевые грядки **X=92..99,Z=28..36 (8×9)**: crimson/warped nylium, грибы и корни; по центру проход для сбора.
- Открытый хозяйственный двор **X=78..89,Z=25..31 (12×7 по фактической модели; открыт до Y1)**; двухблочная продольная дорожка **X=90..91, Z=14..38**, вход с запада.
- [Единая машинная модель R1] (MODEL_R1.json) — 1349 non-air блоков на Y=0..10, реальные block IDs и blockstates.
- [План Y1](./PLAN_Y1.svg), [кровля](./ROOF.svg), [11 послойных схем](./layers), [4 фасада](./facades), [7 функциональных зон](./rooms), [3 разреза](./SECTION_LONGITUDINAL.svg), [автопроверка](./VALIDATION_R1.json).
- [5 отдельных ресурсных loot table JSON](./loot_drafts), [техническое ТЗ](./SPEC_R1.md), [стандартные проверки](./QA_CHECKLIST.md).
- [Оригинальная пиксель-арт изометрия, PNG](./art/GRANARY_ISO_PIXEL_R1.png) — рисунок из данной блочной модели; это **не скриншот Minecraft** и не полный ИИ-арт из чата.

В 2.2.8 не добавляем предметы, блоки, GUI, NPC, полноценную фермерскую систему. Грядки адского нароста растут на soul sand без воды; растения на нилии нельзя считать автоматически возобновляющимися без дополнительных действий игрока. Строительный модуль строго фиксирован; никакой самостоятельной случайной генерации.

> Исполнительное GitHub Issue фиксирует проект для Codex, но не доказывает существование кода города. Достройка существующих городов требует отдельной безопасной реализации.
