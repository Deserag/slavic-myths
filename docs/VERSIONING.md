# Версии и публикации

## Единственный номер исходников

Авторитетный номер — `mod_version` в [gradle.properties](../gradle.properties). Сейчас это **1.9.7.5**, историческая четырёхкомпонентная схема, не стандартный SemVer. Очистка не меняет номер и не публикует релиз.

[build.gradle](../build.gradle) получает номер через `version = mod_version`; `processResources` подставляет его в [neoforge.mods.toml](../src/main/resources/META-INF/neoforge.mods.toml). Имя JAR формируется Gradle: `slavicmyths-${mod_version}.jar`. Не вписывать второй независимый номер в metadata или код. Проверка `tools/recovery-43/source_gates.py` сравнивает properties, production metadata и имя JAR.

README сообщает source version и отдельно фактически опубликованные кандидаты. При смене версии обновляются запись properties, раздел текущего CHANGELOG и статус README; исторические отчёты не переименовываются задним числом. До публикации запись CHANGELOG не становится «вышедшим релизом».

## Статусы

| Статус | Значение |
|---|---|
| Development/source build | Сборка конкретного commit; build PASS не означает публикацию или игровую приёмку. |
| Local test candidate | Артефакт и SHA256 сохранены для проверки; локальная установка не делает его публичным. |
| Published RC | Подтверждены tag, GitHub Release, prerelease, JAR и checksum. |
| Stable | Отдельное решение о готовности, завершённая приёмка и опубликованный релиз. |
| Planned | Roadmap; будущий номер не присваивается текущему JAR. |

На 2026-10-18 опубликованы только [v0.9.10-rc1](https://github.com/Deserag/slavic-myths/releases/tag/v0.9.10-rc1) и [v0.9.10-rc2](https://github.com/Deserag/slavic-myths/releases/tag/v0.9.10-rc2). Локальные JAR 1.6–1.9 не являются GitHub Releases. Теги `archive/*` сохраняют Git-состояние и не означают выпуск мода.

## Следующая согласованная схема

После отдельного решения предлагается SemVer: `2.0.0-rc.1` — кандидат, `2.0.0` — стабильная версия после приёмки, `2.0.1` — совместимые исправления, `2.1.0` — совместимый новый контент. Это примеры будущего процесса, не созданные публикации.

PATCH исправляет ошибки без намеренного изменения совместимости; MINOR добавляет совместимое содержимое; MAJOR обозначает согласованные несовместимые изменения. Совместимость Minecraft/NeoForge и сохранений указывается отдельно. Registry ID нельзя свободно переименовывать даже при повышении MAJOR: нужны явная миграция и проверка миров.

## Процедура выпуска

1. Выбрать принятый commit основной ветки и номер; обновить properties, CHANGELOG и README. Открытые PR и локальные изменения не включаются автоматически.
2. Выполнить Java 21 clean build и ресурсные/production JAR gates. Отдельно получить разрешение на игру и выполнить требуемую клиентскую/серверную/мультиплеерную приёмку. Число запусков и ограничения указывать честно.
3. Сохранить JAR и SHA256 вне дерева исходников; сверить metadata, имя, зависимости и отсутствие smoke/test-классов. Бинарники, build, профили и логи в Git не коммитятся.
4. После решения о публикации создать неизменяемый tag `v<version>` на принятом commit и GitHub Release с JAR и SHA256SUMS. RC помечается prerelease. При отсутствии asset не давать ссылку «скачать» на архив исходников.
5. Проверить скачанный asset по SHA256, затем отметить публикацию в CHANGELOG. Не передвигать старые release tags и не подменять asset молча.

## Откат

Исходники откатываются обычным revert через review, без переписывания истории. Игровой откат требует совместимой копии мира и предыдущего JAR. Старые локальные бинарники и инструменты восстановимы из [архива](maintenance/issue-43/HISTORICAL_ARTIFACTS.md); их проверки не подходят автоматически новой версии.
