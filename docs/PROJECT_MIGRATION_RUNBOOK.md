# Перенос задач в GitHub Project №9

Адрес: https://github.com/users/Deserag/projects/9/views/1

Исходники автоматизации:
- [GitHub Actions](../.github/workflows/project-9-migration.yml)
- [Сценарий миграции](../tools/project-migration/sync.py)
- [Матрица задач и статусов](../tools/project-migration/config.json)

## Почему требуется отдельное разрешение

Текущее подключение ChatGPT к GitHub не позволяет записывать карточки в пользовательский GitHub Projects. Публичная видимость доски не даёт право записи. Обычный репозиторный GITHUB_TOKEN также не умеет обращаться к пользовательским Projects. Миграция выполняется в GitHub Actions с защищённым репозиторным секретом. **Никогда не отправляйте PAT в чат, Issue, документ, коммит или лог.**

## Что сделать владельцу один раз

1. Откройте GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token. Выдайте scope **project** для доступа к пользовательскому GitHub Project №9. Для приватного репозитория потребуются дополнительные права чтения Issues. Ограничьте срок токена.
2. Откройте настройки репозитория: **Settings → Secrets and variables → Actions → New repository secret**. Имя: **SLAVIC_PROJECTS_TOKEN**. Значение: созданный PAT.
3. Откройте [Actions репозитория](https://github.com/Deserag/slavic-myths/actions/workflows/project-9-migration.yml), выберите **Run workflow**, сначала оставьте **apply = false**. Это сухой прогон, ничего не изменяет. Посмотрите лог и Job Summary.
4. Повторно запустите workflow с **apply = true**, **include_closed = true**, **overwrite_existing_status = true** (только для первичной полной миграции, если не требуется сохранить ручные статусы). Теперь карточки будут реально добавлены и классифицированы.
5. Проверьте [доску](https://github.com/users/Deserag/projects/9/views/1) после успешного завершения.

Если в Project уже вручную установлены важные статусы, выбирайте **overwrite_existing_status = false**. Иначе скрипт заменит их матрицей проекта.

## Что переносится

- Связь пользовательского Project №9 с репозиторием Deserag/slavic-myths, если её ещё нет.
- Восемь согласованных статусов, поля Priority, Релиз, Направление и Порядок.
- Представления Работа, Очередь Codex, Тестирование, Доработка, Идеи, Релизы.
- Все существующие Issues (включая исторические закрытые, если include_closed = true), без Pull Requests.
- Индивидуальные назначения по утверждённой матрице. Текущие руны/броня в работе; трофеи следующими; оружие последним большим художественным пакетом; ранее сделанные #76/#77/#79/#82/#83/#90 ожидают теста.
- Закрытые без ручной приёмки задачи не становятся автоматически Готово. #84 относится к Отменена для дальнейшего реворка и остаётся закрытой.
- Существующие ID карточек, статусы и пользовательские представления сохраняются, если это не противоречит явно выбранной опции перезаписи.

**Импорт не меняет код Minecraft, не закрывает и не переоткрывает GitHub Issues, не выполняет игровые тесты.**

## Что проверить

Проверьте, что карточки #92 и #110–114 стоят перед #87 и #115–121; #88 содержит восемь этапов; #105 не исполняется до принятия #104; #91 и #106–109 требуют аудита перед переработкой; закрытая #84 не помечена как принятие всего ранее сделанного.

Учитывайте, что Parent Issue и дочерние Issue являются отдельными карточками с собственными статусами. Закрытие родителя автоматически не означает завершение всех детей.

## Повторное выполнение

Сценарий идемпотентен: уже существующие в Project Issues повторно не добавляются. При ошибке используйте Job Summary, исправьте причину и повторите запуск. Для последующих прогонов рекомендуем **overwrite_existing_status = false**, чтобы не перетирать ручные изменения владельца.
