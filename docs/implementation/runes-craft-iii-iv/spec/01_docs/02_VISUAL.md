# 02 — Художественное ТЗ и правила работы с чертежами

## Что уже приложено

В архиве **не просто описания**, а полноценные растровые листы и отдельные иллюстрации:
- `02_blueprints/sheets/01_ALL_RUNES_REFERENCE.png` — общий лист **4 руны III + 4 новые IV + новая заготовка IV**;
- `02_blueprints/sheets/02_TECHNICAL_BLUEPRINTS.png` — техническая таблица с именами, геометрией, схемами и визуальной иерархией;
- `02_blueprints/sheets/03_CONCEPT_PENCIL_SKETCHES.png` — дополнительный рисованный чертёж существующих III рун;
- `02_blueprints/concept_icons/tier_III/*.png`, `tier_IV/*.png` — **отдельные картинки каждой руны** в высоком разрешении плюс 64px уменьшенные превью;
- `03_mappings/ASSET_MAP.csv` — карта изображений и логики.

Важно: исходные PNG — **арт-референсы / чертежи**, а не гарантированно пригодные для прямой вставки game-ready 64×64 иконки. У части референсов тёмный фон, сложная подсветка и очень тонкие детали. Codex должен получить **читаемую пиксель-арт реализацию без тёмной квадратной подложки, если существующие иконки проекта прозрачные**. Не просто уменьшить 512×512 с Lanczos и назвать финальной текстурой.

## Арт-дирекшен

Стиль: **славянская мифология, тяжёлый рунический камень, серебряная гравировка, локальный свет из резной борозды**. Не использовать логотипы, латинские буквы, текст на самой руне, фото и глянцевые sci-fi UI-детали. Никаких квадратных чёрных задников на игровых иконках. Силуэт и знак должны читаться в 32 и 64 пикселях.

### Четыре III — проверка уже внедрённого визуала

| Руна | Геометрия | Палитра |
|---|---|---|
| Ответный удар | два встречных клинка / рунические углы | красный, угольный |
| Охотник | натянутый лук и стрела | нефритово-зелёный |
| Последний рубеж | центральное солнце-щит | золотой/бронзовый |
| Глубины | кристалл и глубокий ромб | лазурит и синий |

**Если существующая III иконка в предыдущем патче функциональна и читабельна, не перерисовывать автоматически**. Чертежи III — ориентир на будущее; критична целостность текущего патча.

### Четыре новых IV — производство обязательно

| Руна | Основной знак | Доминирующий цвет | Отличие от III |
|---|---|---|---|
| Несокрушимости | щит с восходящим нерушимым знаком | морозный синий / серебро | чёткий тяжёлый шестиугольник, нет золотого солнечного диска |
| Перуновой ярости | угловатый громовой разряд | красно-оранжевый / раскалённый | центральная молния, а не два встречных клинка |
| Духа леса | дерево с 3 ветвями и корнями | изумрудный / тёмный камень | живое дерево, а не инструменты |
| Мастерства | скрещённые кирки / молоты | сочный зелёный / металл | железные инструменты внутри камня; визуально отличать от дерева |
| Заготовка IV | **пустой** восьмиугольный камень с незаполненным вырезом | серебристый и тёмный сланец | не иметь активной цветной светящейся руны |

Руна Духа леса намеренно использует зелёное дерево с одного из вложенных художественных листов, а Мастерство — отдельный зелёный символ инструментов. Это **разные** иконки.

## Форматы и игровые ресурсы

- Каждая из 4 новых IV рун и blank IV: texture PNG **64×64** в `assets/slavicmyths/textures/item/`, альфа-канал, пиксель-арт, без прозрачных полупиксельных ореолов. При финальном уменьшении проверить 32×32.
- Модели предметов `assets/slavicmyths/models/item/<id>.json`, по архитектуре остальных рун: `minecraft:item/generated` или локальный эквивалент; используйте существующие актуальные соглашения.
- **Никаких обязательных 3D-мешей, blockbench-проектов или анимаций для инвентарных рун.** Обычная иконка = корректная 2D модель предмета в GUI и в руке. Объёмные рельефные варианты на чертежах служат для разработки текстуры, а не требованием вводить 3D-рендер.
- Изобразительное задание считается завершённым, если 5 новых текстур имеют различимые силуэты на 64×64 и 32×32, правильные filenames, registered items корректно отображаются в GUI/JEI.
- Не менять из-за этой задачи иконки старого оружия, брони, Полоза, Горыныча и 37 исходных рун.

## Жёсткое соответствие ресурсов

Использовать `ASSET_MAP.csv`; финальную таблицу concept ID → *реальный* item ID → texture path → model path добавить к `FILES.md`. Наименования existing III брать из локального реестра, никаких дублирующих ID.
