# 04 — Критерии приёмки / checklist

## A. Код и архитектура
- [ ] Снято состояние локального repo/working tree, чужие изменения не затёрты; создан краткий список существующих III ID.
- [ ] Четыре III из прошлого патча работают и крафтятся; **нет второго набора предметов с новыми ID**.
- [ ] Сохранены **все** существующие registry IDs, рецепты и свойства Велесовой клятвы / Полоза / Горыныча.
- [ ] Созданы `blank_rune_4` + ровно четыре новых IV rune item ID.
- [ ] `RuneBase` сериализует I–IV и прежние комбинации материалов без изменений, произвольные недопустимые комбинации отклоняются.
- [ ] Нельзя установить IV на неподходящий предмет и нельзя вставить две одинаковые IV в один предмет.
- [ ] В обновлённой рунической наковальне изменения активных эффектов видны сразу; после снятия эффекты исчезают.

## B. Рецепты и прогрессия
- [ ] Все 5 новых JSON валидны для **существующего** `rune_crafting`, ≤3 input, item IDs существуют.
- [ ] Крафт `blank_rune_4` сохраняет компонент tier=4, material=perunite.
- [ ] Каждый рецепт IV отвергает I/II/III основы, требует правильную IV и возвращает 1 руну.
- [ ] JEI отражает пять рецептов, конкретные количества и IV основу; нет отсутствующих переводов.
- [ ] Новый IV крафт поздний по реальной достижимости ингредиентов; при необходимости опиши замечания без самовольной перестройки прогрессии.

## C. Правила механик
- [ ] Ответный удар: окно 4 с и CD 20 с, подтверждённый блок, один удар, без повторной активации AoE.
- [ ] Охотник: 12+ блоков, ×1.12, CD 7 с, только выпущенный нужным луком снаряд.
- [ ] Последний рубеж: ≤35% HP, 6 HP минимального входящего урона, −12%, CD 45 с.
- [ ] Глубины: только руда Y≤32, скоростные капы, правильное сложение с шахтёрскими рунами.
- [ ] Несокрушимость: ≥8 HP, −25%, CD 50 с, активный щит/надетый нагрудник, нет оплаты CD за нулевой урон.
- [ ] Ярость: 4 честных сильных удара, окно 8 с, 5 с эффект, +16% урона/+10% скорости, CD 45 с, без вторичного урона.
- [ ] Дух леса: ≤50% HP, 6 с без получения урона, 1 HP/3 с в течение 12 с, CD 60 с; новые удары обрывают эффект.
- [ ] Мастерство: +25% mining speed ore (общий cap +35%), +1 Fortune до IV, полная несовместимость с Silk Touch.
- [ ] Одновременное срабатывание Last Stand III и Unbreakable IV не тратит два CD; приоритет IV.
- [ ] Нет дублирования эффектов от одинаковых IV на разных слотах, чужие уникальные руны работают как прежде.

## D. Графика и локализация
- [ ] Есть **5 новых 64×64 PNG** с прозрачностью и читаемой пиксельной графикой, без вшитых меток/фоновых прямоугольников.
- [ ] Есть 5 корректных item models, текстуры читаются в 64×64 и 32×32.
- [ ] RU/EN item names, эффекты, уровень, ограничения, перезарядки и место установки совпадают с кодом.
- [ ] Чертежи из ZIP сопоставлены с итоговой графикой (приведи ссылку на mapping и поясни адаптацию).

## E. Автоматические проверки без запуска игры
- [ ] `clean build` успешно, Production JAR существует и не содержит дублей, crash-критичных отсутствующих ресурсов и невалидных JSON.
- [ ] Тесты на tier codec, допустимые слоты, recipe ingredients, защитные приоритеты, cooldowns, двойные события, stack caps, loot count, эмуляцию старых сохранений.
- [ ] Пройти resource assertions и JAR inventory: 5 новых item textures + models + recipes, строки RU/EN, item registration, blank base component.
- [ ] Если есть падающие тесты из параллельных патчей (кубы брони или HP Горыныча), провести сравнение с базой и пометить **смежные**, не менять чужие цифры для прохождения.
- [ ] **Minecraft/сервер/GameTest/PolyMC не запускать**; в отчёте отдельно указать `0 запусков` и что настоящая игровая приёмка не проводилась.

## F. Финальный ответ Codex

Обязательные файлы `REPORT.md`, `FILES.md`, `BUILD_CHECKS.md`, с краткой матрицей фактических ID и рецептов и расшифровкой: сделано / не сделано / блокер. Перечислить изменённые общие файлы, все потенциальные конфликты и весь ручной игровой checklist.

Итоговые статусы: `COMPLETE`, `COMPLETE_WITH_LIMITATIONS`, `BLOCKED`. Если нет игрового запуска — явно оставь limit независимо от build PASS. Commit/push только по прямому указанию пользователя.
