# SLAVIC MYTHS — КРАФТОВЫЕ РУНЫ III–IV
**ТЗ для Codex / отдельный патч / 14 октября 2026**

## Главная задача
Завершить непрерывную **крафтовую** прогрессию рунических изделий I→II→III→IV, не превращая уникальные трофейные руны в стандартные рецепты. Реализовать недостающие игровые механики, рецепты, четвёртую основу и соответствующие визуальные ресурсы. Архив содержит и текстовую спецификацию, и реальные PNG-чертежи/референсы.

## Важное отличие от прежнего черновика
**Велесова клятва IV уже указана как введённая отдельным предыдущим патчем. Не регистрировать её повторно, не выдавать ей новый ID и не добавлять для неё обычный рецепт автоматически.** Новых крафтовых рун IV — четыре: `unbreakable_iv`, `perun_rage_iv`, `forest_spirit_iv`, `mastery_iv`. Новых уникальных наград с боссов не делаем.

## Источник истины и состояние дерева
1. Текущее состояние **локального рабочего дерева**, включая НЕзакоммиченные изменения из ветки `runs` (если она доступна), имеет приоритет над GitHub и всей старой документацией. Сначала проверить `git status`, текущий commit, файлы рун, рабочие деревья/ветки и пересечения с другими патчами. Не выполнять `reset --hard`, `checkout` поверх незакоммиченных изменений, массовых cherry-pick и очисток.
2. Ранее Codex сообщил: **37 исходных rune ID сохранены**, добавлены четыре III и Велесова клятва IV, clean build PASS, но локальные изменения **не были commit/push**. Это **не гарантия**: проверь актуальный код. Четыре III не создавать повторно, если они уже существуют.
3. Ранее в GitHub `main` в `Runes.IDS` были 37 исходных ID, `RuneBase` поддерживал tier=1–3, `RuneFoundation` регистрировал blank_rune_1..3. Уже созданные локально руны III и IV могут отсутствовать в удалённом `main` — это не основание их перезаписывать.
4. Сохранить все существующие namespace/registry IDs и компоненты предметов, наград, усилений. Старые сейвы и установленные руны мигрировать только безопасно, без потери содержимого.

## Порядок выполнения
- **A / Инвентаризация**: определить реальные III ID, их рецепты и эффекты, проверить базу IV; подготовить короткую матрицу «уже есть / исправить / создать».
- **B / III**: убедиться, что четыре руны III действительно крафтятся через руническую наковальню, корректно работают, присутствуют в JEI и реализованы в коде, не дублировать их. Если чего-то нет — реализовать по `01_IMPLEMENTATION.md`.
- **C / IV**: добавить 1 основу IV и **4 независимые крафтовые** руны IV из ТЗ: регистрацию, эффект, ограничения, рецепты, крафт, tooltips, ресурсы.
- **D / Сквозная прогрессия и баланс**: ограничения накопления, анти-эксплойты, взаимодействия с ранними рунами и особыми трофеями.
- **E / Визуал**: использовать референсы PNG из `02_blueprints` по `02_VISUAL.md`, сделать производственные прозрачные спрайты и item-модели, не подменять изображения-референсы готовыми артефактами без доработки.
- **F / Проверки**: тесты, clean build, packed JAR/JSON/resource inspection, регрессии на сохранениях и повторяемость формул; без игрового запуска.
- **G / Отчёт**: `docs/implementation/runes-craft-iii-iv/REPORT.md`, `FILES.md`, таблицы рецепт/ID/источник/возможные ограничения.

## Запреты
- Не трогать посторонние механики оружия/брони, моделей, анимаций, боссов, классов, достижений и мирогенерации.
- Не перерисовывать текущие существующие иконки III, если они уже устроены хорошо; приложенные концепты III нужны для сверки и при необходимости доводки.
- Не вводить глобальное правило «только одна руна IV у игрока» без отдельного обоснования и согласования: это может выключить ранее заработанные трофейные руны.
- Не коммитить/пушить без отдельного разрешения. Не запускать Minecraft/сервер/GameTest/PolyMC без разрешения.
- Нельзя объявлять COMPLETE на основании только `build`: реальная игра остаётся непроверенной и должна быть отмечена отдельным ограничением.
