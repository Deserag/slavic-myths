# Пекельный посад 2.3 — подключение «Грядок и житницы» (2.2.8)

Ветка `feat/2.3-pekelny-posad`; Minecraft 1.21.1 / NeoForge / Java 21.
Основной источник: `docs/concepts/nether-settlement-2.2/gryadki-zhitnitsa-2.2.8/MODEL_R1.json`. Готовый NBT уже существовал и **не модифицирован**.

## Runtime

- `PosadGranary.java` декодирует `src/main/resources/data/slavicmyths/structure/posad/granary_2_2_8.nbt`: 25×11×28, DataVersion 3955, **1349** реальных блоков, **43** состояния.
- Участок в городе `X=76..100; Z=12..39` содержит жилую житницу, инструментальный сарай, грядки адского нароста, багровые/искажённые нилиевые грядки и двор. Полная неизменная модель поштучно интегрируется в native `PosadPiece` при schema >= **7**.
- **5 сундуков**: west_grain, east_grain, west_supplies, east_supplies, shed_tools. Используются существующие `slavicmyths:chests/posad_granary_*.json`, исходные веса и содержимое не изменялись. Lazy loot выставляется только при первом размещении; повторная обработка открытого сундука не должна добавлять награды.
- `PosadGeometry.SCHEMA_VERSION=7`. Сохранённые структуры со схемами 0–6 не получают эту новую модель задним числом. Все остальные участки посада и внешние размеры **113×113** сохранены.
- Существующие команды для отдельной постройки уже поддерживали ID `granary_2_2_8`; команда `/slavicmyths dev posad templates` теперь показывает и этот участок, а `info` выводит 7 построек.

## Проверка

1. `python3 tools/posad-tests/verify_granary_nbt.py`: сравнение **всех 1349** позиций и blockstates с R1, строгих пяти NBT chest-маркеров, 43 palette states и пяти loot table JSON с первоначальными утверждёнными версиями.
2. `granarySchemaSevenAndFiveLootChests`: новая/старая схема, 5 сундуков и координаты модели для поворотов 0–3.
3. `physicalChunkPlacement`: физически расположенные блоки и пять loot chest block entities во всех четырех поворотах.
4. `granaryFiveChestsDoNotRearmAfterLoot`: полный цикл открытия/опустошения всех пяти сундуков и повторного вызова `postProcess`; дублей быть не должно.
5. CI `posad-geometry-java21.yml` и `posad-physical-java21.yml` теперь запускаются при изменении модели, NBT, исходников и верификаторов. **Результат конкретного GameTest подтверждается в GitHub Actions, а не самим наличием теста.**

## Тестирование игроком

Только в новом свободном QA-мире в Незере, не на действующем сервере. Для отдельного здания (загруженные чанки, свободная площадка, OP2):

```mcfunction
/slavicmyths dev posad building granary_2_2_8 ~ ~ ~
```

Для нового целого посада (подходящий берег и объём, все необходимые проверки игрового планировщика):

```mcfunction
/slavicmyths dev generate nether_posad
```

Эти две команды используются на **разных** тестовых площадках. `/place template` без preflight не использовать на ценных мирах.

## Остаточные ограничения

Естественный `StructureSet` для посада по-прежнему выключен: нужны реальная проверка пяти сидов Незера, ограничения chunk-gen/TPS, проверка непрерывного сохранения после перезапуска, мультиплеер, защита от повторной выдачи наград и визуальное подтверждение проходов/дверей/кровли. Этот документ не утверждает успешность не выполненных пунктов.
