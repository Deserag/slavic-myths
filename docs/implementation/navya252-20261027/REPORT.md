## Как проверить в Minecraft — только после отдельного разрешения

Сейчас проверка этого результата выполняется открытием отчёта/листа/схем:
нового игрового кандидата нет. Не использовать installed SHA как доказательство
сборки текущего HEAD. После устранения build blocker — отдельно записать точный
новый JAR/path/version/SHA и source+patch, затем разрешать игровые проверки.

1. Подготовить отдельный Survival-мир и копию старого сохранения; shaders выключены,
   тот же resource pack/modpack, записать seed/координаты/JAR SHA. Без OP построить
   портал, войти в обычный Nether: ожидаются сохранённые ванильные биомы/лава/порталы.
2. Без команд найти естественную Навью рощу, зафиксировать маршрут и координаты.
   Спуститься из верхнего леса через корневые уступы в костяные полости и вернуться:
   ожидается естественный проходимый путь, различие с Warped Forest, читаемость без shaders.
   Если роща/проход не найдены — записать FAIL/NOT_RUN, не заменять `/locate` успехом.
3. Без Creative добыть восемь материалов подходящими инструментами, поставить стены
   5×5 и участки пола; осмотреть front/top/side, колонну по осям и шип вверх/вниз.
   Ожидается читаемая единая палитра, корректные дроп/коллизия, нет яркой сетки тайлинга.
   Негативный случай: неверный инструмент/неподходящая опора — проверить ожидаемое
   поведение по реальному коду, отсутствие дюпа и невидимых коллизий.
