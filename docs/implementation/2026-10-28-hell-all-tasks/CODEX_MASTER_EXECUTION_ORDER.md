## 5. ОБЯЗАТЕЛЬНЫЕ checkpoint commits/push — даже при нехватке токенов

**Это прямое разрешение владельца на COMMIT+PUSH частичного результата.** Важнее любой предыдущей привычки заканчивать работу без публикации, но **не разрешает вредить чужим изменениям**.

**Не ждать одного финального push.** После каждого логического подраздела A1(Posten), A2(heads), B1(spiders), B2(palette), C(old biome regressions), D1(worldgen), D2(mobs+runes), D3(boss), E(ores), F(level tags), G1(armor), G2(weapons):
1. Сверить рабочий diff/добавленные/untracked собственные файлы: `git status --short`, `git diff --check`, `git diff --stat`, `git ls-files --others --exclude-standard`. **Не коммитить чужие** или временные `build/`, `.gradle/`, local saves, секреты. Не делать `git add -A` в чужой грязной worktree без ревизии. Stage explicit собственных исходников/ресурсов/отчётов.
2. Запустить целевые офлайн-тесты и `gradlew.bat --no-daemon clean build --console=plain` если уместно. Если упало, сначала восстановить компиляцию или изолировать незавершённый code behind safe disable/feature gate. Если это невозможно при ограничении контекста, **всё равно сохранить свои изменения** как честно названный `WIP: <scope> — BUILD_FAIL, NOT FOR TEST`, включая `STATUS.md` с точной командой и логом, **но НЕ установить/не выдать этот JAR**. Таким образом ни один полезный рабочий diff не теряется, владелец видит checkpoint.
3. `git add -- <точные файлы>`, `git commit -m "wip(hell): <scope> ..."` или `fix(hell):...`, `git push origin hell` **обычный, без force**. Проверить `git rev-parse HEAD`, `git rev-parse origin/hell` после fetch, показать успешный push; если работа в detached tree, корректно сначала интегрировать свои commits в локальную ветку `hell` без чужих rebase/reset.
4. При push non-fast-forward: `git fetch origin hell`, интегрировать чужие опубликованные коммиты неразрушительно (обычный merge при здоровом чистом single writer/или воспроизводимый cherry-pick своих commits), разрешить конфликты, повторно проверять, **обычный push**. Если writer конкурентный и conflict нельзя решить — сохранить собственные коммиты/патчи и указать `PUSH_BLOCKED`/последний reachable local SHA, НЕ лгать об отправке.
5. Обновить [#337](https://github.com/Deserag/slavic-myths/issues/337) или `docs/implementation/2026-10-28-hell-all-tasks/STATUS.md`: `DONE | WIP | BLOCKED | NOT_RUN`, ссылки на `commit`, build и оставшиеся пункты. **Не закрывать** Issues; нет owner-accepted до реального ответа владельца.

### АВАРИЙНЫЙ ПРОТОКОЛ КОНТЕКСТА/ТОКЕНОВ — очень важно
- **При остатке контекста ~25%/риске принудительного прерывания — немедленно переключись на SAFE CHECKPOINT, не начинай новую фичу.** Создай или дополни `STATUS.md` и `DECISIONS.md`: актуальный HEAD, что изменено и почему, файлы/пути, что тестировалось/не проверено, точная команда продолжения, исходные blockers.
