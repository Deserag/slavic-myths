## Исправлено

**2.1.2 / #339.** Структурный проход уже умел удалять грибные блоки, но декорация
соседнего чанка могла записать крону позднее. `BridgeClearanceFeature` выполняется в
`top_layer_modification` после растительности, читает существующие ссылки структур
в локальном регионе 3×3 и очищает только два блока высоты над пятью полосами
фактически существующего авторского полотна. Область ограничена дальностью грибной
декорации ±8 от чанка. Никаких загрузок FULL-чанков, новых зданий, лута или опроса тиков.
Готовые FULL-чанки в WorldGenRegion пропускаются: соседняя новая генерация не должна
удалять построенное игроком на старом мосту. Жидкости, block entities, обсидиан и
прочая твёрдая застройка не очищаются.

**2.1.3 / #341.** Горизонтальные сдвиги на том же Y повторяли ту же лавовую площадку.
Поиск расширен на конечный набор высот/центров в исходном чанке, с полным preflight
до записи. Когда безопасного места вообще нет, старт сохраняется как `INVALID_START`,
а не как пустая найденная постройка. Отдельно обнаружен и исправлен устаревший
ванильный `StructureCheck`: окончательные starts публикуются в кэш через серверный
поток, поскольку его внутренние карты не являются concurrent. Для доступа добавлена
одна адресная строка access transformer. Нет перемещения в другие чанки, выжигания
лавы, насильственной установки или ретрогена старых стоянок.

GameTest больше не приравнивает noise proposal к размещению: явно считает поздний
отказ, требует недействительный start, его сериализацию `id=INVALID`, обновление
кэша поиска и затем находит другую **физическую** стоянку с сундуком, костром,
верстаком, цепью, фонарём, опорами и доступом. Отвергнутый чанк не считается PASS
естественной постройки. Зафиксированная лавовая площадка `[24,46]` seed `20261026`
должна оставаться нетронутой; реальная безопасная стоянка найдена в другом native start.

Пять seed теперь автоматически перепроверяются в GitHub Actions при изменении
соответствующего production-кода/ресурсов/тестов, а не только самого workflow.

## Как проверить в Minecraft позднее

1. Использовать указанную в installation.json сборку; сначала новый тестовый мир,
   затем **копию** старого. Исходные сохранения не удалять и не перезаписывать.
2. В survival без OP выйти в новые чанки Незера. На сохранившихся сегментах мостов
   проверить пять свободных блоков дороги, две клетки высоты, внешние парапеты;
   намеренные разрушенные пролёты остаются разрывами. Сундуков и наград на мосту нет.
3. Найти стоянку обычным исследованием: один открывающийся сундук, еда/припасы,
   верстак, наружный костёр на камне, реально подвешенный фонарь и безопасный обход.
   Не должно быть лавы вместо функциональных блоков или висящих дорожек.
4. Негативно: проверить строения рядом с лавой/низким потолком, чужие контейнеры
   и старые уже исследованные чанки. Постройка не должна разрушать эти объекты.
5. Забрать содержимое сундука, сохранить/перезайти, вернуться: второй выдачи нет.
   Повторить с двумя игроками на копии мира. Это пока NOT_RUN исполнителем.
6. Только при необходимости OP-диагностики: `/locate structure slavicmyths:broken_nether_bridge`
   и `/locate structure slavicmyths:wayfarer_camp`. Команды не являются survival-доказательством.
   Для seed20261024 мост: origin `(210,40,-808)`, стоянка: chunk `[29,7]`, Y47;
   для seed20261026 отвергнутый `[24,46]` не должен быть реальной стоянкой,
   проверенная физическая стоянка — chunk `[-78,51]`, Y47.

## Риски и откат

Это тестовый кандидат, а не принятый релиз. Старые исследованные чанки не исправляются
ретрогеном. Зафиксированные ограничения Кумирни, графики, аудио, survival/MP сохраняются.
Для отката при закрытой игре перенести новый JAR из `mods` в резервную папку и
вернуть **один** прежний JAR из backup, указанного в installation.json. Не оставлять
обе версии одновременно и не менять мировые данные. Код при необходимости откатывать
новым revert-коммитом в `hell`, без reset/force и без main.
