# Slavic Myths — ТЗ на рефакторинг и расширение рун

**Статус:** согласованное направление реализации, без внесения изменений в текущем чате.  
**Рабочее имя:** «Патч рун»; номер версии определять только по актуальной договорённости автора, **не** из README.  
**Подготовлено:** 13.10.2026. Запуск Codex — в отдельном чате после завершения параллельных работ с оружием, бронёй и другими подсистемами.  
**Источник требований:** этот ZIP + актуальные авторские решения. Старые `docs/specs/*`, дорожные карты и README — только исторический контекст, не источник новых задач.

## Цель

Закрыть ошибки и несогласованность действующей системы рун, сбалансировать существующие эффекты и закончить прогрессию четырьмя крафтовыми рунами III уровня и одной редкой руной IV уровня. **Не** создавать новую независимую систему сокетов, компонент предметов или отдельный интерфейс вместо действующей рунической наковальни.

## Как работать в Codex

1. Один новый чат Codex именно под **руны**. Ранее согласованные *постоянные инструкции нового чата* отправляются **один раз отдельно**; внутри ZIP повторяются только важные для данного патча границы.
2. В рабочей директории проверить `git status`, HEAD и текущие изменения. Не сбрасывать/не переписывать незакоммиченные результаты чужих задач. Перед записью в общие файлы убедиться, что три параллельных патча завершены и актуальная ветка уже содержит их результат; при реальном конфликте **остановить конфликтный блок и описать его**, не делать автоматический merge чужих изменений.
3. Прочитать **только** актуальные классы/рецепты/локализацию, реально задействованные рунами: перечень в `01_IMPLEMENTATION.md`. Не открывать старые гигантские спецификации, не выполнять повторный аудит всего мода, не переписывать историю версий.
4. Реализовать в порядке: **A — стабильность и текущие руны**, **B — четыре III и одна IV**, **C — рецепты, минимальные новые иконки, описание, проверки**. Локальные проверки после подсистем, одна итоговая чистая Gradle-сборка после завершения исправлений. Не запускать Minecraft/PolyMC и не устанавливать JAR в профиль без отдельного разрешения автора.
5. Если спорная реализация противоречит фактическому современному коду, сохранять рабочий сюжетный/боевой контракт. Нельзя молча «исправить» конфликт изменением механик соседнего патча. Отчёт должен содержать эту развилку и выбранное минимальное решение.
6. Не присваивать новому патчу чужую маркировку «патч оружия», не оформлять релиз/тег/публикацию без указания автора. Git-операции — точечные, не включать в коммит посторонние файлы.

## Границы

**Разрешены** только изменения рун, их механик, установки, рецептов, локализации, минимальных иконок новых пяти предметов, узкой интеграции получения руны IV и регрессионных проверок. **Не менять** характеристики оружия, модели/анимации/текстуры существующих 37 рун и брони, логику боссов, сюжетные стадии и награды, кроме явно указанной проверки иммунитета Руны смерти и отдельного источника новой руны IV.

**Основной критерий:** старый мир, старые рунные предметы, сокеты и ID без миграционных потерь; новые 5 рун доступны заявленным способом; все эффекты работают на сервере; нет пропавших текстур и регрессий в наградах.

**Документы:** `01_IMPLEMENTATION.md` — исчерпывающее поведение и баланс; `02_VISUAL.md` — минимальные ассеты; `03_ASSETS.md` — конкретные изменения/ресурсы/границы; `04_ACCEPTANCE.md` — проверки и формат отчёта.
