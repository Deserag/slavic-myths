# 04 — Критерии приёмки и окончательный отчёт

Работа считается готовой **только** при выполнении функциональных и технических критериев. Статический unit/offline PASS не равен подтверждённому запуску Minecraft.

## A. Совместимость и сохранения

- [ ] Все исходные **37 ID** остаются зарегистрированы с теми же именами, ключами и признаками legacy; новые **5 ID** добавлены без конфликтов. Не произошло массовой замены компонентов `ItemState`.
- [ ] Сохранения с рунными предметами 1/2/3 сокета, несколькими копиями современной I–II, старыми rare/boss-рунами и `LEGACY_RUNE_SPECIALS` читаются без потери. Снятие/установка рун не удаляет зачарования, durability, custom name, компоненты/квестовые метки.
- [ ] Старую неработающую руну с неподходящей брони можно безопасно извлечь; новый такой экземпляр установить невозможно. Списание материалов/XP только после всех проверок.
- [ ] Пересчёт после установки/извлечения/смены оружия или доспеха, relog, respawn, смены измерения: нет двойных или оставшихся модификаторов.
- [ ] Рунная наковальня не показывает выход или кнопку подтверждения с возможностью server-side обхода несовместимости.

## B. Исправления

- [ ] **Руна смерти** с обычным допустимым врагом ниже 15% работает по прежней цене и КД; не срабатывает на защищённых многозадачных/многофазных боссах и ни разу не перескакивает фазу/очистку.
- [ ] У **морозной защиты** не действует замедление/слабость именно от холода/руны Мороза; обычные эффекты зелий/команд/прочих мобов продолжают действовать. При смене брони чужой эффект не стирается.
- [ ] **Подавление** уменьшает два последовательных прямых удара цели, нанесённых в пределах 4 с, на 15%, не более одного изменения каждого; после 4 с заканчивается; реапплай до истечения 25 с не проходит. Прерывание специального действия Картауса сохранено.
- [ ] **Угрожающая аура:** 1 копия не работает; две активные копии дают существующий эффект; агрессия после провокации корректна. **Сердце Земли** и **Владыка Земли IV** работают без регрессий.

## C. Численные тесты старых рун

- [ ] `forest` вне леса = 0 дополнительного бонуса; в лесу +1.0 HP, лук +8%, щит/посох в правильных окнах.
- [ ] `midday` ночью = 0; днём +1.0 HP и ×1.12 только для критической стрелы; под крышей состояние соответствует действующей `RuneEffects.day`.
- [ ] `shadow` в светлом месте = 0; в темноте правильные кинжал/меч/лук, КД меча 10 с.
- [ ] `protection` для удара/щита/посоха даёт разные заявленные окна 2/3/2 с.
- [ ] `life` на щите с HP 49% работает, с HP 50% и выше не работает, на посохе +2 HP при допустимой активации, при валидном убийстве +3 HP не чаще 1 раза в 40 с.
- [ ] I–II: Сокрушение не теряет −10% скорости; Кровь 25% шанса до proc cap, не ломает native bleed; `mining_1/2` не складываются друг с другом сверх действующего правила; штрафы/лимиты и затухание копий сохранены.

## D. Новые III (каждая 1 предмет + 1 рецепт)

- [ ] **Ответный удар:** при подтверждённом блоке получен токен 4 с; одна валидная melee-атака даёт ровно +2 HP; второй удар — 0; блок на cooldown 20 с повторного токена не выдаёт; projectile не потребляет токен.
- [ ] **Охотник:** с 11.9 блока бонуса нет, с 12+ +12% при попадании валидного снаряда; в течение 7 с второй выстрел бонуса не имеет; телепортация/изменение позиции после выстрела не увеличивает дальность.
- [ ] **Последний рубеж:** HP 34% и combat damage >0: −12% один раз; HP 36%/падение/самоповреждение: 0; второй удар в пределах 45 с не усилен.
- [ ] **Глубины:** руда под землёй ниже заданного порога +20%; руда под открытым небом/камень/неверный инструмент/не та высота: 0; суммарно с `mining_2` +30%, не +40%; обычные зачарования не обрезаны.
- [ ] Все четыре recipe JSON загружаются, используют III-заготовку и три входных группы; JEI показывает рецепты, сырьё списывается 1 раз.

## E. Новая IV и история

- [ ] У Яги обмен Велесовой клятвы отображается после реального **сюжетного** зачёта `GorynychRewards.claim`, но не до него / не после standalone или creative боя. Требует точно 4 чешуи + 8 перунитовой пыли + 2 усиленные души + 1 древний знак. Не заменяет существующие обмены и награды.
- [ ] Первое melee-попадание по одному врагу +0%, второе +2%, ..., шестое и последующие +10%; через 10 с без попадания снова +0%; смена цели, оружия, рунного состояния, logout/respawn сбрасывают счётчик.
- [ ] По дружественной цели, пустому замаху, кровотечению, отражению, projectile счётчик не растёт.
- [ ] Нельзя установить вторую IV на один предмет. Две исторически установленные IV **не удаляются**; приоритет одной для фактической атаки понятен и не производит двух IV-бонусов.
- [ ] Существующая руна IV Полоза продолжает создавать свой удар и не утратила награду; 3 руны Горыныча и их шансы/получение не изменены.

## F. Редкие и наградные — регрессия

- [ ] Полёт: при снятии сапог/выходе возвращает правильный vanilla flight; floating weapon не атакует недопустимые цели; rare protection щиты не бессмертны; sacrifice не убивает обходом цены; berserker уязвимость сохраняется.
- [ ] Погоня, Отбрасывающий удар, Рассеивание, Боевая линия — действующие триггеры и CD сохранены.
- [ ] Вложенные боевые события не умножают один и тот же бонус дважды; NBT-cooldowns не используют конфликтующие ключи.
- [ ] Каждая новая руна видна в creative, anvil, tooltip и RU/EN; 5 собственных моделей и 5 текстур открываются без missing texture; существующие руны визуально не изменены.

## G. Инструментальные проверки и репортинг

**Оптимальная последовательность:**

1. После A: быстрые targeted/offline тесты чистых правил, локальная компиляция затронутых Java и синтаксический контроль JSON/registry; фиксировать ошибки, не делать полную сборку после каждого класса.
2. После B/C: проверка уникальности ID, связи регистров / ресурсов, соответствия локализаций, JSON-рецептов и тега иммунитета.
3. **Одна итоговая Gradle-сборка** по фактическому проектному wrapper, и только необходимые повторные после реального исправления ошибки сборки. Если тестового окружения нет — не писать «проверено в Minecraft».
4. Не запускать игру/PolyMC, не изменять профиль пользователя и не устанавливать собранный JAR без отдельного разрешения.
5. Сверить список изменённых файлов. **Не включать** лишние изменения оружия/брони в коммит. Пуш/релиз выполнять лишь если отдельно согласованы в текущем Codex-чате.

**Формат последнего сообщения Codex (коротко, конкретно):**

```
Статус: COMPLETE / COMPLETE_WITH_LIMITATIONS / BLOCKED
Актуальный HEAD при старте: ...
Файлы: ... (сводка по подсистемам)
Существующие ID: 37/37 сохранено; новые: 5/5
Исправления: совместимость / казнь / мороз / подавление / refresh
III: 4/4; рецепты: 4/4; IV: 1/1; RU/EN: PASS/FAIL
Проверки: имя теста → результат; Gradle: PASS/FAIL/NOT_RUN
Minecraft/PolyMC: NOT_RUN без разрешения
Конфликты с параллельными задачами: ...
Отклонения от ТЗ: ... (если нет — «нет»)
Git: локальные изменения / коммиты / отсутствие push
Следующее действие для автора: ...
```

Нельзя заменять тестовые факты фразой «всё должно работать». При FAIL указать воспроизводимую причину и файл, не скрывать проблемный этап. При блокирующем конфликте с чужим патчем не пытаться чинить чужую механику в этом задании.
