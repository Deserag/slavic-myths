# Timing scopes

Installed NeoForge21.1.255 MinecraftServer.tickServer increments tickCount, fires Pre, runs tickChildren/status/autosave, stores Util.getNanos()-tickStart into tickTimesNanos[tickCount%100], then fires Post. The world probe records this native ring sample as native_mspt plus separate event Pre/Post elapsed as ms. Neither native vanilla tally nor our event bracket includes every later Post listener; profiling/telemetry in Post has separately disclosed overhead. TPS uses all tick intervals, capped20. Server CPU/thread time comes from ThreadMXBean over long intervals; Windows counter quantization15.625ms is not per-tick precision. JFR CPU stack counts are sampled, not exact milliseconds.

Frame ms = adjacent RenderFrame.Post intervals. render_ms = Pre/Post bracket; render_cpu_ms = current-thread CPU delta across that bracket. Frame intervals can include FPS limiter/platform scheduling; none equals GPU time. Active/visible/iconified/pause/screen/size/camera/cap are recorded, so focus mistakes are not interpreted as code speedups. Known screenshot/cap boundaries trimmed uniformly for cube; raw stalls retained. World samples skip first30s of each scene for setup/settling, while full transition data remain.

JFR ThreadCPULoad user+system is published as raw fractional telemetry without assuming normalization; CPU cost conclusions primarily use ThreadMXBean aggregate means and recorded JVM/machine CPULoad context. GPU sampler, if supported, reports per-process3D-engine scheduling utilization, not device-wide total or GPU frame latency. Its own query duration and process working/private bytes are recorded.

World recordings explicitly enable native minecraft.ChunkGeneration and PacketSent/PacketReceived. Integrated memory channels may bypass packet codec events; absence of events is NOT_MEASURED, never0 network cost. No NetworkSummary aggregation is enabled. Raw JFR stays local; summaries omit socket addresses.

Observer overhead is not subtracted: JFR, per-frame CSV, screenshots at transitions, periodic entity enumeration and the native-input workload all consume CPU/memory. Common world/control observers are identical, but an uninstrumented overhead baseline is NOT_RUN and observers may scale with entity counts. AI attribution uses actual entity/target counts and sampled server stacks; it is not exact per-goal CPU accounting. A single mod/control pair on one seed cannot separate every world-generation, population, route or combat-outcome difference. Report observed scene/path/entity counts beside comparisons rather than treating all differences as isolated mod overhead.

World summaries additionally publish full_phase_including_setup for each scene, preserving first30s frame/tick distributions, maxima, path and chunk-event deltas. This was added during the first mod run after observing that most travel generation occurred early and the walker later stalled: the initial30s must not disappear from exploration evidence. The predeclared age>600 steady-state window remains unchanged. Full-phase numbers include known screenshot/locate/teleport setup and must be labelled accordingly; neither window silently replaces the other or establishes the cause of a hitch.
