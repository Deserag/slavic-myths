## Подтверждённые исходные материалы и художественное решение

- **Живые игровые изображения:** #95; те же [4 оригинальных скриншота в папке `скриншоты для показа` на `main`](https://github.com/Deserag/slavic-myths/tree/main/%D1%81%D0%BA%D1%80%D0%B8%D0%BD%D1%88%D0%BE%D1%82%D1%8B%20%D0%B4%D0%BB%D1%8F%20%D0%BF%D0%BE%D0%BA%D0%B0%D0%B7%D0%B0). Скрин №1 — природные материалы/металлы/часть наконечников; №2 — продолжение наконечников и трофеи; №3 — трофеи **вне scope**; №4 — инструменты **вне scope**.
- **Фактический перечень ID/вкладок:** `src/main/resources/assets/slavicmyths/creative_catalog.tsv` плюс регистрация в Java на актуальном `main`; не принимать скриншот или старый каталог за доказательство реальной привязки ID без проверки модели.
- **Утверждённое направление референса (обсуждение 20.10.2026):** ванильный crisp Minecraft pixel art; объёмные металлы и чёткий 1× силуэт. Светлое благородное серебро с *тонкими* бело-голубыми прожилками и более изящной геометрией, не копия железа. Перунит — насыщенный сине-стальной с локальными бирюзовыми жилами. Очищенное железо — серо-стальное с отчётливыми голубыми/циановыми прожилками, более «техническое» и тяжёлое. Очищенная медь — медно-оранжевая с такими прожилками. Закалённое железо — плотное тёмно-стальное, не тот же цвет/узор, что очищенное. Железная заготовка — грубая недоделанная металлическая форма. Янтарный блок — медово-золотой, с визуальной глубиной, а не абстрактный оранжевый куб.
- Для **природных ресурсов** реалистичные материалы (береста/жир/шкура/кость), а не магические прожилки; для **наконечников** пара обычный/лёгкий различается по геометрии. Не переносить эффекты одного семейства на все соседние PNG. **Никаких shader/glint/particle/gameplay effect**; прожилки — только пиксели в текстуре.

## Обязательный протокол для Codex

1. Перед каждым пакетом прочитать `AGENTS.md`, свежие `docs/PROJECT_STATUS.md`, `docs/ROADMAP.md`, `docs/ARCHITECTURE.md`, текущий HEAD/`git status`. Убедиться, что другая задача не пишет в эти файлы. Без автоматических коммитов, force/reset/отката и работы с чужими worktree. Сохранить совместимость старых миров.
2. Для каждого изменяемого **реального registry ID** определить и записать `ID → item/block model JSON → texture(s) → generator/source`, старый SHA и точный дефект. Item PNG не обязателен для `BlockItem` (например, янтарного блока и руд), если модель наследует block model.
3. **Сначала выделить правильный дефект**: цвет, контраст, пиксельная плотность, силуэт или UV/JSON; исправлять его в нужном реальном asset. Не перегенерировать соседние предметы или целые каталоги. Защищать существующие approved assets от исторических генераторов.
4. **До/после:** те же реальные PNG/model JSON, 1× слот и 3× nearest; для block materials — нужные грани block/item/tiled. Отдельно показать взаимную различимость материалов (особенно серебро/очищенное железо и пары обычный/лёгкий).
5. Java21 clean build, asset/path/UV/model/blockstate checks и проверка production JAR; матрица `REQUIREMENT | EVIDENCE | PASS/FAIL/BLOCKED/NOT_RUN`; один сводный отчёт на законченную партию.
6. **Нельзя менять:** существующие registry ID, loot/recipes/properties, баланс, названия и локализации, creative ordering, звуки, AI, hitboxes, миры, game saves, другие модели. Ни Minecraft, ни PolyMC, ни GameTest, ни сервер самостоятельно не запускать; offline preview нельзя называть игровым скриншотом. Статус игровой приёмки `OWNER_PENDING`.
7. Следовать owner-quality-gate из `AGENTS.md`: **Codex не ставит `owner-accepted`, не закрывает issue и не объявляет DONE без явной ручной приёмки владельцем**. Issue остаётся OPEN при частичных/непроверенных результатах.
