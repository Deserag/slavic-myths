## Основание и блокирующий факт
Владелец ранее указал персонажа, у которого не отображаются глаза. **Имя / registry ID из текущего сообщения не определён**: нельзя произвольно выбрать Полевика, Ским-зверя или другого и выдавать исправление чужого персонажа за этот дефект.

## Чертёж проверки глаз
**[Отдельная панель #80: лицо / профиль / свет / темнота](https://github.com/Deserag/slavic-myths/blob/main/docs/design/COMMAND_LOCALE_EYES_BLUEPRINTS.svg)**. Правильный результат — глаза видны на переднем и боковом видах, UV/texture/renderer слой реально рисуются и не пропадают в idle/walk/hurt. Проверка цвета глаз не должна ломать существующий образ.

## Порядок
1. Найти конкретный ID по актуальным скриншотам/соответствующей переписке владельца и реальным `ClientSetup` renderer, model, PNG; при отсутствии достаточного доказательства запросить у владельца **ровно имя либо скрин**, status `IDENTIFICATION_BLOCKED` — не трогать другие модели в надежде угадать.
2. Сверить `eye part`, texture atlas UV, `RenderType`, emissive overlay, положение глаз при повороте головы; выяснить точную причину (нет геометрии / пустая область UV / неверная прозрачность / модель скрывает part).
3. Поменять **только** конкретные model/texture/render files. Не приделывать случайные белые квадраты поверх морды и не менять пропорции тела «заодно».
4. Снять реальные четыре состояния before/after при одинаковом масштабе и источнике света. Подтвердить оба глаза и отсутствие дефектов в анимациях.

## Не сломать
Все остальные entities, память UV атласа, визуальную идентичность найденного персонажа, анимации, custom entity layers/eyes glowing только если уже требуются. Если личность ещё не подтверждена — работа **не выполнена**, а только корректно заблокирована.

## Правило приёмки и безопасности

- **Сначала подтвердить source HEAD и исходный вид**, затем сделать **минимальную необходимую правку**, затем сравнить с тем же ракурсом/масштабом/состоянием и проверить **регрессии соседних функций**. Наличие кода, успешно собранный JAR и концепт НЕ означают корректный вид/игровую работу.
- Не менять registry ID, NBT/world saves, баланс, модель другого персонажа, механизмы иных веток, если этого не требует дефект. Не делать массовой перерисовки или общего рефакторинга «заодно»; актуальный рабочий main не восстанавливать и не откатывать.
- Один исполнительный пакет в рамках issue; никаких сообщений владельцу каждые 5 минут. Итог одним сообщением: HEAD/commit, точный список изменённых файлов, **сравнение по обязательным видам/сценариям**, Java21 build + resource/JAR checks, ручная игровая проверка — `OWNER_PENDING` до решения владельца. После 2–3 законченных пакетов — короткий handoff в новый чат Codex, без повторного аудита.
