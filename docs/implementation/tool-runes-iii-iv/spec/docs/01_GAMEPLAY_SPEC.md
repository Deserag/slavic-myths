# Игровая спецификация: ровно 8 новых инструментальных рун

## Общие правила

**Новые внутренние rune ids:** `miner_iii`, `excavator_iii`, `farmer_iii`, `lumberjack_iii`, `miner_iv`, `excavator_iv`, `farmer_iv`, `lumberjack_iv`. Item IDs ожидаются `slavicmyths:rune_<id>`; не назначать ID уже существующего предмета другим назначениям.

Матрица совместимости:
| Руна | Куда ставится | Не ставится |
|---|---|---|
| miner | только PickaxeItem и фактически признанные текущим кодом кирки мода | лопата, топор, мотыга, оружие, броня |
| excavator | только ShovelItem/эквиваленты мода | иные предметы |
| farmer | только HoeItem/эквиваленты мода | иные предметы |
| lumberjack | только AxeItem/эквиваленты мода | иные предметы |

- **Режим:** действие массовое, только если `player.isShiftKeyDown()` в момент пользовательского обычного действия. Без Shift — ванильное действие. Не создавать всегда включённого «магического инструмента».
- Центральный блок (`origin`) должен быть обработан обычным успешным действием игрока (разрушение или `use`), а остальные N блоков — дополнительно после проверки, что исходная операция действительно состоялась и не была отменена. Не дублировать центральный блок.
- Тier IV заменяет III при определении эффекта, бонусы области **не складываются**. Установка III+IV на один предмет запрещается с понятной ошибкой; уже существующие неожиданные данные не стирать — IV имеет приоритет. В пределах семьи rune item не мультистакать. Не менять общие ограничения на 1–3 сокета и стоимость старых операций.
- Эффекты только на сервере. На клиенте — только визуал/tooltip. Состояние кратковременно, контекст операции привязан к игроку, измерению, исходному инструменту/стеку и цели; ни транзакционных дюпов, ни долговременной синхронизации области без необходимости.
- Уважать ограничения игры и иных модов: приключенческий режим, spectator, creative, game rules, protection/claims/permission hooks, spawn protection, block hardness (`-1`), harvest tier, текущие эффекты инструмента, блокировки в мультиплеере, `BlockEvent.BreakEvent` и фактическое успешное разрушение. Если нельзя корректно вызвать стандартные проверки для доп. блока, НЕ ломать его.
- Не включать воду/лаву, жидкости, block entities/контейнеры, сундуки, спавнеры и неопознанные специализированные блоки, не вызывать в массовой операции изменяющие игрока команды или рекурсивные вызовы. Операция останавливается или пропускает блок, когда инструмент сломался, игрок сменил инструмент или покинул мир.
- Дроп, опыт, сохранение зачарований, звуки, статистика и сторонние callbacks каждого реально обработанного блока — в рамках нормального vanilla/NeoForge пути, а НЕ `setBlock(AIR)` и единый статический дроп. Никаких удвоенных дропов и XP, и никаких блоков без учёта расхода прочности. Unbreaking роллится на отдельных блоках через корректный инструментальный API, Mending работает стандартно после получения XP. Если дефолтная ломка не поддерживает специфический модовый блок — пропустить безопасно.
- Каждая группа обрабатывается один раз (guard against re-entry) с верхним ограничением блоков и работы на серверном тике; не блокировать основной поток крупным BFS. Предпочтение — небольшие ограниченные очереди с проверками на каждом шаге, аккуратно увязанными с жизненным циклом начального действия.
- Информация в tooltips должна точно совпадать с реальной геометрией, лимитами, механикой видов дерева и правилом Shift.

## Кирка: Руна Шахтёра

III: зона **3×3 = 9** блоков **включая центральный**; при нацеливании на стену — та же плоскость, перпендикулярная стороне попадания. При ударе сверху/снизу — горизонтальная плоскость. Ориентацию определять по фактической стороне блока (`BlockHitResult`/валидный серверный контекст), а не рандомно по положению камеры. Если hit-side достоверно не восстановлен, применять безопасный 1×1, не угадывать и не ломать строения.

IV: **3×3×2 = до 18** блоков, второй слой ровно **за первым слоем, по направлению внутрь грани**, 3×3 на глубине двух блоков, не 18-блочный куб и не одна плоскость 9×2.

Отсеивать блоки, не относящиеся к категории, реально добываемой киркой по действующим `mineable/pickaxe`/item rules. Проверять соответствие уровня кирки и неподходящие hardness/tile types. Это массовая добыча подходящих блоков, а не универсальное стирание всего вокруг. Не получать drops там, где ванильная кирка их не даст. Если центр не подходит — массовый режим не срабатывает.

## Лопата: Руна Землекопа

III: **3×3 = до 9**, по той же логике плоскости; IV: **3×3×2 = до 18**, второй слой вглубь, а не соседнее произвольное смещение. Аналогичные гарантии по серверному событию, защите, прочности и дропу.

Дополнительные блоки только из реально подходящих для лопаты (`mineable/shovel` и фактические правила инструмента: грунт/песок/гравий/глина/снег и аналогичные). Дороги, костры, блоки с правой кнопкой / специфические состояния не включать в массовое уничтожение только потому, что лопата имеет иной `useOn`.

## Мотыга: Руна Земледельца

Активация **Shift + правая кнопка** по земле или зрелой культуре. Два взаимоисключающих режима зависят от центра:
1. Центр — подходящий для ванильной обработки/вспашки верхний блок: **III 3×3**, **IV 5×5**, только в горизонтальной плоскости вокруг цели; обрабатывать лишь блоки, которые допускают обычное tilling (включая свободное пространство над ними); без разрушения посевов, дорожек, декоративных блоков. Центр успешно вспахивается, остальные после проверок.
2. Центр — **полностью зрелая культура**, к которой мотыга применима: **III 3×3**, **IV 5×5**, только зрелые растения той же группы, не трогать незрелые, не ломать сами блоки грядок, снимать дроп обычным безопасным игровым путём; повторный сбор того же блока невозможен. По умолчанию **не пересаживать автоматически** и не создавать бесплатные семена. Для каждого реально собранного растения стоимость прочности 1 использование с обычным Unbreaking (отдельно от vanilla слома культуры); баланс явным текстом в подсказке.

Если у текущего API нет надёжного общего правила для нестандартной модовой культуры, поддерживать только подтверждённые vanilla/проверенные modded растения, остальные пропустить, без зависимости от спорного hard-code. При сборе никакого бонусного дропа, отсутствующего в оригинальном loot table.

## Топор: Руна Лесоруба — ключевое требование пользователя

**III:** после успешной рубки естественного дерева топором при Shift, срубить подходящие стволы **этого дерева**, а также **соседние естественные деревья ТАКОЙ ЖЕ ПОРОДЫ** с основаниями ствола в горизонтальном радиусе **4 блока** от основания исходного дерева. **IV:** радиус **7 блоков**. Ограничение работы **до 48 обработанных брёвен на операцию (III), до 96 (IV)**. Речь НЕ об обычном кубе 4×4×4 или 7×7×7: в радиусе ищутся ДРУГИЕ деревья, затем их естественные стволы рубятся целиком в пределах лимита.

Различать `oak`, `birch`, `spruce`, `jungle`, `acacia`, `dark_oak`, `mangrove`, `cherry` и добавленные породы по строгой нормализации family `*_log` / `*_wood` и соответствующих тегов; stripped logs и player-placed logs по умолчанию исключить из авто-поиска; не смешивать дуб и ель, не переходить от бревна к доскам/ступеням/заборам. **Листву руна не ломает** (её обычная деградация допустима). Плотные близкие кроны не делают деревья одной целью.

**Определение естественного дерева — консервативное, безопасное:** выделить вертикальный ствол(ы) одного семейства с основанием на допустимом природном грунте, проверить разумную геометрию и наличие соответствующей листвы/кроны; ближайшие отдельные корневые основания — кандидаты соседних деревьев. Не присоединять к стволу дощатые постройки, домовые стены, мосты и иные вложенные player-made конструкции; не перескакивать по примыкающим логам между сооружениями. Для составных деревьев (2×2 ствола) считать дерево единым. Сложные специальные деревья, корни/пропагулы/экзотические постройки — пропустить, если нельзя обеспечить защиту. При сомнении: **оставить дерево нетронутым, а обычный первичный блок пусть ломается ванильным образом**.

**Расстояние:** 4/7 блоков по XZ между **основаниями ближайшего ствола** и базой исходного дерева, с допустимым перепадом основания до 2 блоков по Y, квадрат расстояния ≤16/49; порядок обхода по близости. Полная высота найденного дерева сама по себе не ограничена 4/7 блоками, но общее число обработанных logs ≤48/96. Ограничивать количество сканируемых кандидатов и высоту обхода; только уже загруженные чанки и server side. Не искать бесконечно по листьям/брёвнам.

Если рядом есть два дуба и берёза: дубовый топорный удар должен рубить первый дуб и близкий второй дуб (в лимите), берёзу оставить. Если там дом из дубовых брёвен: дом не затрагивать, даже если дуб натурально растёт рядом. Защита построек важнее идеальной полноты рубки.

**Важно про обещания:** полностью достоверно отличить прирученное/вручную поставленное бревно от естественного без сохранённого происхождения блока невозможно. Потому критерий реализации — строгий консервативный детектор + отрицательные тесты домов/структур; в спорных случаях auto-fell отключён для кандидата. Не объявлять 100% защиту, если тестами не доказано.

## Дополнительные тесты

1. Нет руны / нет Shift: строго обычное действие на один блок/растение.
2. 3×3 и 3×3×2 ориентация: Север/Юг/Восток/Запад, верх/низ; всего 9/18, включая центр.
3. Разная прочность: непригодная кирка не добывает руду и не выдаёт её дроп; смешанная стена пропускает неподходящие блоки.
4. Массовая обработка не обходится через отменённое событие или защищённую территорию; творческий режим не выдаёт survival-дропы.
5. Культура 5×5 с незрелыми растениями: только зрелые, грядка остаётся; не теряются семена в unintended duplication.
6. Топор: два дуба в R4 / R7 и берёза; выход за радиус; 48/96; срубленное дерево рядом с дубовой постройкой — постройка целая; chunks not loaded.
7. Чары и loot/XP: количество предметов/прочность соотносится с реально сломанными блоками; нет дополнительной итерации по центральному блоку; Unbreaking применён по-блочно.
8. Многопользовательский мир: одновременно два игрока с рунами, разные миры, смена инструмента, смерть/выход во время очереди.
