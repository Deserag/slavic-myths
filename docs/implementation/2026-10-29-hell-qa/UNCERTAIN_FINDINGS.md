**Дата создания:** 29.10.2026. Это постоянный живой список. Codex дополняет его при изолированном игровом QA по [полной задаче](CODEX_ISOLATED_RUNTIME_VISUAL_QA.md), коммитит и публикует вместе с результатами. ## Открытые вопросы (наследованные из предыдущих обсуждений)

### Q-001 — Два bossbar Повелителя магмы на старом кадре
- Категория: boss / UI / save / multiplayer.
- Сборка/условия: исторический пользовательский кадр; точный текущий JAR SHA и UUID сущностей пока не известны.
- Наблюдение: на кадре видели два bossbar, но неизвестно, было ли в мире два отдельных экземпляра босса или двойная регистрация бара одного.
- Ожидание: у **одного** легального босса — один принадлежащий ему bossbar; при двух вручную призванных экземплярах два бара сами по себе не доказательство бага. Не допустить orphan bossbar на Peaceful/death/relog.
- Источник: [#327](https://github.com/Deserag/slavic-myths/issues/327), где это прямо обозначено как неподтверждённая проблема.
- Воспроизведение: в отдельном тестовом мире сравнить количество реально загруженных `magma_lord`/UUID и bossbar при одном /summon, двух /summon, естественном энкаунтере, после /difficulty peaceful, смерти и перезахода.
- Доказательства: PENDING (после теста: JAR SHA256, seed, XYZ, команды, real screenshots, latest.log).
- Почему неоднозначно: одного кадра недостаточно для количества сущностей; баг и нормальный второй босс дают схожую картину.
- Варианты решения: если один босс — искать двойную регистрацию/утечку event/bar; если два — корректно разделить UUID; не переписывать shared bossbar систему без воспроизведения.
- Статус: `NEED_REPRO`.
- Решение владельца: PENDING.

## Шаблон новой записи

```md
### Q-XXX — Краткое название
- Категория:
- Сборка: branch / commit / JAR SHA256 / NeoForge / seed / dimension / XYZ / difficulty
- Наблюдение:
- Ожидание и ссылка на контракт:
- Точные шаги воспроизведения и частота:
- Доказательства (log/video/image/test save copy):
- Почему баг или норма неясны:
- Предлагаемые варианты исправления и риски:
- Статус: NEED_OWNER_DECISION | NEED_REPRO | NEED_ART_SOURCE | NEED_TECH_AUDIT | RESOLVED_AS_BUG | RESOLVED_AS_INTENDED
- Решение владельца: PENDING
```

Не путать с подтверждёнными дефектами: доказанный баг и несоответствие утверждённому дизайну исполнитель чинит самостоятельно, затем пересобирает/ретестит; сюда заносит только нерешённые спорные случаи и те, что требуют подтверждения фактов. Весь реальный runtime без изоляции = `NOT_RUN`, а не отсутствие проблем.
