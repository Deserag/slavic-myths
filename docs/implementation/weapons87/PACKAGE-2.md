# Пакет 2 — адресный хват и player-render косы

Цепочка #87 остаётся IN_PROGRESS. Это промежуточный пакет #115/#117/#192/#121, не итоговая сдача всей программы и не установка PolyMC.

## Реальные изменения

- 28 существующих моделей: только `display` (повороты, масштаб, перенос точки хвата). Геометрия, UV, текстуры и все остальные JSON-поля сравнены с `before-grip-source.zip` и сохранены.
- У коротких булав/мечей/топоров сохранены прежние углы и масштаб; исправлена только точка, которая должна лежать в ладони. Древние копья уменьшены с масштаба1.15 до0.65; кинжал Соловья0.8→0.5; длинные посохи получают отдельный хват с безопасным наклоном. Эти визуальные размеры не меняют reach/hitbox или характеристики.
- Орнаментальная геометрия косы KEEP. Лезвие развёрнуто наружу от головы; `ScytheGrip` используется настоящими `WeaponHands` и `NightClient` custom render paths. Единый pivot не смещается из кисти при переходе стойка→взмах. Учтён существующий наклон руки к−90° в кадре контакта: древко остаётся горизонтальным и направленным вперёд. Сроки серверных действий, NightSwingPose, боссовые mesh/UV/textures не менялись.
- Физически левая ориентация кистеней отражена поворотом, чтобы груз висел с внешней стороны руки; формы/палитры/спрайты сохранены. Предыдущие manifest и source comparisons пакета1 сохранены отдельно с суффиксом package1 и `package1-source-projections.zip`.
- Канонический `weapons87_grips.py` идемпотентен и применяется последним из weapon overlay; генераторы проверены в отдельной копии.

## Доказательства

До применения сохранены 28 персональных технических листов `blueprints/grips/*.png` с точными JSON-предложениями. `grip-68/` — исходный полный обзор, `grip-68-after/` — реальные production transforms после изменения; `grip-before-after/` — 22 составных листа одних камер/масштабов для68 IDs, Steve/Alex и обеих рук. Это фиксированная source-поза ITEM с настоящими ModelPart/UV и native translateToHand, не скриншоты Minecraft и не отыгранные атаки.

`head-clearance.json` проверяет треугольники против native head box только в этой фиксированной позе. После изменения кандидаты остаются только у двух прежних чеканов; их принятые углы/модели/позиции не менялись. Это геометрические кандидаты без маски прозрачных texel, а не объявленный runtime FAIL/PASS. Их стоит посмотреть в ручной проверке; произвольно менять принятые чеканы по синтетической позе нельзя.
