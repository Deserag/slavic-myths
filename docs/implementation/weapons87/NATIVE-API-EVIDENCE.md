# Installed API evidence

Installed dependency: build/moddev/artifacts/neoforge-21.1.255-sources.jar (generated by Gradle, not vendored here), SHA256 1735c8a969db4d4a308d83bd6dc67152f2b15ca4181bd59dd715c21c0f8ed265. Minecraft1.21.1 official mappings/Java21. The offline fixtures compile against these same installed classes.

- IClientItemExtensions.getArmPose/applyForgeHandTransform/getCustomRenderer: official client extension hooks, no common class references to renderers.
- ItemInHandRenderer invokes applyForgeHandTransform before its use-animation branch; true skips only that branch, not preceding camera bob. Installed BOW branch uses f8=useDuration-(remaining-partialTick+1), divisor20 and applyItemArmTransform(sign*.56,-.52-equip*.6,-.72). BowDrawClient preserves that source pose, changes duration to actual12/30 for three items only; negative initial visual progress clamps0 like server. Native fixture independently reproduces installed vanilla20 branch and compares120 matrices, then compares606 values to actual FieldBowItem/FinistBow factories.
- ItemRenderer.getModel calls ItemOverrides.resolve with actual LivingEntity, then render calls ClientHooks.handleCameraTransforms before custom renderer. BakedModelWrapper delegates isCustomRenderer.
- SeparateTransformsModel.bake uses context.useBlockLight from root for all perspectives; therefore explicit root gui_light front is required to preserve original generated GUI lighting.
- minecraft:item/generated display.fixed rotationY180; WeaponProjectileRenderer previously reused it during flight. Actual native ItemTransform and independent velocity-vector comparison prove perpendicular-before/aligned-after.
- LivingEntity.hurt rejects smaller damage while invulnerableTime>10 and amount<=lastHurt. A bypass_cooldown secondary hit resets lastHurt and window, so it is not a safe blind fix for ThunderAxe.
- DamageContainer has reductions INVULNERABILITY/ARMOR/ENCHANTMENTS/MOB_EFFECTS/ABSORPTION/INNATE_RESISTANCE and setPostAttackInvulnerabilityTicks, but no lastHurt accessor. Any mechanic correction needs careful scoped design.
- bone_arrow is an ArrowItem, currently using vanilla Arrow and vanilla projectile renderer; GUI bone point is its inventory identity. No custom arrow entity/physics is introduced by ordinary art QA.

These are source/API observations, not proof of runtime. No world/entity/client/game instance was created by the numeric/model-part fixtures.
