Референс игрового UX: WoW Dragonflight Talent Tree (узлы и связи, выбор/подсказки), Guild Wars 2 Hero Skills (назначение навыков) — **не копировать художественный стиль, классы и число игровых слотов чужой игры**. Пользоваться реальными `ClassDefinitions.BASES = druzhinnik/vedun/razboinik` и доступными слотами `ClassState`.

### Состояния (каждое обязано работать)

1. **ВЫБОР КЛАССА:** только 3 класса, карточки сопоставимы, подтверждение и описание; не показывать чужую ветвь.
2. **ДЕРЕВО БЕЗ ВЫБОРА (исходное состояние):** после открытия основного окна `selected = ""` и ничего не инспектируется. **ВСЁ доступное пространство полотна** используется для графа; **нет фиксированного процента 70/85/80, нет постоянного сайдбара**. Исключения — лишь тонкая верхняя навигация и компактная bottom action strip, а не дополнительные панели. Связи узлов читаются, дерево не обрезано, масштаб/панорама с управлением понятны.
3. **КЛИК ПО НАВЫКУ:** вывод компактной контекстной карточки (название, 0/3, описание, требования, изучение, назначение), которая **не отталкивает/не перекраивает** дерево; ESC/клик по пустому месту закрывает. Hover показывает tooltip, но не выбирает.
4. **КЛАВИШИ И СЛОТЫ:** **на том же экране** внизу 3 компактные активные и фактические пассивные иконки (без огромных блоков). Клик по иконке: выбрать выученный навык, назначить слот и **изменить привязанную клавишу** (1/2/3 — схематические ярлыки, фактические `KeyMapping` из `ClassClient`). Смена разрешается также из выбранной карточки. Дополнительная вкладка `Клавиши` даёт полную таблицу, но не заменяет быстрый доступ в дереве. Отмена, очистка, конфликт ванильных/чужих биндов. Не назначать невыученное.
5. **НАПРАВЛЕНИЯ:** отдельный экран выбора реальных First/Second `BRANCHES`, компактно и понятно, locked requirements.
6. **МАСТЕРСТВО:** отдельное полотно/каталог для Third/Ultimates и испытаний, без смешения с активным деревом и биндами.

### Технические ограничения

- В реальном `main` по состоянию на 19.10 `ClassScreen.java` содержит списковый `initSkills()`, а `ClassTreeLayout.java` рассчитывает граф. **Это не совпадает со скриншотом игрового окна.** Codex сначала точно устанавливает source SHA/JAR скриншота и не правит не ту рабочую версию.
- Настоящий renderer, pointer hitboxes, pan по пустой области, zoom в точку указателя, кнопка fit tree и запоминание положения при selection/network refresh. Узлы не закрываются всплывашками; разбиение на страницы/вкладки по реальным смысловым функциям.
- `ClassDefinitions`, `ClassState`, `ClassNetwork`, `ClassClient` — истинные источники skills/ranks/points/активных биндов. **Не придумывать новые классы или слоты**.
- Проверить GUI scale 2/3/4, 1280×720 и 1649×928; нет перекрытия текста/иконок/корней дерева. Никаких обрезанных `Дерево навыко…`.
- Server-authoritative purchase/branch requirements, сохранения, MP, старые миры; не трогать навыковый баланс ради UI.

### ЖЁСТКАЯ ПРИЁМКА

**Видеопоследовательность и реальные рабочие состояния:** выбрать класс → открыть дерево (НИЧЕГО не выбрано) → zoom+pan+fit → tooltip hover → выбрать узел → закрыть карточку → изучить/заблокированный → нажать bottom-slot → назначить/сменить клавишу/отменить → направления → мастерство → назад. Реальные снимки 6 состояний **из production source** или честный `IN_GAME_NOT_RUN`; Java21 build и JAR. Макет SVG / генеративный рисунок **не** доказательство рабочего окна.

**Промежуточный отчёт и ручная приёмка владельца обязательны.** Не брать другой issue до завершения текущего UX-пакета; не помечать `owner-accepted`.
