# Сборка, версия, выпуск, PolyMC

## Версия
Обновить номер релиза до **1.8.5** в тех местах, где реально задана версия текущей ветки мода (Gradle/metadata/manifest или соответствующая система проекта). Не создавать новый release branch без явного запроса. Не перезаписывать историю; пользователь предпочитает обновлять `main`.

## Обязательные проверки до копирования JAR
1. `git status --short` — проверить только изменённые файлы задания, не затирать чужие изменения.
2. `gradlew` / реальная Gradle сборочная команда проекта без `runClient` и без запуска игры. Проверить успешный exit code, правильные dependency и output version.
3. Быстрые автоматические и статические тесты, если доступны, плюс проверка `lang`, `.png`, модели, `sounds.json`, recipes, item registry.
4. Проверка jar содержит новые resources и он не пустой.
5. Краткий отчёт по отсутствующим runtime GUI-checks: пользователь тестирует вручную в PolyMC.

## PolyMC
**По явному разрешению пользователя обновить тестовый инстанс PolyMC**.
- Найти существующий, уже используемый для Slavic Myths тестовый профиль. Использовать известный инсталляционный скрипт/путь из проекта, если он существует; не запускать PolyMC GUI.
- Если профиль отсутствует или его нельзя точно идентифицировать, не удалять и не заменять чужие JAR; оставить готовый JAR и сообщить точную причину, что установка не завершена. Не выдавать ложное «PolyMC обновлён».
- Проверить installed NeoForge/Minecraft version (Minecraft 1.21.1, соответствующий существующему профилю mod loader) и отсутствие двух версий одного `modid` одновременно.
- Сделать безопасную копию заменяемого mod JAR (или сохранить в backup вне mods), удалить из целевой папки `mods` только однозначно идентифицированный старый JAR того же modid; не удалять соседние моды.
- Копировать свежесобранный JAR в `mods`, сверить SHA256 byte-for-byte с билдом, отчитаться каким профилем/путём обновлено.
- **Ни при каких условиях не запускать Minecraft, PolyMC, runClient или UI-тестирование**.

## Отчёт Codex краткий, по-русски
- Итог: 1.8.5, компиляция/тесты.
- Перечень реализованных главных/побочных квестов, вещей, очищения.
- Файлы модели/текстур/озвучки/анимаций и подтверждение, что открывал refs.
- Путь JAR, установленный профиль PolyMC и SHA256 (только если реально установлено).
- Что пришлось адаптировать к реальной архитектуре (конкретно).
- Не заявлять 100%-ую проверку внешнего вида, если не делали реальный запуск; пользователь проведёт ручную проверку.
