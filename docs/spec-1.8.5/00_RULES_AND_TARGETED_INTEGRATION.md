# Приоритеты и ТОЛЬКО точечная интеграция
## Что читать в репозитории
1. Правила `AGENTS.md` по местам работы, корневые настройки Gradle/мода — только для проверки версии и сборки.
2. Поиск по именам/реестрам (разные варианты `BabaYaga`, `Baba_Yaga`, `CatBayun`, `Bayun`, `GrayWolf`, `GreyWolf`, `Skaz`, `TaleBook`, `quest`, `trust`, `reputation`). Найти исходные классы без просмотра всех мобов.
3. Только актуальные квестовые сохранения, вход в диалог, NPC interaction, рендер/статусы, доступ к NPC локациям и существующую избу Яги.
4. Точечно найти текущие `mor`, `morov`, infected block maps, полоз/ритуал/рог, лут Лиха и Овинника, чтобы не создать второй набор систем.
5. Точечно посмотреть регистрацию предметов, текстур, моделей, sound events, GUI и Книгу сказаний.
6. Если используются разные trust levels, адаптировать проверку II к существующей шкале (доверие II = второй уровень), не менять шкалу глобально.

## Приоритет исходных данных
**Игровая согласованная механика текста > одобренный Minecraft-референс в части внешности > текущие реальные контракты проекта > предложения, но без отступлений от сути.** У референса могут быть неправильные буквы/цифры; не переносить изображения текстовыми GUI-заглушками.

## Запреты
- Никаких глобальных миграций/новых модулей/сторонних библиотек ради короткой квестовой цепочки без необходимости.
- Не перезаписывать ванильные текстуры, существующие моровые предметы и модели NPC.
- Не создавать постоянных копий Кота, Бабы-яги, Волка на карте. Временные актёры сцены не являются «новыми приручаемыми NPC».
- Не ломать старые квесты/награды, приоритет обычного поведения NPC вне сцен.
- Не создавать бессмертного Волка, который бесконтрольно побеждает Полоза.
- Не выдавать легендарную награду Полоза как награду за ранние поручения.
- Не спамить чатом, звуками, тиковой логикой, поиском десятков чанков, сетевыми пакетами.
- Не ломать запланированную 1.8.6 глобальную навигационную книгу и 1.9/2.0 системы Ада.

## Структура и стиль кода
Новые интерфейсы/классы только если реально нужны. Прогресс хранить per-player и server-authoritative. События — event driven (победа, контакт, диалог, взятие/сдача предмета, победа над Полозом), не сканировать все инвентари и все сущности каждый тик. Реальный код не должен предполагать несуществующие классы.
