# Обязательный стандарт: ввод оружейных навыков (22.11.2026)

**Решение владельца:** все дополнительные активные способности оружия вызываются через `Shift+ЛКМ` и/или `Shift+ПКМ`. Запрещается добавлять отдельные клавиатурные кнопки для новых оружейных навыков. Этот документ применяется при создании или изменении любого оружия, в том числе будущего. Базовый код для изменений: `feature/ocean-rewards-completion-20261120` @ `6d134bf78`; задача #529.

## Границы подзадачи #529
Только ввод и маршрутизация действий; **НЕ** менять цифры урона, длительности, cooldown, стоимость, рунную совместимость, общий дизайн описаний или HUD. Не переносить навыки класса, аксессуаров, транспорта и инструментов в оружейный диспетчер.

## Контракт для каждого оружия
1. **ЛКМ без Shift:** штатная атака либо уже существующая уникальная базовая атака; **ПКМ без Shift:** штатное контекстное действие (зарядка, блок, бросок, поток, выстрел). Их нельзя дублировать при Shift.
2. **Shift+ЛКМ:** дополнительный навык, если предусмотрен; его обработка начинается в клиентском `WeaponSkillInput.attack`, где сначала проверяются экран, живой игрок, Shift и **реально удерживаемый предмет**; событие отменяет vanilla swing/attack и отправляет существующий пакет с конкретным skill ID. Добавить предмет в общий `WeaponSkillBindings.shiftLeftSkill`; серверное событие отменяет обычную атаку по существу и копание блока при Shift. Если навык недоступен, обычный удар не должен выполняться «взамен».
3. **Shift+ПКМ:** дополнительный навык через `Item.use`, `useOn` либо существующий предметный `RightClickItem` только для основной руки; явно отделить ветку Shift от ПКМ без Shift. Если предмет имеет блокировку, зарядку или метание, порядок обработки обязан исключать двойное действие.
4. **Больше двух активных дополнительных действий:** не добавлять третью букву. Переиспользовать те же два сочетания в явно отображаемом режиме/контексте, без потери существующих способностей. Пример: посох Мора переключает стихию через Shift+ПКМ, а Shift+ЛКМ вызывает воронов в режиме МОР или бурю в режиме ОГОНЬ.
5. **Сервер:** проверять конкретный предмет в руке, живого игрока, разрешение цели, cooldown и цену применения. Клиент не выбирает произвольный серверный класс или ID предмета. Не рассчитывать на новый CD или damage без отдельного согласования. При работе с пакетами и Shift учитывать серверное состояние sneak.
6. **Пояснения:** подсказывать действительную комбинацию, включая удержание/отпускание ПКМ, если навык заряжается; никаких старых `G/V/J/K/R` в текстах оружия. Общую цветовую систему и HUD будут менять отдельно.
7. **Разделение:** навыки классов, управление транспортом, декоративные/аксессуарные предметы, творческие режимы тестирования не перехватывать. Существующие пассивные эффекты оружия сохраняются.

## Регрессия перед приёмкой

- Обычный ЛКМ/ПКМ **без Shift** не вызывает дополнительный навык.
- Shift+ЛКМ по воздуху, существу и блоку **не наносит одновременно vanilla-удар и удар навыка**.
- Shift+ПКМ не запускает сразу обычный выстрел/зарядку/блокировку; удержание и отпускание различаются корректно.
- Все ранее доступные навыки вызываются в новых условиях; режим посоха Мора не теряет воронов/бурю.
- Нельзя срабатывать с предметом не в основной руке, после выбрасывания или при открытом меню.
- Пакеты не обходят проверку статуса персонажа, целей и cooldown; в мультиплеере состояния игроков независимы.
- Смена рук/предметов, relog, смерть, UI scale и dedicated server проверяются отдельно.
- `gradlew clean build`, GameTests, реальный клиент и мультиплеер фиксируются отдельно; **исходный код не является доказательством игрового PASS**.

**Правила для новой реализации:** дописать предмет в одну центральную таблицу маршрутизации ввода, зарегистрировать серверную ветку действия, сделать документацию и тесты. Не копировать бывшие `ClientTickEvent + KeyMapping` обработчики оружия.
