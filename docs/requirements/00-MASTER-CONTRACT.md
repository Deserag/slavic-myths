# 00. Единый договор на любой новый контент

1. **До кода:** найти утверждённое решение владельца, родительское/дочернее Issue, актуальный HEAD `hell`, уже имеющиеся аналогичные реализации и запреты scope. Не переписывать то, что уже реализовано.
2. **Один предмет задачи — один контракт:** `ID | что увидит игрок | как получит без OP | численные параметры | визуальный референс | ограничения | реальные доказательства`. Не выдумывать непринятые числа.
3. **Полнота:** регистрация Java + data JSON + текстуры/модели/звуки + RU/EN + получение/активация + награда + сохранение + интеграция. Отсутствует звено — `FAIL`.
4. **Игровая доступность:** от обычного старта нового мира до функции и ожидаемого результата без читов. Одна команда `/give`, `/summon` или `/locate` не доказывает доступность.
5. **Не разрушать старое:** modid `slavicmyths`, registry IDs, существующие сохранения/NBT, прогрессию и принятые механики; отдельная проверка старого мира.
6. **Никакого «заглушка = готово»:** не создавать пустые предметы/классы, недостижимые задания, неподключённые лут-таблицы, фиктивные эффекты/аудио, невидимую модель.
7. **Точная приёмка:** матрица `REQUIREMENT | REAL_SOURCE | PLAYER_PATH | TEST | EXPECTED | EVIDENCE | PASS/FAIL/BLOCKED/NOT_RUN`. У каждого PASS — артефакт проверки.
8. **Строгий scope:** арт не меняет баланс; баланс не переписывает модели; генерация не переносит достижения; случайная правка чужой системы запрещена без отдельного согласования.
9. **Сборка ≠ работа:** Java21 clean build и проверки ресурсов необходимы, но не считаются тестом мира, NPC, GUI, MP, FPS и лута.
10. **Честный финал:** «Сделано / Не сделано / Как проверить в Minecraft / Риски и откат / Следующая задача». Не запускать игру/PolyMC/сервер без отдельного разрешения; отмечать `NOT_RUN`.
11. **Контроль исполнителя:** не писать `DONE` и не закрывать Issue самостоятельно. Даже все технические PASS ≠ принятие владельцем.
