# Правило развития контента по патчам: предметы, руны, боссы и награды

**Решение владельца от 30.10.2026.** Обязательно учитывать при *планировании* будущих версий Slavic Myths. Базовая ветка разработки — `hell`, `main` не трогать. [Задача посадника #374](https://github.com/Deserag/slavic-myths/issues/374); [двух боссов #365](https://github.com/Deserag/slavic-myths/issues/365); [экономика #373](https://github.com/Deserag/slavic-myths/issues/373).

## 1. Сначала содержимое патча, затем сквозные награды
- **Не пытаться при каждом добавлении босса, сооружения, жителей или квестов одновременно придумывать новую руну, валюту, оружие, амулет и всю экономику.** В текущем патче сначала утвердить/создать собственную механику, мир, NPC, структуры, поведение, встречаемость и базовые предметы, без необязательных новых наград.
- **В следующих патчах** отдельно рассматривать тематические новые предметы, руны, аксессуары, альтернативы наград и их связь с боссами, квестами, ремеслом и прогрессией. Это не запрет на выдачу новых предметов в текущем патче, если они действительно необходимы для механики/лора и специально утверждены.
- Не добавлять что-то лишь ради количества. **Нет нормы «одна руна в каждом патче»**: в патче может быть 0 новых рун или несколько только после отбора и согласования владельцем. Не создавать «пустые» ID/заглушки, не регистрировать отсутствующие предметы.
- У каждого нового босса и квестового NPC разрешены **базовый реальный трофей, необходимая обязательная добыча и заранее существующие расходные награды**. Большие бонусы и новые уникальные руны — отдельно позже. Воспринимать временную базовую награду как **играбельную стартовую**, но не как окончательно сбалансированную награду для late game. Нельзя объявлять баланс окончательным по одной компиляции.

## 2. Условие отбора новых предметов/рун в патче (для проектирования)
Перед утверждением каждой новой руны/награды оформлять в соответствующей будущей Issue таблицу:

| Поле | Обязательно |
|---|---|
| Предмет, RU/EN имя, проектный ID | Чёткое отличие от существующих `resources/weapons/armor/magic/accessories` |
| Лор и связь с патчем | Почему это принадлежит именно этой теме/биому/боссу |
| Игровая роль | Что реально изменяет: боевой эффект, защита, передвижение, ремесло и т. п. |
| Уникальность | Аудит существующих рун/аксессуаров/оружия, отсутствие функционального дубликата |
| Получение без OP | Босс/контракт/обмен трофея/ремесло/структура, шанс, ограничения, повторяемость |
| Сила и цена | Тир, cooldown/duration, cap, обменная стоимость и сравнение с уже доступным gear в данный момент |
| Взаимодействия | Рунные слоты/Curios/броня/оружие, основные эффекты, RPG, существующие классы мобов |
| Визуал/звук/тест | Vanilla Minecraft стиль, 2D 16×16 для предметов, допустимый 3D для block/entity, реальные звуки если нужны, QA MP/save/anti-dupe |

Если нет игрового смысла/сбалансированного способа получения — не создавать предмет, оставить будущим кандидатом. Не менять старые ID, сохранения, рецепты и награды задним числом без явного миграционного решения.

## 3. Отдельный этап «интеграция наград»
- После реализации нескольких основных механик назначается **отдельная интеграционная/балансировочная задача**: пересмотреть реальную сложность получения, содержимое сундуков, фактический лут врагов, доступность ресурсов и ценность валюты по выживанию.
- Затем разрешается предложить: новые руны/артефакты по тематике уже известных боссов; альтернативы обмена их трофеев; новые способы изготовления или улучшения вещей, торговлю и приоритетную выдачу по доверительным уровням. Никакие варианты не активируются автоматически.
- **Интеграция не должна переписывать базовый квестовый движок**, стирать уже заработанные поручения, трофеи/одноразовые claimId, изменять прошлые сбережения игроков и выдавать награды дважды. Для любого обновления: миграция, обратная совместимость, per-player claim, unit/game MP test + проверка в выживании.
- Отдельно вести список кандидатов в будущих Issue. Их концепция, ID/название, баланс и патч **не утверждены заранее**. Решение владельца обязательно и для новых наград, и для пересмотра цены старых.

## 4. Пекельный посад — действующий частный случай
- **#373 = обычная торговля** 12 профессий, монеты, бартер, профессиональный XP. **Ни одного квеста или доверия** в этом пакете.
- **#374 = ЕДИНСТВЕННЫЙ новый городской квестовый источник**: посадник в Посадничьем тереме (публичный титул существующей роли старейшины, без 13-й профессии); личная репутация, увеличение числа поручений, поиск по Книге сказаний, сдача законных трофеев. **Другие NPC посада не раздают отдельные персональные поручения**; задания дружины, фермеров, ремесленников, городские просьбы можно **подавать через общий список у посадника** с отметкой инициатора/отдела. Старые независимые квесты обычного мира и воинские задания вне Пекельного посада НЕ удалять.
- **#365**: существующие натуральные боссы Мытарь/Баук не требуют квеста для спавна или победы; посадник показывает X/Z+радиус из реально сохранённой области. Награда базового обмена **20 `slavicmyths:ancient_coin` + 2 `minecraft:netherite_scrap` за один законный трофей** сохраняется на текущем этапе как **временный baseline**, а не ценный конец прогрессии. Она уже была утверждена и **не заменяется самовольно**. Позже владелец решит, усиливать ли её, заменять или дополнять альтернативным **взаимоисключающим** выбором наград/руной. **Сейчас никаких новых рун за трофеи НЕ создавать**, конкретные имена/ID/стоимости не фиксировать.
- Правило `один claimId → одна выдача` не меняется ни сейчас, ни в будущих патчах. Законный трофей принимается у посадника даже без предварительного квеста/ранга; репутация управляет **доступом к поручению**, не правом на естественную встречу с боссом и не правом сдать уже полученный трофей.
- **Городской источник поручений — только посадник, не старейшина Вечевой палаты, не торговая лавка, не сотник.** Местами работы остальных NPC могут быть казармы/кузня/житница, но квесты они сообщают через посадника, без дублирующего меню и отдельных активных контрактов. Сцены/диалоги других жителей допустимы как подсказки, но не как выдача задания.
- Внешний вид и координаты Посадничьего терема ещё требуют отдельного чертежа. До согласования не вставлять новое здание на занятую Вечевой палату/площадь/дороги, не терять сохранённые дома.

## 5. Не путать состояния работы
1. **Концепция**: идеи/тематические варианты, неизвестные ID/баланс.
2. **Утверждённое ТЗ**: объём/критерии/цены одобрены; можно создавать задачу, но реализация ещё не поручена.
3. **В работе**: только по отдельному поручению владельца, собственная ветка от `hell`.
4. **Тестирование**: доказательства `REQUIREMENT | EVIDENCE | PASS/FAIL/BLOCKED/NOT_RUN`; реальный клиент/сервер только с разрешением безопасной среды.
5. **Готово**: только решение владельца; ни одна идея/Issue/PR/clean build не равны выпуску.

Планирование и проектная политика сами по себе **не авторизуют Codex, коммиты игрового кода, worldgen или реорганизацию уже активных PR**. Все пересечения с прежними задачами устраняются узко, с ссылкой на новые решения владельца.
