# Будущая система классов — НЕ РЕАЛИЗОВАНА

## Зачем

Класс должен менять стиль боя и взаимодействия с миром, а не только числа урона.
Игрок начинает без класса, осваивает знания и затем выбирает направление.
Система вводится постепенно поверх обычного выживания, без немедленного превращения в RPG.

## Предварительные направления

| Направление | Возможный стиль | Возможное продолжение |
| --- | --- | --- |
| Дружинник | Мечи, топоры, щиты, тяжёлая броня; физический бой, защита | Богатырь: сила, тяжёлое оружие, живучесть, боевые приёмы |
| Волхв | Стихии, молнии, посохи, ритуалы, боги; собственный магический ресурс | Условный Волхв Перуна |
| Ведун | Духи, травы, зелья, проклятия, лечение, обереги | Условный Ведун Леса |

Охотник, знахарь, кузнец и жреческие направления — возможные идеи.
Список и названия не утверждены. Эти роли и ветви — игровая интерпретация,
не заявление о существовании исторических «классов».

Общая схема: без класса → первые знания → направление → развитие → способности
→ специализация → продвинутый класс. Примеры: Воин → Дружинник → Богатырь;
Ученик → Волхв → Волхв Перуна; Ученик → Ведун → Ведун Леса.

## Правила будущего проектирования

До реализации решить: стоимость выбора, смену и совмещение направлений,
смерть и сохранение прогресса, PvP, совместимость с другими модами и баланс ресурсов.
Ничего из этого текущая версия не предрешает. Не запрещать базовое выживание
игроку без класса. Никаких пассивных сканирований всех игроков ради класса.
Способности требуют серверной проверки владения, cooldown, дальности и стоимости.
Боевые бонусы применять через атрибуты/события с устойчивыми ID модификаторов:
повторный вход не должен накапливать бонусы.

## Затрагиваемые системы Minecraft

Урон и атрибуты, использование оружия/щитов/брони, предметы и рецепты,
эффекты и взаимодействие с сущностями, смерть/respawn/смена измерения,
сохранение и загрузка игрока, синхронизация сервер→клиент.
Позже — отдельный GUI, клавиши и визуальные эффекты, изолированные на клиенте.

## Возможные данные игрока

Версия схемы; необязательный ResourceLocation класса и специализации;
набор ID знаний и открытых способностей; прогресс по утверждённой модели;
ресурсы и сроки cooldown — только когда появится использующая их механика.
Не хранить вычисляемые бонусы или копии описаний классов на каждом игроке.
Неизвестный ID должен безопасно обрабатываться при удалении контента.

При первой реализации — Forge Capability с сериализацией NBT, миграцией схемы,
обработкой PlayerEvent.Clone (включая доступ к capability исходного игрока),
согласованными правилами смерти и синхронизацией после входа/respawn/смены мира.
Проверить API clone/invalidation именно в Forge 36.2.42 до написания кода.
Определения классов отделить от состояния игрока; выбрать формат данных только
после появления конкретных требований. Сейчас capability и сеть отсутствуют.

## Связь с первыми предметами — только планы

- Громовой камень: волхвы, ритуалы, изготовление предметов Перуна, открытие способностей.
- Оберег: ведуны, волхвы и другие классы, будущая защита от духов.
- Берестяной свиток: знания, рецепты, сведения о существах и развитие отдельных ветвей.

Сейчас предметы инертны. Нет классов, маны, выносливости, прокачки, дерева навыков,
заклинаний, способностей, классовых предметов или GUI. Registry ID не меняются при
будущем подключении систем; бизнес-логика добавляется вне регистрации контента.

## Связи после 0.3.0 — только будущая концепция

Сердцевина Лешего → будущая ветка Ведуна → природная магия → взаимодействие
с лесными духами. Сейчас это редкий ингредиент без рецептов и активных эффектов.

Волхв Перуна → Перунит → Громовой камень → способности молнии.
Минерал и crafting-цепочка существуют; класс и способности молнии НЕ реализованы.
Домовой и Леший не добавляют данные класса игроку и не требуют новой Capability.

## Состояние после 0.4.0

Книга сказаний упоминает три пути, но выбора/классов/маны/способностей игрока нет.
Пять знаний используют уже сохраняемые vanilla advancements; отдельная capability
ради дублирования этих флагов не создана. План capability выше относится к будущим
классам, не к текущей реализации. Свиток и оберег теперь участвуют в первом ритуале;
Древний знак — progression item. Боевой магии у этих предметов по-прежнему нет.
