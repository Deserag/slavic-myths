## Обязательное качество — не путать ванильный стиль с рисунком в Paint
1. Ясная 2D-иконка обычного предмета, уместная рядом с vanilla Minecraft (аметистовый осколок, осколок эха, кварц, железный слиток, перо — **только стилистические аналоги**, ничего не копировать). Ни псевдо-фотореализма, ни сглаженных кистевых мазков.
2. Работать осмысленными **пиксельными кластерами** и ступенчатым силуэтом. Свет создаёт несколько читаемых групп плоскостей: светлая грань/кромка, основной материал, затенённая сторона, локальный глубокий контур. Запрет: гигантская однотонная заливка с чёрной обводкой, хаотичный шум, "вырезка из Paint", толстый блюр, AO-фон/тень вокруг самой иконки, сглаживание, shader-glint.
3. Разные украшения и награды различать **сначала силуэтом, потом символикой/деталью и только затем палитрой**. Не делать из каждого трофея одинаковую круглую монету. Но физически круглые монеты и печати не насильно превращать в квадраты.
4. Проверять исходный JSON модели и реальную active texture: native resolution и display constraints **не ломать автоматически**. 16×16 — эталон **читаемости**, не команда масштабировать любой PNG. Передавать PNG с настоящими пикселями, не снимок генератора с соседним декоративным фоном.
5. По умолчанию обычный плоский трофей, печать, пряжка, монета, клык, перо, фрагмент = `minecraft:item/generated` с отдельной 2D-текстурой при отсутствии осмысленной 3D-функции. **3D не запрещена во всём моде**: блоки, щиты, оружие, предметы с действительной пространственной формой могут оправдывать её. Для 3D-предметов инвентарь всё равно должен читаться и проверяться отдельно.
6. Использовать существующие модели и хороший art **KEEP**, не делать массовую конверсию всего `resources`. В модели `mor_crystal`, унаследованной от блока, ничего не менять только из-за наличия 3D.
7. В #111 `pearl_fragment` **снять блокировку дизайна**: разрешена адресная замена исходного одиночного повёрнутого кубоида на `minecraft:item/generated` и новый качественный **плоский** PNG. Не переносить UV прежнего 3D кубоида в плоскую текстуру. Сколотый, асимметричный *осколок*, не целая жемчужина: молочная светлая грань, голубовато-серая тень, слабый перламутровый оттенок без плавного градиента. Исключение из старого общего пункта «не менять geometry/UV» относится только к этой одобренной смене типа модели; gameplay и registry неизменны.
8. Общая эстетика референсов #111 владельцем одобрена, но **пара А/Б для отдельного ID не выбрана**. Исполнитель выбирает наиболее удачное решение под реальную игровую иконку, фиксирует выбор и причины в отчёте, не выдаёт выбор за персональную приёмку владельца.

## Порядок передачи Codex
- **Сначала** HEAD / git status, inventory ID, реальные texture/model references, генераторы, исходные SHA, свои/чужие незакоммиченные изменения. У #111 уже заявлено 8 локальных FIX без commit/push: **не уничтожить их** и не считать, что они опубликованы.
- Сверить 8 сделанных FIX с новым художественным ориентиром: не переписывать удачные текстуры автоматически. Реализовать отдельной партией `pearl_fragment`; неоднозначные решения оставить явно отмеченными.
- Делать поставки максимум по **3–4 ID**. Каждый пакет — `ID | исходная модель/PNG | дефект | KEEP/FIX | выбор A/Б и мотив | точный diff | SHA старый/новый | результат`.
- Представлять **фактическое** `before / after` в одном масштабе GUI 1× и увеличении 3× nearest, сравнительную ленту семьи и минимум один кадр из игры **после разрешённого игрового запуска**; если запуска не было — честно `NOT_RUN`, `IN_GAME_OWNER_PENDING`.
- Java 21 build + JSON, PNG, assets/JAR checks; не изменять ID, registry, лут, геймплей, локализацию, общие рендеры, порядок творческого инвентаря, NBT или чужие файлы.
- Не закрывать #92/#111–114 без подтверждения владельца, не назначать `owner-accepted`. Для #114 сохраняется QA-first: выбранные новые FIX только при доказанном дефекте и с собственным индивидуальным макетом.
