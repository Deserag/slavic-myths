# #83 — микропатч еды: главным образом мясо (решение владельца 20.10.2026)

## Авторское решение по двум игровым скриншотам вкладки «Еда и напитки»

Владелец: **«В целом шибко править нечего; похожее мясо существ чуть улучшить по цвету и ванильному стилю. Это микропатч, не редизайн всей еды».** Большинство блюд, посуды, выпечки и напитков выглядят приемлемо. Мясо от разных животных вправе быть похоже — нельзя ради контраста делать искусственные необычные формы или яркие фантазийные цвета.

Обязательный [чертёж 16×16 — шесть кандидатов, натуральные палитры и приблизительные силуэты](./ISSUE_83_MEAT_MICROPATCH_BLUEPRINT.svg). **Это концептуальные новые направления, НЕ baseline actual production PNG и НЕ готовые изображения для установки.** Сначала проверять реальные файлы игры. [Общее правило минимальных правок](../PIXEL_ART_GUIDE.md).

### Дополнительный осмотр, без обязательной перерисовки

`cooked_goose`, `cooked_duck`, `cooked_goat`, `cooked_boar_meat`, `cooked_venison`, `cooked_bear_meat` — соответствующая приготовленная пара. Быстро сравнить каждую с сырым видом; если разница действительно отсутствует/есть неправильные цвета — точечно исправить **только одну доказанно дефектную иконку**, не делать автоматическую серию из шести. Супы, каши, пироги, блины и напитки по этим скриншотам **не требуют переделки**.

Модовые рыбы `raw_carp`, `raw_pike`, `raw_crayfish` / приготовленные — **вне микропатча**, если не будет отдельного подтверждённого дефекта.

## Сравнение с ванильным Minecraft

Визуальные ориентиры **по художественному языку, не источники ассетов для копирования**: `minecraft:chicken` и `minecraft:cooked_chicken` (птица), `minecraft:porkchop` / `minecraft:cooked_porkchop`, `minecraft:beef` / `minecraft:cooked_beef`, `minecraft:mutton` / `minecraft:cooked_mutton`.

Проверять в штатном масштабе GUI:
- естественные сдержанные различия красно-розовых и коричневых оттенков;
- узнаваемую толщину мышечной части, небольшие жировые/бликовые пятна и читаемый контур;
- целые пиксели/прозрачность, без гладкого blur, без фотографии, без чрезмерной детализации;
- разные идентичные мясные куски можно оставлять похожими, **но не 100% одинаковыми и не перекрашенными в неестественные цвета**;
- сохранить естественную и последовательную связь сырого и приготовленного вида.

**Не копировать** vanilla PNG и не перерисовывать мясо один в один по vanilla. Сопоставить читаемость и степень упрощения.

## Исполнительная последовательность Codex

1. Ознакомиться с `AGENTS.md`, настоящим брифом и `docs/PIXEL_ART_GUIDE.md`, проверить `git status`, актуальный `main` и одновременных исполнителей.
2. По двум присланным владельцем скриншотам выделить группы близких форм (сырая птица/коза, тёмные кабан/оленина/медведь). Для каждого из 6 raw ID сделать **A/B baseline по настоящему source PNG**, увидеть реальные отличия. Метки `OK/CHANGE`, точные пути PNG, цвет/форма, SHA.
3. Из подтверждённых проблем выбрать **минимальную группу 2–5 PNG** (не менять все 6 автоматически), выполнить точечный пиксель-арт без вмешательства в соседние модели/registry. Если совпадают из-за источника генератора, исправить только нужные шаблоны и проверить, что генератор не перезаписал хорошие assets.
4. Кратко проверить приготовленные пары, без обязательного редизайна. Исключить супы/выпечку, напитки, пиво и опьянение #84/85.
5. Визуальная проверка `old/new` одного ID при **1×** в настоящем инвентарном слоте и при 3–4× **nearest pixel**; одна итоговая линейка изменённых PNG на одинаковом фоне. Если есть игровая проверка владельца, она отдельно удостоверяется — source-preview не Minecraft-screenshot.
6. Java 21 clean build, проверки model JSON→PNG, ресурсы production JAR, неизменность соседних иконок/механик. Компактный отчёт по всем рассмотренным IDs: `ID | current defect | CHANGED/UNCHANGED | real before/after | files | PASS/NOT_RUN`.

## Жёсткие границы

- Никакой массовой перерисовки 94 food items, никаких новых еды/животных/рецептов и спецэффектов.
- Не менять `FoodProperties`, питательность, насыщение, raw/cooked processing, cooking recipes, `CustomModelData`, `lang`, `registry IDs`, `loot`, `NBT`, creative ordering.
- Ванильные ресурсы `minecraft:*` **не менять**; использовать как стилистический ориентир.
- Не трогать пиво/кружки/алкоголь #84/85 и готовые хорошие блюда; не менять item model JSON, если виноват только PNG.
- Не записывать `DONE`, не закрывать issue без ручного принятия владельцем в реальной игре. Предоставить только результат законченного микропатча и `OWNER_PENDING`, если runtime-test не состоялся.
