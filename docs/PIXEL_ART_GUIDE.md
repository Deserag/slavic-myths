# Slavic Myths 2.0 — художественный контроль изменений (НЕ замена готовых текстур)

**Дата:** 20.10.2026. Применяется только к новым микропакетам #81, #82, #83, #84, #86, #87, #88, #91. Этот guide — **проверяемое ограничение**, не команда массово унифицировать все изображения и переписать рабочие источники.

## Эталон по умолчанию

- У каждого предмета есть **своя узнаваемая форма** в обычном слоте Minecraft: не достаточно отличать предмет только цветом либо большим tooltip.
- Предпочтителен видимый pixel art с целыми пикселями, без антиалиасинга, гладкого размытия, масштабирования с bilinear или фотореалистичного градиента; разрешения PNG выбираются в соответствии с фактической моделью/UV — **не приводить все к 16×16 слепо**.
- Цвет и блики согласуются в рамках **одного семейства**: чистая светотень, ровная читаемая кромка, узнаваемый материал. Разным семействам **не обязательно** иметь одинаковую палитру или рамку; нельзя уничтожить художественную идентичность редкой руны, трофея, напитка или уникального оружия ради «единого тона».
- Сохранять хорошо работающие композиции. Художественный контроль направлен на **исправление конкретного дефекта**: нечитаемого силуэта, перепутанного UV, размытой текстуры, ошибочной иконки, сломанного display transform или бессмысленного дублирования; не на создание новой концепции.

## Схема приёмки каждого заменяемого ресурса

| Шаг | Обязательное доказательство |
|---|---|
| Диагноз | registry ID, точный model/PNG path, текущая версия, видимый конкретный дефект |
| Baseline | Screenshot/рендер **исходного production файла**: инвентарь 1×, 3× nearest, дополнительные ракурсы только по типу вещи |
| Запрет регрессий | Назвать **что НЕ меняется**: соседние PNG, ID, рецепты, model parent, transforms, slot layout, клиентская логика |
| Минимальный diff | Изменены лишь assets/UV, необходимые для устранения доказанного дефекта, без побочной смены внешности остальных |
| Проверка | До/после того же ID, одинаковый масштаб, одинаковое освещение/слот/камера и отсутствие пропавших текстур |
| Итог | Точный список IDs и файлов, факт Java21/resources/JAR validation, owner in-game acceptance отдельно |

## Отдельные ориентиры для пакетов

### #81 Материалы и трофеи
Визуально различать руду, слиток, кость, зуб, редкий трофей. Не заменять разницу силуэта просто другой палитрой. [Пиксельный визуальный лист](./design/ITEM_ICON_BLUEPRINTS.svg).

### #82 Растения и земледелие
Проверять фактические стадии `age`, item icon семян, саженца и урожая. Семена и кусты разных видов отличаются формой/размером листа/плода, не просто несколькими пикселями оттенка.

### #83 Еда
Суп остаётся в посуде, хлеб/пирог/сыр/мясо имеют разный силуэт. Не менять food effects, стеки, предметные ID и визуал пива.

### #84 Пиво + опьянение
**Исключение из обычной практики «разные силуэты для разных товаров»**: здесь должна быть **ОДНА сохранённая целая форма кружки**. Отличается только **ВЕРХНЯЯ поверхность жидкости и/или пены**. Предмет не должен выглядеть повреждённым/течь. Никаких боковых маленьких бутылочек, дополнительных кружек, надстроек, новых моделей для всех сортов. Приёмка — единая строка из 8 на реальном 16px item slot. Механика опьянения — часть той же Issue: 1–3 обычных без негативных эффектов, с четвёртой — первая ступень.

### #86 Руны
Сохранять глиф/редкость/назначение, единый стиль знаков в **одном конкретном семействе**, но не выравнивать все до одинаковой круглой пластинки. Missing icons исправлять только после подтверждения registration/model path.

### #87 Инструменты и оружие
Важнее всего силуэт и правильная посадка в руке: slot и первая/третья камера — отдельные проверки. Не править глобальные first-person transforms ради плохой иконки.

### #88 Броня и одежда
Инвентарная иконка не равна модели на теле. Требуются front/right/back/3/4 на Steve и Alex и проверка `layer_1/layer_2`, UV и trim. Статы не меняются.

### #91 Декор
Каждый блок проверять `top/side/bottom/tile/item` и повороты ступеней/плит/дверей. Рабочую породу дерева и нормальный набор текстур не перекрашивать просто заодно.

## Правило «не сломать унитаз при починке бачка»

Если устраняется локальная неисправность, **не допускается никакая новая визуальная или функциональная поломка рядом**. Это обязательное условие для acceptance: один исправленный дефект + ноль новых подтверждённых регрессий. Чужая итерация не считается выполненной по количеству изменённых файлов или красивой концепт-картинке.
