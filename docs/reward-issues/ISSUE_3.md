# #3 — регистрация урона залпа

Работа выполняется от `origin/main` (`b7616080`) в отдельном worktree.
Локальные обновления исходного рабочего каталога не перезаписываются.

## Диагностика

14 октября 2026, первый реальный GameTest server, 18:59 MSK:
нативные `AbstractArrow.onHitEntity` / `LivingEntity.hurt`, три равных попадания
по 6 урона по небронированному зомби с 100 HP дают 100 → 94 HP.
`invulnerableTime=20`. Равный повторный урон при оставшихся более 10 тиках
отклоняется. `AbstractArrow` на отрицательный результат `hurt` выполняет
`ProjectileDeflection.REVERSE`. Это подтверждённая причина прямых попаданий.
Тест явно вызывает нативную обработку контакта и не выдаётся за тест траектории.

## Изменение

Производственный метод стрельбы отмечает только многострельный залп UUID.
При успешном уроне сервер запоминает связку цели, владельца и залпа,
UUID обработанных стрел и время. Окно 40 тиков охватывает короткую очередь.
Хранилище использует слабые ссылки на цели и максимум восемь залпов на цель.
Нет сканирования мира или дополнительной проверки всех игроков каждый тик.

Следующая действительно попавшая стрела той же связки получает собственный
`DamageSource` с единственным дополнительным признаком `BYPASSES_COOLDOWN`.
Тип остаётся vanilla arrow; броня, щит, сопротивления и иммунитеты сохраняются.
Общий `invulnerableTime` не обнуляется. Повторный контакт той же стрелы
с той же целью отклоняется. Новый залп, другой владелец и vanilla crossbow
такого исключения не получают. Бонус +18%, расходы и старые режимы этого
изолированного PR сохранены; последняя локальная механика без бутылок
будет включена отдельно при интеграции #10.

## Проверки

`gradlew.bat clean build -I tools/reward-issues.init.gradle compileRewardChecksJava`
прошёл на Java 21, Minecraft 1.21.1, NeoForge 21.1.255.
Второй GameTest server (19:10 MSK, интервал старта более 10 минут): все четыре
проверки PASS. Для обоих предметов три нативных контакта по 6 дают 100 → 82 HP.
Повторная обработка стрелы, другой владелец, другой залп и vanilla crossbow
HP не меняют. Три отдельные цели получают по 6. Физический залп обычного
арбалета, созданный production `performShooting`, даёт три столкновения по 8,
100 → 76 HP; стрелы исчезают, прочность расходуется на 3.
В физическом тесте направления трёх стрел сведены на одну цель специально,
чтобы отделить регистрацию урона от геометрии веера. Щит/броня/проки,
singleplayer и подключённый dedicated client пока **PENDING**, этап не завершён.

Ранние три ошибки настройки init-script возникли до запуска Minecraft и исправлены.
Реальные запуски данного этапа: GameTest server 2, client 0, standalone dedicated 0.
Тестовые классы opt-in и не добавляются в production sourceSet.
