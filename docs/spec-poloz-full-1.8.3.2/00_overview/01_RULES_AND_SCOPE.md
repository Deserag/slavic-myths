# Правила, ограничения и рамки

## Обязательные правила работы Codex
- Работать только в актуальной ветке `main`.
- Не проводить полный аудит всего проекта.
- Разрешён только точечный поиск по уже существующим связанным системам: мобы, рендеры, модели, звуки, анимации, эффекты блоков, книга сказаний, богатыри, руны, PolyMC-пайплайн.
- Не делать лишних рефакторингов.
- Не переписывать unrelated systems.
- Не запускать Minecraft клиент и не выполнять `runClient`, если это не требуется пользователем. Здесь запуск клиента запрещён.
- В конце только собрать JAR и обновить тестовый профиль PolyMC без запуска игры.

## Ключевой художественный принцип
Референсы из папки `refs/` — это обязательная основа.
Если между текстовым описанием и картинкой есть микроконфликт, то:
1. сначала сохраняется утверждённая игровая логика из текста;
2. затем сохраняется визуальный облик из референса;
3. при невозможности точного 1-в-1 переноса — максимально близко адаптировать под Minecraft.

## Что запрещено
- Нельзя заменять утверждённый дизайн Полоза другим змеем/драконом.
- Нельзя превращать Плеть Полоза в обычный меч/копьё/цепь без плетевого поведения.
- Нельзя делать броню Полоза просто перекрашенной незериткой без выраженного нового силуэта и чешуйчатых деталей.
- Нельзя делать синтезаторные «биты» вместо голоса Полоза.
- Нельзя глобально заменять ванильные блоки: заражённые блоки — это локальные заражённые аналоги, а не редизайн всего Minecraft.

## Локализация
- Русская локализация обязательна.
- Проверить все новые имена, предметы, подсказки, записи книги сказаний.
- Английская локализация — по возможности, но RU приоритетна.
