## План реализации

1. **Реестр и границы.** Сопоставить все923catalog IDs с Java registry и vanilla item components; выделить441кандидат и пересечения вне этих групп (валюты, инструменты Чуди). Отделить usable Item, функциональный активируемый BlockItem, ингредиент/трофей, декор, spawn egg/technical, delegated #278/#284/#285/#287. Для каждого исключения указать причину/владельца задачи; не считать plain Item бесполезным без поиска consumers.
2. **Поимённая матрица пользы.** Для оставшихся функциональных объектов: RU/EN имя/ID, класс, advertised purpose, настоящий handler, recipe/loot/trade/reward, ранний/средний/поздний stage, action/effect/limits, vanilla/текущий baseline, KEEP/BUG/PROPOSE/OBSOLETE-кандидат, доказательство/тест. OBSOLETE не означает удалить ID. Для материалов — producer→consumer graph и доступность потребителя, а не обязательный Item.use.
3. **Экономика.** Полный source-wide поиск coin/валют/merchant/recipe/quest/ritual, проверка загрузчика данных и вызова handler. Разделить источник, потребление, возможную обратную конвертацию и потенциальные циклы. Исходная гипотеза — KEEP существующие sinks. Если найдётся конкретный пробел, отдельно предложить1–2малых решения с before→after; не вводить новую валюту, цену или сундуковую массу без решения.
4. **Доказанные исправления малыми группами.** Сначала еда/тара/неартефактные расходники; затем farming/tools; затем materials/trade UX. Каждый BUG воспроизводится до правки и имеет минимальный regression. Исправлять уже заявленную механику/ошибочный tooltip; сохранять ID/components/server authority. Новые рецепты/баффы/нерфы/стоимость/stage — только отдельное утверждение с конкретными числами и причиной. Если ошибки не обнаружены, KEEP без искусственного патча.
5. **Технические gates.** Java21 clean build --no-build-cache, source/JSON/resource references, стабильные ID/components, production JAR без тестов. Детерминированные offline проверки чистых rules, рецептурных графов/экономических циклов и обработанных дефектов. Static/симуляция не объявляются gameplay PASS. Проверить сохранность #277/#287 и #278/#284 source guard; native regressions только после отдельного разрешения runtime #286.
6. **Сдача.** Отдельные логические коммиты только после разрешения на реализацию/публикацию. Полная матрица `ID | baseline | action | expected | evidence | PASS/FAIL/BLOCKED/NOT_RUN`, краткие Survival маршруты и ограничения. Обновить PROJECT_STATUS/ROADMAP/ARCHITECTURE по реальному результату. OPEN/IN_PROGRESS до owner playtest, Project поля не имитировать.
