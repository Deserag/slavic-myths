## Task 2 — world generation / placement architecture (placement phase)

- Confirmed a loaded-chunk visibility defect in `PosadPiece`: panes and shelves were written through `LevelChunk.setBlockState` instead of the `WorldGenLevel` write path. That bypass is useful only for the carved-pumpkin/golem special case and can leave a loaded client stale until the chunk is resent/reloaded. Schema 25 removes that bypass for panes/shelves and uses flag-2 `WorldGenLevel.setBlock`; carved pumpkins retain the no-golem direct write but explicitly publish a block change when the level is a live `ServerLevel`.
- Schema 25 makes the complete city volume Y=1..17 deterministic: an otherwise unauthored city cell is explicit AIR. This prevents natural Nether terrain from surviving between authored voxels as random interior obstructions. The change is schema-gated: persisted schema <=24 pieces keep the old null/no-write semantics, so partially generated old starts are not destructively reinterpreted after upgrade.
- Registry IDs and the persisted `Anchor`, `Turns`, `Schema`, `BridgeLength` and `Supports` fields are unchanged.

Verification for this phase: static source inspection only; Java/Minecraft runtime execution is reported after the complete Task 2 change set.

### Task 2 — native worldgen activation and bounded planning

- Root cause confirmed: `PosadWorldgen` registered the `slavicmyths:nether_posad` structure type/piece, and the approved placement baseline existed only under docs, but production had no `worldgen/structure/nether_posad.json` or `worldgen/structure_set/nether_posad.json`. Natural generation therefore had no active data-driven structure/placement entry.
- Added those two production JSON files using the already-approved baseline exactly: weight 1, random spread, spacing 80, separation 32, salt 22022026, linear spread and frequency 0.75; biome tag and registry IDs are unchanged.
- Natural generation no longer invokes the dense 113×113 `PosadTerrain.inspect` scan. New `inspectWorldgen` uses a bounded 4-block safety grid plus the exact 8-block support grid and the existing bounded bridge/shore search. The dense `inspect` remains intact for manual/loaded-world QA where player data may exist.
- Shared bridge selection was factored into one `finishPlan` implementation so dense/manual and bounded/native planners cannot drift in rotation, shortest-shore selection, support rotation or bridge bounds.
- Added synthetic Java assertions that the bounded native planner preserves the flat-land plan, rejects sampled protected cells, and performs less than one tenth of the dense planner's terrain reads in that fixture.
- Added a physical GameTest asserting that the production `nether_posad` structure and random-spread placement load through Minecraft registries with spacing 80, separation 32 and salt 22022026.
- The Posad Java21 geometry and physical GameTest workflows now also run on `refactor/cleanup-audit-20261101` so this isolated cleanup branch can produce real CI evidence instead of inheriting results from `hell`.

Natural generation is enabled only for newly generated chunks by Minecraft's normal structure pipeline; no retrofit, destructive regeneration or old-world rewrite was added.
