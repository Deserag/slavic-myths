# Исторические бинарники, scratch и инструменты

Из актуального индекса удалены 17 `release/*.jar` (271826740 bytes), 560 `.log` и 666 файлов прежнего `work/`. Это не переписывает историю и не уменьшает старые Git packs. Локальные файлы оставлены там, где ещё могут понадобиться; вторичные копии удаляются после проверенного сохранения уникальных данных.

## Сохранность

У владельца вне репозитория находится `historical-tracked-artifacts.zip`; SHA256 `3f97727b35b5e49593a5ad7bf80c8f9c220f0e6b4ee6a1fe3d8758c2609499a8`. Каждая запись прочитана обратно и сверена. Архив включает оригиналы 31 install/verify инструмента до перевода в архивный режим.

В `work/` были исходные WAV, рисунки, старые спецификации, Python-инструменты и Java API snapshots. Он **не удалён без сохранения**: всё содержимое есть в архиве, прежней Git-истории и локально в основной копии. Он не является production source-set Gradle. Действующие `src`, `art`, assets и поддерживаемые `tools` не вычищались по расширению. При необходимости адресно восстановите аудио/рисунок в `art/`, спецификацию в `docs/`, поддерживаемый инструмент в `tools/` и проверьте зависимости.

Release notes и checksum manifests оставлены в Git. Публичные Releases содержат только RC1/RC2 0.9.10; JAR 1.6–1.9 из архива не опубликованы. Текущая версия собирается из исходников.

## Архивный режим

`install_kuzya_166.py`, `install_pesigolovtsy_165.py`, `install_armor_revision.ps1` и родственные инструменты проверяли конкретный старый JAR, старые gates, scratch-логи и определённый тестовый профиль. Baseline нельзя заменить текущим JAR. Теперь они немедленно завершаются сообщением об архивном статусе, прежде чем читать профиль или устанавливать файлы. Исторические verify также не выдают новой версии ложную приёмку. Исходный код сохранён для воспроизводимости.

## Восстановление

1. Найдите путь и SHA256 в manifest. Используйте локальный recovery archive владельца или Git revision до удаления (`source_commit` в manifest); это не публичная ссылка на бинарник.
2. Извлеките конкретные входы и оригинал инструмента в отдельный исторический каталог с прежним layout. Для Git-версии подходит `git show <source_commit>:<path>`; не накладывайте старый checkout поверх main.
3. Сверьте SHA256 и восстановите совместимые исторические JAR/отчёты. Перед новым использованием перепроверьте все предпосылки.
4. Не запускайте installer в пользовательском профиле без отдельной задачи на установку и резервирования. В #43 установка и запуск Minecraft не выполняются.

Пробы `tools/higher-tests` и `tools/mor-tests` с baseline 1.7.9 тоже исторические: им нужен восстановленный layout. Они не входят в обязательный текущий build и в этой задаче не запускались.
