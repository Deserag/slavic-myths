# Полоз: устаревшая цель BodyMelee после смены AI goal

17 октября 2026, исходный main `fb2994e958911169317523e1066b8a1ca7a155af`, 1.9.7.5. Отдельная ветка `codex/poloz-body-melee-lifecycle`, исправление найденного в обычном мире критического краша. Полный отчёт производительности публикуется отдельно.

В 15:38:11 dev client/integrated server завершился с NPE в `PolozEvents.BodyMelee.tick`, когда Heavy bandit потерял ссылку на босса. Нативный `GoalSelector.tick` сначала проверяет допустимость нового goal, затем вытесняет прежний. `BanditEntity.CombatGoal.stop()` очищает цель. Новый BodyMelee уже запущен, но его tick делал безусловный cast/dereference. Это последовательность в одном server thread, не доказанная межпоточная гонка.

Изменение: один снимок текущей цели с проверкой `instanceof GreatPoloz` и `isAlive()` непосредственно перед использованием. При неподходящей цели tick возвращается; стандартный selector завершает goal при следующей проверке. Очистка цели предыдущим goal, выбор части тела, дистанции, урон, 20-tick cooldown и навигация действующей атаки сохранены. Registry IDs, ресурсы, визуал и механики боссов не изменены.

До исправления: нативный GameTest воспроизвёл тот же NPE при реальном вытеснении CombatGoal тяжёлого бандита, NPE для пустой цели, ClassCastException для другого типа и атаку по мёртвой цели. Контроль обычной атаки/cooldown прошёл. После исправления: 1/1 GameTest, все 6/6 подслучаев PASS. Opt-in тест использует установленные production goals и нативный GoalSelector; это не полноценная битва с боссом.

Java 21 `clean build` + runtime GameTest PASS. [Gates](gates.json): 3919 JSON, 1325 PNG, 6804 resource parity, 1685 Java21 classes, 221 subscribers PASS; fixture отсутствует в production JAR. SHA-256 исправленного JAR: `a4f05c99b24a0639c1aacb57efc8aaff4023f26c60d03291e5a240ec26b6817c`.

Первый вариант теста ошибочно использовал `tickRunningGoals(false)`, который не вызывает этот goal; контроль cooldown обнаружил ошибку. Этот запуск не считается воспроизведением production-сбоя. После сверки с установленным исходником GoalSelector тест исправлен, затем выполнены действительные before/after проверки. Всего до игрового повтора: 3 headless GameTest server JVM, включая эту ошибку fixture.

Повтор с исправлением: примерно51min обычных сцен, включая Полоза,5 циклов spawn/combat/cleanup и10min idle, исходный NPE не повторился. Полоз до очистки оставался в фазе1, HP2396, тогда как main до краша дошёл до фазы2, HP1910: это не идентичные бои и не доказательство FPS-ускорения. Позднее окно Полоза: до124,5FPS/p99 19,87ms/MSPT16,01; после124,3FPS/p99 19,21ms/MSPT15,93. Production guard направлен на надёжность.

В естественном мире следующие три босса не приобрели цель. Отдельный focused flat run с тем же production guard завершился штатно: Горыныч GROUND HP2800→2316,97; Карачун фазы1–3, HP1600→117,15; Морозко фаза1, HP1400→1345,22. FPS135,9/135,9/135,7, MSPT5,06/4,78/5,03. Нативные атаки, нормальные HP, защищённый игрок с выданной экипировкой; полное Survival-прохождение/победы не подтверждены.

Общий normal-world запуск **FORCED_STOP_FIXTURE**, не полный PASS: ошибочный тестовый disconnect оставил старый сервер в меню. Сохранение завершилось; после JFR/thread dump остановлен только собственный JVM. Это не исходный production NPE и не доказанная утечка. Исправленный disconnect fixture компилируется, но реальная загрузка копии старого save/настоящий перезаход **NOT_RUN**. Владелец запретил новые игровые запуски. Connected MP/dedicated gameplay, поздние фазы Морозко/воздушная Горыныча/награды NOT_RUN.

Доказательства before/after: [cases.json](cases.json), sanitized gzip logs, [исходный crash](source-crash.sanitized.txt), gates.json. Один normal-world и один flat клиент с исправлением, плюс исходный main-клиент. Три headless GameTest JVM перечислены выше отдельно. Полные игровые CSV/JFR summaries публикуются в независимой ветке `codex/performance-2-release`, путь `docs/implementation/performance-2.0/REPORT.md`.

Механики, damage/cooldown, ID и ресурсы сохранены, изменение формата сохранения отсутствует. Main/PolyMC/пользовательские миры не менялись; auto-merge не выполняется.
