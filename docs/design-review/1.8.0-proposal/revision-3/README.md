# Проверка длины рук и лука — 2026-10-12

**Макет и статический аудит; production не изменён.** Проверены rig JSON, действующие native meshes, текущие генераторы и SkimModel BOW. Сопоставлена ванильная HumanoidModel из установленной зависимости1.21.1: туловище и опущенные руки имеют согласованные нижние границы; ориентироваться только на согнутый локоть неверно.

Измерения — по реальным vertex AABB в опущенной IDLE позе; таз задаёт основной root/hips cube. Это геометрический ориентир Minecraft-модели, не медицинский антропометрический норматив. Правая/левая рука проверены отдельно. Пальцевые анатомические суставы в этих кубических моделях не выделены; «кисть» здесь — нижний конец модели ладони/руки.

В генераторах Rig.box второй параметр задаёт нижний y, а не центр куба. Например, у Алёши hand skin начинается на18.1 и имеет высоту4.8; нижняя граница pelvis —13.8. Это подтверждает проблему непосредственно в исходной геометрии, а не только в согнутом макете. Для реализации нужно менять параметры/пивоты плеча и предплечья согласованно, перенести места хвата и UV; не просто растянуть кисть или оружие.

`tools/design_review_arm_proportions.py` создаёт изолированный сравнительный макет. Сохраняет верхние плечевые накладки, удлиняет плечо ниже плеча и предплечье до ладони; конечный ладонный участок переносится без растяжения.20 offline geometry checks PASS: выбранные длины, симметричное удлинение слева/справа и новая нижняя граница руки относительно таза. Перемещение/натяжение UV в client не проверялись.

## Лук

Положение рукояти ручного лука соответствует диапазону кисти исходной геометрии. После изменения рук его привязку нужно перенести к новой ладони. Задний лук и колчан размещены в разных боковых областях спины; анимационного collision-теста не было.

Найдены реальные проблемы исходного генератора/анимации:

1. Между крайними сегментами плеча лука есть пространственный зазор по z: разность центров1.25, толщина0.85; небольшой y-overlap не закрывает этот зазор. Тетива также не заканчивается непосредственно в деревянных крайних точках.
2. SkimModel BOW меняет string.z целиком на3×draw. Это сдвигает концы тетивы, вместо V-образного натяжения с неподвижными концами.
3. BOW поворачивает left_shoulder на−90°; ручной лук дочерний этой цепи, а встречной компенсации его ориентации нет. Нужно проверить/исправить сохранение вертикальной плоскости лука. draw_arrow — соседний child руки; его локальное z-перемещение после поворота плеча не следует автоматически считать направлением выстрела. Положение/ориентацию стрелы надо задавать в согласованной системе координат лука.

[Схема геометрии тетивы](bow-string-proposal.png): соединённые плечи лука, закреплённые крайние точки, две секции тетивы, движущаяся средняя точка. Это предложение устройства геометрии, не игровая поза и не тест попаданий стрел.

Следующая игровая реализация должна совместить одобренную длину рук, хват оружия, вытянутую левую руку, согнутую правую руку при натяжении, стрелу на средней точке тетивы и правильную сторону выстрела. Одна правка масштаба спрайта эти ошибки не исправит.

Production остаётся1.7.9; версия/Java sources/resources/PolyMC не менялись. Minecraft client/server starts0, build не запускался. Предыдущие требования о компактной книге/возвращённом дереве, forward оружии и лимите двух восстановлений с reset после окончания боя сохраняются; их production integration ещё не выполнена.
