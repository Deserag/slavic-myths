- Место хвата перенесено к ладони у конца предплечья: предыдущий макет использовал центр AABB всего right_hand, который в этих моделях содержит и предплечье.
- Головка палицы Ильи увеличена с4.8 до6.8 модельного пикселя (≈42% шире); древко1.6×12. Железная головка с уступами, без пальцеобразных выступов, деревянная рукоять видима.
- Сабля Алёши остаётся тонкой, изогнутой и непрерывно соединённой с гардой; в новой позе направлена вперёд с ладони, а не вдоль ноги.
- У Добрыни проверен знак ориентации: его копьё изначально остриём вверх, поэтому после сгиба руки надо дополнительно развернуть копьё в месте хвата. Нейтрализован прежний постоянный rx(spear,-12); железный наконечник смотрит вперёд.
- У Финиста выявлен постоянный z(weapon,58) даже в IDLE. В макете убран этот наклон, затем кисть/оружие повёрнуты вместе. Анимационные SWORD/MORPH/DRINK/ходьба/щит должны быть проверены отдельно при реализации; это не заявляется выполненным.

## Причина лечения и согласованное правило

Пользователь прямо уточнил: счётчик сбрасывается **после завершения боя**, не после нового призыва.

| Герой | Фактический код1.7.9 |
|---|---|
| Финист | boss() понимает только персональный KartausEncounter. В recover() при boss()==null и HP≥119 снимаются REST/lastStand. Обычные враги и debug boss не удерживают его в состоянии отдыха, поэтому цикл может повторяться. Счётчика нет. |
| Алёша | Аналогично boss() ограничен SkimValley. При b==null и HP≥122.5 снимаются lastStand/RECOVERING. Вне этого сюжетного боя возможны повторные восстановления. |
| Илья | В сюжетном бою Returned ограничивает возвращение; после повторного восстановления переходит DOWN_FOR_ENCOUNTER. Это другая логика, не тот же бесконечный цикл. |
| Добрыня | Retreated сохраняется до bind нового WitchYard; после первого отхода повторно не запускает такую же ветку в этом бою. Нужно сохранить защиту от повторного входа в recovery и явно согласовать её с общим лимитом. |

HeroCalls.recover также автоматически лечит/возвращает FinistDormant/Dormant и проверяет главным образом сюжетные locks. Лимит нельзя исправить только в FinistEntity: иначе snapshot/пересоздание сущности обойдут счётчик.

Следующая реализация должна дать всем героям одну верхнюю границу: первое истощение → отход/лечение/возвращение; второе → отход/лечение/возвращение; третье → уход из боя, без третьего лечения и автоматического возвращения. Counter/active battle identity сохраняются в NBT/snapshot и записи owner+hero; recall/новый UUID/перезагрузка/потеря target не сбрасывают лимит. После окончания боя counter очищается, ушедший герой становится доступен для явного нового призыва. Сюжетный бой определяется существующей encounter identity/status; обычный бой нельзя считать оконченным только по target=null во время retreat.

`tools/recovery_budget_draft.py` — executable модель этого правила с duplicate observations, сохранением/восстановлением snapshot, отказом нового призыва в активном бою и reset после finish. **376 проверок модели PASS; production integration NOT_IMPLEMENTED.** Это не GameTest, не измерение AI и не проверка событий Minecraft. Реальные объёмы/скорости/пороги лечения этой моделью не меняются.

Изменение механики, сериализации и подключения к обычным боям предстоит выполнить в production после согласования текущей итерации. Новые store/registry IDs, world scanning каждый тик и принудительная загрузка chunks для этого не требуются.
