# Архитектура, события и схема интеграции (без полного аудита)

## Найти только необходимые существующие точки
Скриптом точечного поиска/IDE навигацией определить класс регистрации новых сущностей, client renderer, атрибутов, sound events, загрузки моделей/анимаций, существующее взаимодействие «спутник/союзник», хранение данных мира/игрока, применяемое API book/quest лишь если требуется. Прочесть максимум минимально связанных мест. Если общей системы спутников нет — реализовать самодостаточно, не переписывать старые сущности.

## Обязательные состояния сущностей
**Илья:** IDLE, FOLLOW, GUARD, PURSUE, TAUNT_CAST, SHIELD_RAISE, SHIELD_HOLD, SHIELD_RECOVER, MACE_WINDUP, MACE_STRIKE, SHOCKWAVE_CAST, UNYIELDING, RETREAT_START, RETREAT_MOVING, HEAL_DRINK, RECOVERY, RETURNING, DOWN_FOR_ENCOUNTER.
**Идолище:** IDLE, ACQUIRE_TARGET, CHASE, FIST_WINDUP, FIST_SLAM, STOMP_TELEGRAPH, STOMP_PULSE, GRAB_START, GRAB_HOLD, GRAB_THROW, FEED_SUMMON, FEED_GRAB, FEED_CHEW, BREATH_WINDUP, BREATH_ACTIVE, CHARGE_WINDUP, CHARGE_RUNNING, STUNNED, RAGE_TRANSITION, DEATH.

Каждое серверное состояние хранит `startTick`, `endTick`, cooldown-map, `targetUUID`, `encounterId`, `phase`, `interruptibleWindow`; перед переходом проверять существование entity, loaded chunk и target validity. В renderer передавать state ID + normalized animation progress; client particles spawn from event packet/state transition **однократно**.

## Активный encounter
В мире существует объект `encounterId`: `bossUUID`, arena origin + radius, initiatorUUID, activeParticipants UUIDs, allies UUIDs, startTick, enrage flag, heal charges and summon budget. Тик босса server-side. Если все игроки вышли/умерли/тайм-аут, boss reset/recovery without marking victory. При рестарте сервера выбирать один договорённый режим: либо корректно продолжить из данных мира и entity UUID, либо завершить encounter и безопасно очистить миньонов/агро; НЕЛЬЗЯ восстановить Илью 2 раза и сохранить дубликат.

## Оптимизация
- Тяжёлый выбор нового пути AI не каждый tick; refresh 8–20 ticks, проверка цели 5–10 ticks.
- Ближний hitbox вычислить из серверного box/capsule под текущую анимацию, максимум 1 раз damage per swing per target.
- Атака имеет явный `hitFrame` server ticks, не привязанный к FPS.
- Не хранить вечно ссылки на `LivingEntity`: UUID + re-resolve, валидировать alive/dimension/arena.
- Client FX budget: 120 particles/event high, 40 medium, 14 low; texture atlases nearest filtering and mipmapping compatible with project.
- Дальность отображения босса не меньше 96 блоков, а его hitbox и bounding box стабильно обрабатываются при рендере издали.
