# Сохранение победы, участие, будущая 1.7.6 БЕЗ лута

## Что сохранять
На сервера (World SavedData/Capability/Attachment API фактической версии проекта) хранить карту `playerUUID -> bosses`: `idolishche_poganoe`, `firstDefeatedWorldTick`, `lastDefeatedWorldTick`, `defeatCount`, `usedHeroIds: [ilya_muromets]`, `allyWasAliveAtStart`, `participationFlag`, `eligibleForFutureRewards`. Не зашивать выдачу наград/рецептов/достижений в 1.7.1. Факт уже состоявшейся победы потом читается 1.7.6 без обязательного нового убийства.

## Кто считается участником
Players, не spectator/creative debug, которые в течение последних 45 сек босса получили или нанесли >=1 валидный combat event, и в момент убийства находятся в той же dimension ≤72 блока от origin. Только этим игрокам записать прогресс; ally contribution учитывается только если её owner сам участвовал. Если boss заспаунился debug command у администратора, debug прогресс не должен случайно засчитываться игрокам, пришедшим посмотреть.

## Версии хранения
Храни `schemaVersion = 1`; при повторном входе/рестарте нет двойной выдачи и повтора интро. Обработка recover без dupe: привязанная по UUID hero entity максимум 1 на owner+type; при загрузке очищать некорректные старые боевые locks и миньонов только своего encounter.

## Что показывать игроку
После победы: «Идолище Поганое побеждено. Победа записана в летописи.» Без окна трофея, без мешочка/мешка, без drop table. Если проект имеет существующую книгу сказаний, допускается **только безопасное** обновление already-known boss entry / status с существующим API, не добавлять новую ветку заданий. Если интеграция требует переработки книги — не делать; запись данных достаточно.
