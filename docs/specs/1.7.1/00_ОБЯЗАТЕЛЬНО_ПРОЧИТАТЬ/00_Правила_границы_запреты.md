# САМЫЙ ВАЖНЫЙ ФАЙЛ: общие требования, ограничения и запреты

## 1. Статус документа
Данный ZIP целиком является **промптом + обязательным ТЗ на НЕПОСРЕДСТВЕННУЮ реализацию Slavic Myths 1.7.1**. Не отвечать пользовательским текстовым планом, не генерировать второй ТЗ, не просить утвердить описанные в этом пакете решения. Выполнить код, JSON, модели, текстуры, анимации, звук, тестирование, сборку; подготовить краткий отчёт о сделанном и честный список остаточных блокеров.

## 2. Не анализировать проект целиком — жёсткое требование
- **Запрещены:** чтение всего репозитория, массовое прохождение через все пакеты, full-text dump кода, анализ истории коммитов, изучение всех существующих мобов и боссов, бесконечное переизучение модификации, перепроектирование сложившихся систем.
- **Разрешены:** 1 краткий осмотр `build.gradle`/`gradle.properties`/`mods.toml` или эквивалентных конфигов для проверки текущей платформы и версии; 1 точечный поиск существующих регистраций entity/sound/renderers, API союзников и сохранения прогресса; чтение **только найденных непосредственно связанных** файлов для интеграции.
- Ограничить предварительное чтение до ~15–25 релевантных файлов; если нужно больше, обосновать в отчёте *конкретные* дополнительные точки подключения. Не открывать каждый файл других боссов ради сравнения.
- Учитывать **фактическую** текущую платформу репозитория (по последнему плану — Minecraft 1.21.1, NeoForge), но не перетаскивать старые Forge 1.16.5 классы; адаптировать нейминги и API к фактическому коду.

## 3. Граница релиза
Реализовать Илью Муромца (танк 280 HP, 2.5 блока) и Идолище Поганое (босс III уровня, 900 HP, 9 блоков); битву с их взаимодействиями. Восемь обязательных файлов персонажей задают вид, анимации, AI/механику и звуки. Дополнительные файлы задают арены, боевой баланс, прогресс, интерфейс, тесты. Не добавлять Добрыню, Алёшу, Финиста, Маринку, Скима, Картауса, Калина, Индрика, новых богов или переработку прежних боссов.

## 4. Строго запрещено
1. Добавлять лут, награды, уникальные трофеи, новые рецепты наград и достижения за победу, предназначенные для 1.7.6; можно создать только **запись о победе**, метку участия богатыря и проверочные команды разработки.
2. Переписывать старые механики RPG, баланс других боссов, JEI, книгу сказаний, задания Бабы-яги/Баюна и чужие текстуры «за компанию».
3. Вводить по умолчанию глобальное разрушение блоков боссом; arena griefing выключен, эффекты ударов через частицы/звук/урон сущностям. Не ломать дома и чужие базы.
4. Заменять 3D-блочные модели плоскими 2D-пластинами, гладкими скульпт-мешами, дефолтным зомби со сменой размера или случайным перекрашенным Minecraft-скином.
5. Делать специально нарисованные предметы/текстуры в 16×16. Для сущностей — 128×128 / 256×256 атласы и пиксельная детализация, см. дизайн.
6. Использовать аудио/кадры из фильмов «Мельницы» без проверенных соответствующих прав; не утверждать, что права отсутствуют; не подделывать голос актёра или выдавать синтез за оригинал.
7. Делать «вечный щит» Ильи и постоянный бессрочный агр босса без контригры. Игрок обязан двигаться, уклоняться, спасать союзника и прерывать кормление.
8. Запускать логику боя на клиенте как источник истины или сохранять таймеры только в transient client state. Не допускать дубликатов сущностей/исцеления при переподключении.

## 5. Правила приоритетов
1) Общие ограничения и таблица чисел в `README`/этом файле; 2) числовые параметры из `03_Общие_системы`; 3) частные навыки/анимации; 4) визуальные референсы. При расхождении изображение — стилистический ориентир, не точные размеры. Исправлять опечатки концепт-арте только в документах/локализации; **игровые русские названия: «Илья Муромец», «Идолище Поганое»**.

## 6. Реализация и качество
- Класс entity и render/model слои отделить от AI, боевых состояний и анимаций; расширяемая структура без переписывания чужих систем.
- Таймеры и проверки состояний в server ticks (20 tps), косметика по синхронизированному идентификатору состояния. Animation state не может отменить реальные дистанции, урон и hit detection.
- Глобальные эффекты статусов применять только при наглядном предупреждении и только где указано; соблюсти cooldown, immunity frames, friendly fire rules.
- Частицы умеренные с параметром снижения плотности. Звуки не накладывать по 10 раз в секунду при многократных проверках AI.
- Дружелюбный спаун Ильи не должен заполнять деревни/случайный мир; Идолище не генерируется случайно в базах игроков. См. 03.
- Важно: минимум 6 HP — ориентир для **полноценного НЕзаблокированного опасного попадания** Идолища после защиты обычной полной алмазной брони без чар, а не для каждого ядовитого тика/миньона/скользящего эффекта. Щит, благословения, зачарования и устойчивость вправе снизить итог. Исключить абсолютные магические bypass на весь урон.

## 7. Правило наград в будущем
Сохранять `playerId`, `bossId`, `defeatedAtWorldTime`, `usedHeroIds` (если были), `eligibleForFutureRewards=true` после честной серверно зафиксированной победы. Эта запись **не выдаёт** награду. Для мультиплеера запись делать всем игрокам с легитимным участием в пределах дистанции и с ненулевым contribution; не открывать всем на сервере.
