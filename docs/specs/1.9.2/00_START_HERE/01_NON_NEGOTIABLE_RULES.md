# Непереговорные правила реализации

1. Менять только функциональность **1.9.2**. Не делать новую генерацию структур, гору/Горыныча, Ад, мор, Карачуна как заражённого босса и глобальную переработку рун 3 уровня.
2. **Экономия токенов:** запрещён полный повторный аудит проекта и сканирование всех исходников. Сначала прочитать маленький набор entrypoint-файлов регистрации entity/items/effects/sounds; 1 соседний босс, механика испытаний Морозко, воронов/летунов (если уже есть), текущие руны, аксессуары, снапшот управления/хоткеев и сетевой слой. Все дальнейшие поиски — адресные по найденным символам.
3. **Сначала узнать фактический стек из `build.gradle`, `gradle.properties`, конфигурации проекта.** Исторический ориентир Minecraft 1.16.5 / Forge 36.2.42 / Java 8 / modid `slavicmyths`; не менять версии насильно, если текущий проект отличается.
4. НЕ запускать Minecraft-клиент, `runClient`, `runServer`, PolyMC или GUI. Пользователь сам делает визуальное игровое QA; можно запускать компиляцию / unit checks / production build, которые не поднимают игру.
5. Сделать настоящие детализированные **Minecraft-voxel** модели, отдельные PNG-текстуры, UV, реальные анимации; НЕ заменять Карачуна перекрашенным Морозко/зомби, ворон — летучими мышами без новых моделей, косу — плоским увеличенным мечом, амулет — recolor.
6. Последний `KARACHUN_DARK_BOSS_APPROVED.png` — обязательный визуальный приоритет над предыдущим, более светлым референсом.
7. Сами картинки — **референсы**, не игровые текстуры. Текстуры и модели создавать/интегрировать самостоятельно. Все подписи и описания из изображения могут быть ошибочными; спецификация механик по Markdown приоритетна.
8. Реальная серверная логика ИИ, damage/cooldowns/status/loot; клиент только рендер, анимации, звук и галлюцинации. Проверять packet origin и owner UUID.
9. Карачун **не умирает**, при 5% HP останавливает бой и однократно выдаёт награды; никакого обычного death-loot. Действуют только честные участники, без дублирования в MP.
10. Русский `ru_ru` полностью, плюс английская локализация по существующим правилам проекта. Никаких сырых registry keys и англоязычных UI на русском клиенте.
11. Не запускать внешние сайты, не скачивать случайные asset packs, новые зависимости без необходимости; использовать существующую модельную/анимационную инфраструктуру. Не вносить массовые unrelated изменения.
12. Если нет оснований считать механики готовыми (хитбоксы/анимации/звуки/ресурсы/управление), не рапортовать «реализовано». Отдельно отчёт план/факт, реальные compile-результаты, оставшиеся риски.
13. **Никакой принудительной смерти у игрока.** Навык «Последний час» имеет телеграф, шанс уклониться; offhand-disable не уничтожает экипировку, не отключает безопасность тотема бессмертия и не блокирует обычное управление.
14. В настройках спецэффектов предусмотреть режим сниженных визуальных искажений (для тошноты/тьмы/мерцания). Не навязывать всем на сервере смену игрового времени.
15. Не изменять доступность/архитектуру существующих богатыpей, Морозко или Серого волка. Использовать их текущие паттерны взаимодействий, не подменять механики.
16. По старому проектному workflow: после успешной неигровой production-сборки обновить continuation/checklist, подготовить один актуальный JAR. **Копировать JAR в пользовательский PolyMC instance только если известен точный текущий путь и это разрешено workflow; не запускать PolyMC, не угадывать путь, не удалять чужие моды**. Если путь не известен — указать готовый артефакт и пропустить копирование.
