# Серверное испытание Карачуна и state machine

## Доступ и жизненный цикл
- Вызов **только специальным ритуальным предметом** через Бабу-ягу ИЛИ Кота Баюна, используя существующие отношения/квестовые механики. Если вход открыт у одного NPC, не требовать обязательного второго. Повторные испытания разрешены. Не создавать мироген/рандомный спавн.
- Предмет вызова похож на миниатюрный темно-ледяной тотем с руной и тремя выступами по референсу items. Если изображение показывает большой алтарь, это демонстрационная сценка; не вводить постоянную глобальную структуру worldgen без согласования. При необходимости в локальном месте призыва показать временный ритуальный FX.
- Место — безопасная локальная область в Overworld, **без глобального изменения времени суток** или случайной порчи мира. Радиус боя/границы через уже существующую trial логику Морозко; конфигурировать. Не блокировать unrelated игроков.
- Босс по дефолту 1200 HP; 5% = 60 HP. Состояния `DORMANT -> INVOKING -> OPENING -> ACTIVE_PHASE_1 -> ACTIVE_PHASE_2 -> ACTIVE_PHASE_3 -> YIELDING -> REWARDING -> EXIT`. При потерянных игроках/выходе всех `FAILED_CLEANUP`.
- С первой секунды OPENING на server создаёт 4 реальных ворон. В последующей phase возможен пополняющий summon, никогда >4.
- При попадании, способном пересечь 5%-порог, **клампить HP** на порог и одномоментно отключать дальнейший damage/hit/death (включая DOT/fire/bogatyr hits). Нельзя позволять Карачуну умереть от overshoot.
- YIELDING: Карачун опускает косу, исчезает локальная ночь, вороны удаляются с VFX, фантомы немедленно чистятся у каждого клиента, всем участникам снимаются **его** шкалы страха/угасания и связанные эффекты, не снимать посторонние негативные эффекты мира, выдать персональные награды один раз.

## Кто участник
- Серверный `trialSessionId` / UUID босса; добавить playerUuid в участников после входа в активное испытание и минимального подтверждённого вклада (нанёс урон, получил урон, призвал богатыря который сражался, помощь союзнику/другое определённое событие). Избегать бесконечной выдачи AFK и случайным проходящим; параметры можно согласовать с существующим Morozko system. Богатыри сами по себе не занимают слот награды, их усилия засчитываются владельцу.
- Тотем вызова не изымается навсегда (по ранее утверждённой схеме повторных призывов), но должен иметь блокировку против дублирования параллельных испытаний; не создавать сразу 5 копий boss через спам-клик.
- Если группа вайпнулась или trial заброшен, снять только собственные эффекты, удалить птиц/phantoms, не выдавать наград, не оставлять вечную тьму.

## Возвращение/сохранение
При перезапуске/перезаходе: либо восстановить корректную server-owned сессию, либо безопасно закрыть и очистить её без повторного loot. Выбор соответствует текущей системе Морозко; обосновать и протестировать. Не оставлять вечные loaded chunks/AI задачки.
