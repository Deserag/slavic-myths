# 1.9.7 — Ресурсы, имена, привязки

## Сначала сверить с проектом
Использовать существующий namespace мода, конвенции предметов, моделей, textures, lang, sounds, registry, network и player-data. Ниже — **логические имена**, не навязанные классы или абсолютные пути. Не создавать копий перунита, наград боссов, кулдаун-менеджера или библиотеки анимаций. Текущая версия Minecraft/loader определяется из Gradle-проекта (ожидается семейство Minecraft 1.16.5, но код подстраивать под реальный проект).

## Перечень нужных ассетов
| Логическое имя | Что требуется | Формат / условие |
|---|---|---|
| `amulet_two_winters` | Общая иконка предмета, две половины кристалла | PNG с прозрачностью; предпочтительно 32×32, при несовпадении со стилем проекта адаптировать |
| `amulet_two_winters_morozko` | Визуальный вариант Морозко | PNG либо существующий механизм property override без тяжёлого рендера |
| `amulet_two_winters_karachun` | Визуальный вариант Карачуна | PNG либо тот же механизм; базовая иконка должна оставаться корректной |
| `item/amulet_two_winters` | Item model inventory/held | JSON-модель в принятом проектом формате с vanillа item transform |
| `amulet_switch_ice` | Звук выбора Морозко | Предпочтительно существующий / ванильный звук, без обязательного нового OGG |
| `amulet_switch_dark` | Звук выбора Карачуна | То же |
| `amulet_ice_shield` | Активация и разрушение щита | То же |
| `amulet_dark_wave` | Волна Карачуна | То же |
| `nether_aura_warning` | Предупреждающий сигнал | То же |
| `lang` | Название, режимы, способности и сообщения | ru_ru и существующий резервный язык проекта |
| `recipe/first` | Крафт первого оригинала | Рецепт с результатом `template=true` |
| `recipe/copy` | Крафт копии | Рецепт с валидацией `template=true` и возвратом оригинала |

**Важно:** если кастомный рецепт нужен для NBT/remaining-items, сериализатор и регистрация должны быть совместимы с текущим Minecraft API и существующей JSON/recipe инфраструктурой. Указывать/добавлять только реально используемые ресурсы; не хранить лишние ненужные пустые OGG и модели.

## Привязки в игре
1. Базовая иконка видна в инвентаре/руке и при выпадении предмета. Два режима имеют заметный акцент и понятную подсказку.
2. Способности вызывают лишь лёгкие краткие частицы и звуки (см. `02_VISUAL.md`), а не шейдер/долгую анимацию.
3. Обновление mode-state на клиенте — при изменении/входе в мир, не раз в тик. Если у проекта нет штатного визуального override по данным игрока, допустима нейтральная иконка и чёткое различение режимов эффектом, tooltip и сообщением; приоритет — корректные серверные механики.
4. Все ресурсы, требуемые на клиенте, не должны загружаться кодом выделенного сервера.
