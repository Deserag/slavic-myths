# Worldgen, persistence, performance, multiplayer

## Где и как генерировать
- **Только Overworld**, в подходящих естественных биомах лес/тайга/холмы: огонь преимущественно поверхность/возвышение; вода у каменистого склона или над пригодной подземной полостью с видимым входом. Не генерировать в Nether/End, океане, на bedrock и над гигантскими пустотами; не заменять existing villages/strongholds/player structures.
- Рабочая редкость — разнести минимум на несколько сотен блоков, настроить размещение под Forge 1.16.5 и реальные правила spacing/separation; **подходящую частоту зафиксировать в конфиге**, не использовать безусловный шанс на каждый тик/чанк. Избегать ситуации, когда две сюжетные структуры появляются в тысячах блоков от всех игроков — нужна реальная discoverability и достижение survival.
- Проверки terrain slope, biome, Y level, fluid, caves, roof support. Для воды достаточная толща грунта над залом, спуск на безопасную глубину (рабочий диапазон Y25–55 для основной части, не создавать ниже bedrock). Использовать настоящий блок-лэйаут, не «вырезать плоскость» площадью 100×100 в поселении.
- Rotation N/E/S/W должна крутить **всё**: structure blocks, stairs, slabs, fences, stateful blocks, orientation doors, trapdoors, water channels, block entities, chest loot markers, miniboss future anchors, protected bounds.
- Семя мира даёт воспроизводимую генерацию; не генерировать половину комнаты/срез сундука границей чанков, ждать правильного placement или использовать встраиваемый template/jigsaw механизм. Если реализации worldgen не хватает, явно отчитаться, а не делать частичную структурную свалку.

## Разрушаемость и заражение
- Не делать все блоки перманентно unbreakable. Для главных реликтовых комнат предусмотреть **механический** запрет доступа/награды до 1.9.4; предусмотреть, что игрок может прокопать путь обычной киркой, поэтому **фрагмент там не присутствует сейчас** (никакой exploit).
- Локально размещать уже имеющиеся варианты заражённых vanilla blocks (1.8.3.1) там, где они реально существуют; не дублировать registry по другому названию. Отсутствующие варианты заменить аккуратным локальным декоративным блоком, не переписывая поведение ваниллы.
- Никакой автоматической инфекции новых ландшафтов из этих построек, если это не утверждено; окружающий мир не должен массово меняться.

## Persistency и multiplayer
- Состояние restored fire, cleansed pools и opened secret cache хранить в мире по **конкретному экземпляру структуры**; открытия книг/достижений — per-player. Server authoritative.
- Реальные контейнеры не пересоздают loot при unload/reopen/restart. Если игрок разрушил сундук, он не появляется повторно при загрузке. Важно для старых миров и модового сохранения.
- Два игрока одновременно нажали на чашу: consumable расход только у одного successful update, награда без повторного roll. Если нужно, персональная последующая выдача при посещении восстановленного храма — отдельный server claim flag.
- Локальные частицы/звуки отправлять только близким клиентам. Не сканировать каждый загруженный мир для поиска восстановленных строений.

## Регрессии
Старые registry IDs, runes sockets, особые крафты 1.8/1.9.1/1.9.2, миссии Бабы-яги, Морозко/Карачун, vanilla biomes, рендер на dedicated server — без поломок. Чанк вне структуры не должен получать новых тяжелых постоянных tick entities.
