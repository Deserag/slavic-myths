# Loot tables, вероятность, защита от ферм и кооператив

## Роллы для обычных сундуков (ориентиры баланса)
Это **независимые категориальные попытки** для каждого обычного контейнера, а НЕ шанс встретить саму структуру и НЕ вероятность отдельного предмета в конкретной куче. Реализовать data-driven Forge loot tables подходящего стеку формата.

| Категория | Шанс на контейнер | Ограничения |
|---|---:|---|
| Базовые полезные предметы (еда, уголь, бутылочки и пр.) | 100% | 1–3 обычные стопки; не постоянный дорогой предмет |
| Тематические ингредиенты (Священный уголь / Капля) | 65% | Обычно 1–2 штуки |
| Особые расходники (Пепел, Склянка, Очищенная вода) | 30% | 1 штука / умеренная редкость |
| Редкие материалы / обереги (Камень очищения, Слеза, Оберег пламени) | 10–15% | 0–1 штука; не более одной редкой награды с этой категории |
| Древние обломки рун | 10% | 1 штука, без высокоуровневых готовых рун |

Не заставлять каждый сундук выдавать все категории. Реальная вероятностная логика и ограничения на количество — в data-driven таблицах. `loot-table seed` берёт world context/контейнерный seed и сохраняется; не перевычислять награду при открытии, рестарте, смене игрока. Избегать генерации контейнера со стороны клиента.

### Сюжетные фрагменты
- В 1.9.3: **0% — ещё не доступно**. Не класть «Пламенную часть амулета» / «Водную часть амулета» в loot tables, рецепты, creative loot или брошенные предметы (можно зарезервировать IDs только если это необходимо для 1.9.4, без доступной выдачи).
- В 1.9.4 (другой патч): при победе над мини-боссом и открытии отдельного реликвария **каждый легитимный участник** получает по 1 соответствующей детали. Не один shared сундук на группу, не счётчик kill drops, нужен сохранённый per-player ledger.

### Multiplayer
Сундуки дают обычный разделяемый лут по правилам vanilla; это допустимо, потому что он необязателен для сюжета. Уникальные прогресс-флаги исследованных мест и будущие фрагменты амулета — персональные/персистентные. Ритуал огня и очистка бассейнов не позволяют одному игроку испортить структуру для всех остальных; продумать необязательный per-player claim на разовую награду и общий мировой признак восстановления.

### Экономика
- Нет дешёвой фермы без лимита: не выдавать заново rare на block tick / unload / relog.
- Нет нового легендарного оружия / готовых рун III в этих сундуках.
- Предметам с повторным использованием назначить ясный интервал/cooldown и убрать возможность спама.
