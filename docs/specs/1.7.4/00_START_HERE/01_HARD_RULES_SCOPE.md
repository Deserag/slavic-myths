# Mandatory execution limits / compatibility contract

## Precedence and scope
1. These hard rules > the latest specifically approved character art > mechanic/animation tables > existing implementation patterns > Codex suggestions. If a conflict appears, follow precise text over artistic shorthand; never silently change gameplay values.
2. The target project is Slavic Myths, current dev branch, generally MC **1.21.1 NeoForge** (verify only existing wrapper/build config; DO NOT forcibly migrate). Preserve actual `modid`, package hierarchy, Java mappings, resource pack version, dependencies, item groups, data components, spawn conventions, and renderer registration. No new dependency if a current animation API can serve.
3. 1.7.4 only: Finist, optional companion as lightweight synced entity if required, Kartaus, black-banner minions as reused vanilla monsters, reusable summon item, boss egg and trigger item, minimal encounter site, FX/SFX, localization, persistence, tests. Do not fix/rebalance 1.7.1–1.7.3 unless an exact small compatibility fix is essential.
4. NO new natural world generation, NO giant fortress, NO settlement, NO 3D cutscene movie, NO 1.7.5 final boss, NO 1.7.6 relic rewards, NO gods or Koschei. No chain of rooms. A narrative battlefield marker can be a temporary blockless decal/particle circle.
5. Only one personal hero permitted with Kartaus: **Finist**. A normal non-story summon supports the previously established **two-hero maximum**. A hero unavailable/retreating still occupies slot until encounter ends. Other heroes may not enter personal-boss event and may not be swapped during combat. In world exploration, pre-existing rules win.

## Fast working sequence — NOT a repo survey
Read Gradle properties/build metadata, main registration entry and narrowly search for existing Sivka/Burka summoning behavior, a current hero, a boss with saved encounter and bar, sound events, animation renderer and language keys. Locate those references and STOP searching. Reuse proven registration/synchronization/persistence, create only the minimal new classes and assets. Avoid `find .`, `rg --files` over huge asset trees, reflection introspection, refactoring common AI and multi-hour test loops. Suggested work order: register entities/items/events -> functional AI -> synchronization -> 2 models -> animations -> sounds/VFX -> localization -> targeted tests -> gradle build.

## Technical invariants
- All damage, targeting, cooldowns, spawns, tracking, unique encounter ownership and progression are **server authoritative**. Client receives IDs/animation state/VFX; no client-determined hit or additional cloned spawn.
- An encounter has stable owner player UUID + encounter UUID + dimension; every banner/minion/hazard has encounter ID. No global scans; query inside 24–32 block radius at fixed intervals (>=10 ticks), never every tick all loaded entities. No chunk tickets or force loading. Stop encounter if owner logs out/unloads/leaves dimension according to existing behavior; clean up special minions/markers safely. Handle concurrent encounters, duplicate packet/use event and server restarts.
- Health terminology: 170 HP = **85 hearts** for Finist; 650 HP = 325 hearts for Kartaus. Player reference: 24 HP = 12 hearts; 6 HP damage after full diamond armor = 3 hearts, BEFORE accessory buffs. Do not confuse HP with hearts. Magical attacks can use bypass only when exactly documented; do not ignore all armor on everything. Measure post-armor values at current MC attributes rather than assume base values.
- No free invulnerability via repeated morphs, teleport loops, unkillable summons, unrestricted flight, permanent negative effects, camera takeover, permanent terrain destruction, excessive full-screen flashes, red silhouettes visible through opaque walls indefinitely, or unbounded minion count. Client without particles must still read boss attacks via poses/ground decals/sound and subtitles.
- Finist cannot be another high-damage melee assassin or another pure tank; Kartaus cannot be another illusion-teleport witch with duplicate bodies (Marinka). Use commander / suppression / priority-target combat.
- Body texture atlases at least 128x128 PNG, Kartaus at least 128x128 (256 preferred), falcon 128x128, item sprites >= 32x32 actual. No simple recolor of existing hero, no 16x16 as final. Prefer 64x64 for actual items.
- Original OGG within package are permitted original procedural game effects. DO NOT extract cartoon dialogue, songs or copyrighted actor voices; voice lines are written scripts and require original recordings/rights. Do not claim effects are human recordings.
- Summoning item never consumed, no durability, no cost, no cooldown on failed use except anti-spam. Creative egg only for debugging/free spawning, not a survival boss exploit. Survival Kartaus trigger is reusable as long as no encounter is running; victory has no unique loot before 1.7.6.

## Release deliverables
- Actual code/resources changed, successfully built JAR, proof of quick smoke tests (or transparent untested items), checked client render + dedicated-server data separation if possible, no missing texture/sound entries; localized items/tooltips.
- If launcher instance path is literally present in repo/config/user instructions, copy JAR only after verifying it is the correct `mods` directory. Otherwise report path, don't guess.
